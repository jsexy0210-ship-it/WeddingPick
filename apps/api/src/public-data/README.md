# 공개 인허가 자료로 업체 등록

전국 지자체가 올리는 인허가 자료에는 업체 이름·주소·영업 상태가 공개돼 있다.
특정 사이트를 긁어오지 않고 이 공개 자료만 쓴다 — 사업계획서 20번.

## 쓰는 법

1. [지방행정 인허가 데이터 개방](https://www.localdata.go.kr)에서 업종별 파일을 내려받는다
   (공공데이터포털에서도 같은 자료를 받을 수 있다). 파일은 보통 CP949 CSV다.

2. **파일을 먼저 들여다본다.** 어떤 업종이 우리 분류 중 무엇에 해당하는지는
   파일을 봐야 안다.

```bash
npm run public-data:import --workspace @weddingpick/api -- \
  --file 예식장.csv --inspect
```

컬럼 이름과 앞 몇 줄을 보여준다. 잘못 넣으면 미용실 전부가 스드메로 들어오는
식의 일이 생기므로, 모르는 파일은 반드시 여기서 시작한다.

3. 분류를 정했으면 무엇이 들어갈지 본다.

```bash
npm run public-data:import --workspace @weddingpick/api -- \
  --file 예식장.csv --category hall --dry-run
```

4. 괜찮으면 `--dry-run`을 뺀다. **`--region`을 주지 않으면 전국이 들어간다**
   (초기 타겟은 전국으로 정해졌다 — 제품·기술 명세 19번).

```bash
npm run public-data:import --workspace @weddingpick/api -- \
  --file 예식장.csv --category hall
```

여러 번 돌려도 안전하다. 같은 지역·같은 이름이면 새로 만들지 않고 확인일만
갱신한다.

## 어떤 업종을 어디에 넣나

**정해진 대응표를 두지 않는다.** LOCALDATA의 업종 구분은 우리 분류와 일대일로
맞지 않고, 배포 시점에 따라 달라지기도 한다. 억지로 표를 만들어두면 맞지 않는
파일을 그 표에 밀어 넣게 된다.

확실한 것 하나는 **예식장업 → `hall`**이다. 나머지는 `--inspect`로 내용을 보고
정한다. 특히 스드메(스튜디오·드레스·메이크업)는 인허가 대상이 아닌 곳이 많아
공개 자료로 다 채워지지 않는다 — 채워지지 않는 것이 정상이고, 그 빈자리는
사용자가 올린 문서와 가격 제보가 메운다.

## 하는 일

- **영업 중인 곳만** 넣는다. 폐업·휴업·취소는 뺀다 — 문 닫은 업체를 비교 대상에
  올리지 않는다
- 주소에서 **시도·시군구까지만** 남긴다. 비교에 쓰는 건 지역이지 번지가 아니다
- 자료의 갱신일자를 `last_verified_at`에 넣는다. 변하기 쉬운 정보는 마지막 확인일을
  함께 둔다(사업계획서 25번)
- 같은 지역·같은 이름이면 새로 만들지 않고 확인일만 갱신한다. 여러 번 돌려도 안전하다
- **등록하면 그 이름으로 기다리던 견적이 자동으로 연결된다.** "더 채플 앳 청담"으로
  읽힌 문서가 "더채플앳청담" 등록과 함께 붙는다

## 컬럼 이름이 다르면

업종과 배포 시점에 따라 컬럼 이름이 조금씩 다르다. 못 찾으면 **실제 파일의 헤더를
알려주고 멈춘다** — 엉뚱한 컬럼을 업체명으로 잡는 것보다 낫다. 그 이름을
`localdata.ts`의 `COLUMN_ALIASES`에 더하면 된다.

## 확인해야 할 것

- **이용허락범위** — 데이터셋 페이지의 라이선스를 확인하고, 출처 표시가 필요하면
  앱과 웹에 넣어야 한다
- 인허가 자료의 상호는 사업자등록상 이름이라 **간판 이름과 다를 수 있다**.
  매칭이 안 되는 이름이 쌓이면 `structured.vendor_aliases`에 별칭을 더한다.
  `structured.unmatched_vendor_names` 뷰가 무엇부터 손봐야 하는지 보여준다
