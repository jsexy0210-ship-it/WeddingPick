## v3.23 · 2026-09-08 (구현 중 변경 · 사용자 결정)

### 초기 설정 · 질문 전환 모션

새 질문이 위에서 내려오던 `wpDrop`(translateY −14 → 0 · 380ms)을 **폐기**합니다. 화면이 위에서 떨어지는 것처럼 보였습니다.

```
변경 전   wpDrop      translateY −14 → 0 · opacity 0 → 1 · 380ms
변경 후   요소 상승    translateY 10 → 0 · opacity 0 → 1 · 420ms · cubic-bezier(.16,1,.3,1)
```

`tokens.json` `motion.rise`를 그대로 씁니다. 답한 질문이 아래에 쌓이는 구조는 그대로이고, 새 질문은 제자리에서 살짝 올라오며 나타납니다.

### 바텀시트 · 딤은 제자리, 패널만 이동

시트를 열고 닫을 때 **딤 배경이 시트와 함께 미끄러지지 않습니다.** 딤은 제자리에서 페이드하고 패널만 올라오고 내려갑니다.

```
딤(backdrop)   opacity 0 → 1 · 200ms ease-out      닫을 때 1 → 0
패널            translateY 100% → 0 · 350ms · cubic-bezier(.16,1,.3,1)   닫을 때 역방향 250ms
```

RN `Modal animationType="slide"`는 딤까지 같이 움직이므로 쓰지 않습니다. 공용 `BottomSheet` 하나가 모든 시트(날짜 선택 · 정렬 · 로그인 · 확인 · 일정/메모/지출 입력)를 맡습니다.

## v3.22 · 2026-09-09

### 콜드 스타트 대응 · 정보 0층 신설

출시 첫날 실 제보는 0건입니다. 실 제보로만 순위를 매기면 전 업체가 「수집 중」인 빈 앱이 됩니다.

```
0층   실 제보 0건 · 업체 안내 있음    「업체 안내 150만원~」 회색 · 출처 표기
```

실 제보와 섞지 않고 대신 보여줍니다. 3건이 되면 자동 교체.

**출시 초기 추천 근거는 지역 + 스타일 + 업체 안내 가격**입니다. 추천 이유는 「고른 스타일이랑 맞아요」가 먼저고 「실 제보 N건」은 데이터가 생기면 등장합니다.

**빈 섹션은 접습니다.** 후기 0건 → 한 줄, 경험 3명 미만 → 숨김.

### 혜택 안내 시트 신설 · WP-SHT-017

온보딩 완료 후 홈 최초 진입 1회, 400ms 뒤. 네 혜택 중 금액이 가장 큰 **웨딩지원금 5만원**만 내세웁니다. 응모 조건 3개 나열 + 「혜택 보기」 / 「나중에」.

### 이벤트 예산 · 월 50만원

```
미션 4개 완주      5,000원 × 40커플    200,000
친구 초대          3,000원 × 50건      150,000
홍보 인증          2,000원 × 50건      100,000
월간 웨딩지원금     50,000원 × 1커플     50,000
```

미션 3만원 × 500커플은 1,500만원이라 원래부터 불가능한 숫자였습니다. 소진되면 다음 달에 다시 엽니다.

**미션 4번째를 «비교하기» → «Pick 인증 1건»으로 바꿨습니다.** 앱 안에서 끝나는 미션만 두면 5천원을 주고 데이터를 못 얻습니다. 완주율이 낮아져 소진이 3~4배 느려지고, 완주 1커플이 곧 실 제보 1건입니다.

### 광고 실운영 · 보류

사용자 오더 대기. 판단 데이터 미달.

### 잔상 수정

아이콘이 바뀔 때 2~3개가 동시에 보이던 문제를 고쳤습니다. `wpSwap` 키프레임이 5개 기준(20% 슬롯)으로 고정돼 있어 아이콘이 10개로 늘자 페이드가 슬롯을 넘었습니다.

개수별 키프레임 8종(`wpSwap5`~`wpSwap12`)을 두고 `wpSwap${ORDER.length}`로 씁니다. 슬롯 = `100/N %`, 홀드는 슬롯의 70%까지, 페이드는 슬롯 끝에서 정확히 끊습니다.

### 700ms 임계값

```
0~700ms      아무것도 띄우지 않음
700ms 초과   화면 성격과 무관하게 로더 노출
```

빈 화면이나 멈춘 화면을 보여주지 않습니다. `tokens.json`에 `motion.loaderThreshold`로 넣었습니다.

## v3.14 · 2026-09-08

### 초기 설정 4단계 → 2단계

예식일 · 지역 · 예산을 **한 화면**에서 이어서 묻습니다. 목록에서 하나 고르는 같은 성격이라 화면을 나눌 이유가 없었습니다.

```
기존   예식일 → 지역 → 예산 → 취향     4화면 · 1/4~4/4
변경   [예식일 · 지역 · 예산] → 취향    2화면 · 1/2~2/2
```

**고르면 다음 질문이 열립니다.** 값을 고른 질문은 위로 접혀 `✓ 예식일 · 2027년 5월 16일` 한 줄이 되고, 다음 질문이 아래에서 올라옵니다. 진행바는 8% → 38% → 68% → 100%로 이어집니다.

**되돌아가기는 접힌 줄의 「바꾸기」로** 합니다. 뒤로가기로 화면을 되감지 않습니다. 안드로이드 뒤로가기는 로그인으로 나가는 데만 씁니다.

**취향 이미지는 별도 화면 유지.** 사진을 훑는 성격이라 목록과 섞으면 둘 다 흐려집니다. 2×3 격자로 6장을 보여줍니다.

**건너뛰기 삭제.** 취향은 추천의 근거라 건너뛰면 첫 화면에 보여줄 것이 없습니다. 최소 1장을 받고 CTA에 고른 개수를 적습니다. 예산만 「아직 모르겠어요」를 남깁니다.

**다음 버튼은 값이 없으면 회색 비활성**입니다. 중간 질문에서는 고르는 순간 다음 질문이 열리므로 누를 일이 거의 없습니다.

| | 기존 | 변경 |
|---|---|---|
| 화면 수 | 4 | 2 |
| 진행 표시 | 1/4 ~ 4/4 | 1/2 ~ 2/2 |
| 되돌아가기 | 뒤로가기 | 접힌 줄의 바꾸기 |
| 취향 건너뛰기 | 있음 | 없음 |
| 취향 이미지 | 4장 | 6장 |

날짜를 고르면 필드 아래에 오늘 기준 D-day가 바로 나옵니다 — 「앞으로 250일 남았어요」 — 숫자만 코랄로 강조합니다.

예산 구간의 집계 문구(「가장 많은 구간이에요」)를 없앴습니다. 온보딩에서 남들 금액을 보여주면 앵커링이 생기고, 백엔드 집계가 필요한데 근거도 애매합니다.

예식일의 보조 칩(미정 · 봄 · 가을)을 없앴습니다. 기준이 애매해 D-day와 준비 순서를 계산할 수 없습니다. 날짜만 받습니다.

취향 이미지 3장을 실제 사진으로 교체했습니다 — 깔끔한 화이트 · 모던 미니멀 · 따뜻한 필름.

**기존 4단계 시안은 보존**합니다. `웨딩픽 진입 온보딩.dc.html`의 WP-APP-008~012는 그대로 두고 보류로 표시했습니다.
