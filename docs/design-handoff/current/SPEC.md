# 웨딩픽 · 기능 명세 (구현 지침)

Codex · Claude Code가 화면을 구현할 때 읽는 문서입니다. 화면 목록은 `screens.json`, 값은 `tokens.json`을 봅니다. 이 문서는 **화면에 보이지 않는 규칙**을 다룹니다.

---

## 0. 판단 기준

무언가 애매할 때 이 순서로 정합니다.

1. `tokens.json`에 값이 있으면 그 값을 쓴다.
2. `screens.json`에 layout·rule이 있으면 그대로 따른다.
3. 둘 다 없으면 **이 문서의 원칙**을 적용한다.
4. 그래도 애매하면 **만들지 않고 물어본다.** 임의로 새 패턴·새 색·새 문구를 만들지 않는다.

**최상위 검수 질문** — 이 화면만 봐도 웨딩픽이 먼저 골라주고 사용자는 비교해서 Pick하는 서비스라는 것이 이해되는가. NO면 다시 만든다.

## 1. 도메인 개념

### 1.1 정보 체계 3단 (혼동 주의)

| 개념 | 용어 | 정의 |
|---|---|---|
| 상위 개념 | **확인된 제보** | 사용자가 올린 자료를 검증해 만든 정보 전체 |
| 금액 | **제보 금액** | 확인된 제보로 집계한 금액 구간 |
| 제공 행동 | **Pick 인증** | 사용자가 자료를 올려 정보를 확인받는 행동 |

**금지어** — `확인된 정보` `확인된 금액` `실제로 낸 금액` `실제 결제` `실제 결제 데이터` `결제인증` `데이터`

이 세 용어는 서로 대체할 수 없습니다. 「확인된 제보 12건」은 건수, 「제보 금액 152~184만원」은 금액, 「Pick 인증하기」는 행동입니다.

### 1.2 Pick vs 결정

| | Pick | 최종 결정 |
|---|---|---|
| 의미 | 후보에 담기 | 이 업체로 하기 |
| 화면 | Pick 탭 | 우리웨딩 |
| 개수 | 업종당 여러 개 | 업종당 1개 |
| 되돌리기 | Pick 해제 | 결정 취소 |
| 배우자 | 각자 Pick, 공통 Pick 존재 | 함께 결정 |

**관심업체 · 찜 · 저장 개념은 없습니다.** Pick 하나로 통합했습니다. 「저장했어요」 같은 문구를 쓰지 않습니다.

### 1.3 업종 (카테고리)

```
웨딩홀 · 스튜디오 · 드레스 · 메이크업 · 본식스냅
결혼정보회사 · 예물 · 혼수 · 허니문 · 청첩장
```

`카테고리`라는 단어를 사용자 화면에 노출하지 않습니다. `업종`을 씁니다.

## 2. 정보 4단계 (가장 자주 틀리는 부분)

확인된 제보 건수에 따라 **금액 표기 자체가 달라집니다.** 서버가 건수를 함께 내려주고 클라이언트가 표기를 결정합니다.

| 건수 | 금액 표기 | 부가 표기 |
|---|---|---|
| 0~2건 | `수집 중` | `아직 정보가 적어요 · N건` |
| 3~4건 | `152~184만원` | `확인된 제보 3건` + 정보가 적다는 안내 |
| 5~9건 | `152~184만원` | `확인된 제보 7건 · 최근 12개월` |
| 10건 이상 | `152~184만원` | `확인된 제보 12건 · 최근 12개월 · 기준금액 168만원` + 조건별 분포 |

**규칙**
- 빈 칸이나 `—`를 쓰지 않는다. 항상 문자열이 들어간다.
- `수집 중`일 때 금액 텍스트 색은 `#868B94`로 낮춘다.
- 건수가 0이어도 업체를 목록에서 빼지 않는다.
- 기준금액은 10건 이상에서만 노출한다. 그 아래에서는 중앙값을 계산해도 보여주지 않는다.

### 금액 표기 포맷 (고정)

```
152~184만원
확인된 제보 12건 · 최근 12개월 · 기준금액 168만원
```

검색 · TOP3 · 업체상세 · 비교 · 홈 추천에서 **동일하게** 사용합니다. 구분자는 ` · ` (공백-중점-공백)입니다.

기준금액 ⓘ 설명은 `확인된 제보의 중앙값이에요`로 고정입니다.

## 3. 로그인과 회원 상태

### 3.1 비회원 이용은 없습니다

스플래시 다음이 바로 로그인입니다. 둘러보기 경로와 지연 로그인 시트를 폐기했습니다.

로그아웃 · 세션 만료 · 토큰 무효 상태는 **항상 WP-AUTH-001로 보냅니다.** 로그인 전에 볼 수 있는 화면은 로그인 4개(WP-AUTH-001~004)뿐입니다.

**폐기된 것**

```
WP-APP-004   시작 화면 · 둘러보기 경로
WP-HOME-008  비회원 홈
WP-SHT-001   지연 로그인 시트 → 다른 방법으로 시작 시트로 대체
WP-ST-001    비회원 상태 → 세션 만료로 대체
```

### 3.2 소셜 로그인 4종만

| | |
|---|---|
| 카카오 | 첫 화면 Primary · `#FEE500` 배경 `#191919` 글자 |
| 네이버 | 시트 1번 · `#03C75A` 배경 흰 글자 |
| 구글 | 시트 2번 · 흰 배경 `#212124` 글자 `#DCDEE3` 테두리 |
| 애플 | 시트 3번 · 검정 배경 흰 글자 |

**이메일 로그인은 지원하지 않습니다.** 비밀번호 입력 · 찾기 · 재설정 화면을 만들지 않습니다.

첫 화면에는 카카오만 노출하고 나머지는 시트로 접습니다. 로그인 화면에도 화면당 Primary CTA 1개 원칙을 적용합니다.

### 3.3 재실행

마지막 계정을 기억해 「카카오로 계속하기」로 바꿉니다(WP-AUTH-003). 다른 계정으로 바꿀 길을 바로 아래에 둡니다.

세션이 살아 있으면 로그인 화면을 건너뛰고 홈으로 갑니다.

### 3.4 로그인 후 흐름

```
WP-AUTH-001 로그인
  ↓ 최초 로그인이면
WP-APP-008~011 초기 설정 4단계
  ↓
WP-APP-012 완료 → 홈
```

이미 설정을 마친 계정이면 로그인 직후 홈으로 갑니다.

### 3.5 Pick 인증 회원

Pick 인증이 1건 이상 반영된 회원입니다. 얻는 것:

- 조건이 비슷한 제보 상세 열람
- 후기 작성 시 `Pick 인증` 배지 자동 부여
- 월간 웨딩지원금 응모 조건 충족

**기능을 잠그지 않습니다.** 인증하지 않아도 모든 화면을 볼 수 있고 금액 구간도 봅니다. 추가 정보만 열립니다.

## 4. 배우자 연결

### 4.1 공유 범위

| 항목 | 공유 | 비고 |
|---|---|---|
| Pick한 곳 | O | 둘 다 고른 곳이 상단으로 |
| 일정 | O | 한 명이 넣으면 둘 다 알림 |
| 지출 | O | 등록자 표기 |
| 메모 | O | 작성자 표기 |
| 최종 결정 | O | 함께 |
| 검색 기록 | X | 각자 |
| 알림 설정 | X | 각자 |

**항목별로 켜고 끌 수 있습니다** (WP-MY-006). 스위치를 끄면 그 항목만 숨겨지고 연결은 유지됩니다.

### 4.2 동시 편집 충돌 (WP-CPL-004)

**자동 병합하지 않습니다.** 두 버전을 나란히 보여주고 사용자가 고릅니다.

```
상대 변경  coral 1.5px 테두리 + brand 배경
내 변경    회색 1px 테두리 + 흰 배경
```

고른 내용이 둘 모두에게 반영되고, 「나중에 다시 바꿀 수 있어요」를 함께 적습니다. 충돌은 마지막 저장 시각으로 판정합니다.

### 4.3 연결 해제

공유가 멈추고 **지금까지 쌓인 기록은 각자에게 남습니다.** 함께 쓴 메모는 각자 사본으로 남습니다. 상대에게 알림이 갑니다.

## 5. Pick 인증 · OCR 흐름

```
WP-RPT-002 이미지 선택
  ↓
WP-RPT-003 분석 (OCR)
  ↓
WP-RPT-004 확인 ← 핵심 화면
  ↓ 업체가 불확실하면
WP-RPT-005 업체 확인
  ↓ 같은 거래 감지되면
WP-RPT-006 묶기
  ↓
WP-RPT-007 제출 완료
  ↓ 자동 검증
WP-RPT-008 처리 결과
```

### 5.1 WP-RPT-004 확인 화면이 핵심입니다

OCR이 읽어낸 항목과 확신이 낮은 항목을 **시각적으로 분리**합니다.

| | 읽어낸 항목 | 확인 필요 항목 |
|---|---|---|
| 카드 배경 | `#F7F8FA` recessed | `#FFFFFF` |
| 테두리 | 없음 | `1.5px #FF6F61` |
| 태그 | `읽었어요` 회색 | `확인 필요` coral 채움 |
| 힌트 | 없음 | 왜 확인이 필요한지 한 줄 |

Hero는 확인 필요 개수를 말합니다 — 「두 가지만 확인해주세요」. 전부 읽었으면 「그대로 제보할까요?」

### 5.2 필드 라벨

| 내부 필드 | 사용자 화면 |
|---|---|
| amount | **낸 금액** |
| paidAt | **낸 날짜** |
| status | **상태** |
| vendor | **업체** |
| product | **상품** |

`결제금액` `결제일` `결제상태`를 쓰지 않습니다.

### 5.3 분할 묶기 (WP-RPT-006)

같은 업체·비슷한 시기의 기존 제보가 있으면 묶을지 묻습니다.

```
같이 묶을까요?
같이 묶으면 총 182만원이에요.
```

`같은 거래인가요?` `거래 내역` `트랜잭션`을 쓰지 않습니다.

### 5.4 원본 삭제

확인이 끝난 원본 이미지는 **24시간 안에 삭제**합니다. 이 사실을 3곳에서 알립니다 — 권한 요청 시트 · 업로드 화면 안내 · 제출 완료 화면.

## 6. 후기

### 6.1 별점을 쓰지 않습니다

3축 3지선다입니다.

| 축 | 선택지 |
|---|---|
| 진행은 어땠나요 | 빨랐어요 / 적당했어요 / 늘어졌어요 |
| 결과물은 어땠나요 | 기대 이상 / 기대만큼 / 아쉬웠어요 |
| 추가 비용 안내는요 | 명확했어요 / 보통이었어요 / 불친절했어요 |

본문 500자. 사진 선택.

집계 화면(WP-REV-006)은 「14명이 답했어요」 + 항목별 막대 + 많이 나온 말 칩입니다. **평점 숫자를 만들지 않습니다.**

### 6.2 업체 반론

원 후기 아래에 붙습니다. **원 후기를 지우거나 고치지 않습니다.**

```
[원 후기]  김OO · Pick 인증 · 2026.07
           촬영 당일 진행이 빨라서...

[업체 반론]  강남 A 스튜디오 · 관계자 확인
             보정 기간은 성수기 기준 3~4주로...
```

반론 등록은 WP-BIZ-004에서 하고, 소속 확인(WP-BIZ-002)을 통과해야 합니다.

### 6.3 신고

사유 5개 라디오 + 상세 입력(선택). 자동 검토하고 하루 안에 처리합니다.

「개인 경험을 적은 후기는 신고 대상이 아니에요」를 하단에 명시합니다.

## 7. 광고 (구현 시 필수)

### 7.1 독립성

광고비와 요금제 등급은 다음에 **영향을 주지 않습니다.**

```
웨딩픽 TOP3
오늘의 Pick
개인화 추천
자연 검색순위
확인된 제보
후기 및 후기 순위
```

**구현** — 광고 랭킹은 자연 추천과 **분리된 별도 테이블**로 관리합니다. 추천 쿼리에 광고 가중치 컬럼이 들어가면 안 됩니다.

### 7.2 노출 표기

광고 슬롯에는 `광고` 라벨을 반드시 표시합니다. 위치는 이미지 좌상단, 배경 `rgba(0,0,0,.5)`, 흰 텍스트 13px.

자연 결과 사이에 광고를 끼워넣지 않습니다. 별도 영역에 둡니다.

### 7.3 요금제

| 플랜 | 월 정액 | 슬롯 |
|---|---|---|
| LIGHT | 30,000원 | 업체 상세 스폰서 |
| STANDARD | 70,000원 | 업체 상세 + 검색 |
| PREMIUM | 150,000원 | 업체 상세 + 검색 + 지역·업종 |

첫 달 무료 또는 50% 할인 **1회**. 영구 무료 없음.

### 7.4 실운영 전환 게이트 (WP-ADM-034)

```
테스트 전체 오픈 → 판단 데이터 충족 → GPT 독립 분석
→ Claude 독립 분석 → 보고서 2건 → 사용자 최종 결정 → 실운영
```

**종료일을 고정하지 않습니다.** 데이터 충족 여부로 분석 시점을 정합니다. 두 AI의 판단이 갈려도 합의하지 않고 그대로 제출합니다. **오픈 스위치는 사람만 조작합니다.**

현재 상태 — 테스트 중 · 판단 데이터 미달 · 사용자 오더 대기

## 8. 회원탈퇴 데이터 처리

**원칙** — 탈퇴 = 개인정보 삭제. 검증된 비식별 서비스 정보까지 삭제하는 것은 아닙니다. **통합 보존기간(30일 등)을 두지 않습니다.**

### 즉시 삭제

```
계정정보 · 프로필
배우자 연결정보
Pick · 취향 · 개인화
일정 · 체크리스트
개인 지출내역
```

### 작성자 정보 분리 후 유지

```
Pick 인증 자료      → 목적 달성 시 삭제
제보에서 추출한 비식별 정보 → 유지
작성 후기           → 작성자 정보 제거 후 유지
업체별 금액 구간 · 건수  → 유지
```

### 별도 보관

```
신고 · 분쟁 기록      → 처리 및 법적 필요기간
법령상 보존 의무 정보  → 법정기간 후 삭제
```

**화면 문구** — 「지워지는 것」 / 「작성자 정보와 분리되는 정보」로 섹션을 나눕니다. `보존 데이터` `탈퇴 후 유지 데이터` 같은 관공서 언어를 쓰지 않습니다.

## 9. 홈 우선순위 엔진 (WP-HOME-002)

히어로에 무엇이 올라오는지 8단계로 정합니다. **위에서 걸리는 첫 항목**이 올라옵니다.

| 순위 | 조건 |
|---|---|
| 1 | 긴급 일정 — 오늘·내일 일정이 있으면 |
| 2 | 다음 할 일 — 현재 준비 단계의 마감이 가까우면 |
| 3 | Pick 후보 변화 — 배우자가 새로 골랐거나 금액이 바뀌면 |
| 4 | 커플 공통 취향 — 둘 다 고른 곳이 3곳 이상이면 |
| 5 | 예산 초과 — 지출이 예산의 90%를 넘으면 |
| 6 | 웨딩픽 TOP3 — 추천 근거가 충분하면 |
| 7 | 혜택 · 정보 변경 — 마감이 가까운 혜택이 있으면 |
| 8 | 일반 추천 — 위에 걸리는 것이 없으면 |

**근거가 없으면 추천하지 않습니다.** 판단할 정보가 부족하면 다음 일정으로 대체합니다. 억지로 추천 문구를 만들지 않습니다.

## 10. 이미지

### 10.1 우선순위

```
업체 제공 → 사용 허가 → 공공 · 공식 → 업종 기본 이미지
```

**`사진 준비 중` 문구나 빈 상자를 노출하지 않습니다.** 업종 기본 이미지로 자연스럽게 대체합니다.

인물 얼굴이 잘리는 사진은 업체 제공이어도 쓰지 않고 다음 순위로 넘어갑니다.

### 10.2 예시 데이터 분리 (중요)

| | 업체명 | 이미지 |
|---|---|---|
| **웹** | 가명 `강남 A 스튜디오` 형식 유지 | 샘플 이미지 유지 |
| **앱** | 실제 업체명 | 실제 이미지 |

웹은 공개 화면이라 실제 상호와 실제 촬영물을 노출하지 않습니다. 앱은 서비스 화면이라 실제 데이터를 씁니다. **시안의 가명은 앱 개발 시 실제 데이터로 대체합니다.**

금액은 웹·앱 모두 확인된 제보로 집계한 실제 구간을 씁니다.

### 10.3 규격

`tokens.json`의 `image.specs`를 봅니다. crop은 중앙 cover입니다.

## 11. 문구 규칙

### 11.1 금지어

**AI** — 사용자 화면에 `AI`를 노출하지 않습니다.

| 사용 | 금지 |
|---|---|
| 오늘의 Pick | AI 추천 |
| 웨딩픽 TOP3 | AI TOP3 |
| 웨딩픽이 비교했어요 | AI가 분석했어요 |
| 웨딩픽 콘텐츠 | AI 웨딩 콘텐츠 |
| 추천 이유 | AI 분석 결과 |

내부 개발 · 관리자 · 비용관리 문서에서는 AI 용어를 유지합니다.

**운영자 용어** — `안내` `제공` `지급` `검증` `반려` `처리` `수집`을 사용자 화면에서 사용자 표현으로 바꿉니다.

| 사용 | 금지 |
|---|---|
| Pick 인증이 안 됐어요 | Pick 인증이 반려됐어요 |
| 리워드가 아직 안 들어왔어요 | 리워드가 지급되지 않았어요 |
| 확인하는 데 최대 하루 걸릴 수 있어요 | 검증에 하루가 걸립니다 |

**애매모호 표현** — `거의` `아마` `대략` `어느 정도` `가능성이 높음` `~일 것으로 보임`

대신 상태를 직접 씁니다 — `확정` `미확정` `검증 전` `확인 필요` `조건부` `측정값` `추정값`

```

```

같은 의미를 서로 다른 섹션에서 반복하지 않습니다. 화면당 Primary CTA는 1개입니다.

### 11.3 톤

- `-요` 체. `-습니다` 쓰지 않음
- 느낌표 쓰지 않음
- 이모지 쓰지 않음

- 명사형보다 행동형
- 부정 명령형보다 긍정 결과형

```

## 14. React Native 변환 시 주의

HTML 시안을 RN으로 옮길 때 그대로 안 되는 것들입니다.

| HTML | RN 대체 |
|---|---|
| `box-shadow: inset 0 1px 0` | `borderTopWidth: 1` + `borderTopColor` |
| `box-shadow: inset 0 -1px 0` | `borderBottomWidth: 1` + `borderBottomColor` |
| `color-mix()` | 고정값 — `#FFE8E4`(tint) · `#FFF5F2`(surface) · `#FFD9D4`(border) |
| `text-wrap: pretty` | 없음 |
| `-webkit-line-clamp: 2` | `numberOfLines={2}` |
| `aspect-ratio` | `<View style={{aspectRatio}}>` (RN 0.71+) |
| `gap` | RN 0.71+ 지원. 이하면 margin |
| `position: sticky` | 없음. `FlatList` `stickyHeaderIndices` |
| `overflow-x: auto` | `<ScrollView horizontal>` |
| `linear-gradient` | `react-native-linear-gradient` |
| `data:image/svg+xml` | `react-native-svg`로 직접 그림 |
| `font-variant-numeric: tabular-nums` | `fontVariant: ['tabular-nums']` |
| `cursor: pointer` | 제거 |
| `::part(empty)` | 제거 |

### 심볼

Pick Mark는 `react-native-svg`의 `<Path>` 2개로 그립니다. `tokens.json`의 `symbol.paths`를 그대로 씁니다. **path를 다시 그리지 않습니다.**

### 안전 영역

```
statusBar            safeTop
tabBar               72 + max(safeBottom, 0)
dock                 92 + max(safeBottom, 0)
sheet 하단 패딩        28 + max(safeBottom, 0)
```

| 기기 | safeBottom |
|---|---|
| iOS 노치 | 34 |
| iOS 홈버튼 · SE | 0 |
| Android 제스처 | 16~24 |
| **Android 3버튼** | **0 ← inset이 0으로 온다** |

**Android 3버튼이 하단 잘림의 원인입니다.** 시스템 바가 앱 영역 밖에 있어 inset이 0으로 옵니다. edge-to-edge를 켜면 48px 바가 탭바를 덮습니다. 3버튼 기기에서는 edge-to-edge를 끄거나 WindowInsets를 직접 읽습니다.

하단 고정 요소에만 inset을 더합니다. 스크롤 내용에는 넣지 않습니다. 넣으면 스크롤 끝에 빈 공간이 두 번 생깁니다.

`34` `18` `48` 같은 숫자를 상수로 박지 않습니다.

### 플랫폼 차이

| 항목 | iOS | Android |
|---|---|---|
| 뒤로가기 | 좌상단 화살표 + 스와이프 | **물리 버튼 · 제스처 — 화면마다 처리** |
| 자간 | 0em | **display −0.04 / title −0.03 / body −0.02 / caption −0.04em** |
| 시트 닫기 | 드래그 · 배경 탭 | 드래그 · 배경 탭 · **뒤로가기** |
| 권한 재요청 | 한 번 거부하면 설정으로만 | **두 번 거부하면 영구 차단** |
| 폰트 | Apple SD Gothic Neo | Roboto · Noto Sans KR |
| 화면 전환 | 오른쪽에서 밀려 들어옴 | 아래에서 올라오며 페이드 |
| 공유 | UIActivityViewController | Intent Chooser |
| 상태바 아이콘 | 자동 반전 | light · dark 직접 지정 |

**안드로이드 자간을 넣지 않으면** 글자가 벌어져 2줄 제목이 3줄로 터집니다. 「이번 주엔 스튜디오를 정할 차례예요」가 대표적입니다.

### 뒤로가기 처리

| 상황 | 뒤로가기를 누르면 | |
|---|---|---|
| Root 5탭 | 앱을 닫는다. 홈 탭이 아니면 홈 탭으로 먼저 | 탭 이동 |
| 바텀시트 열림 | 시트만 닫는다. 화면은 그대로 | **필수** |
| 초기 설정 4단계 중 | 이전 단계로. 첫 단계에서는 로그인으로 | **필수** |
| Pick 인증 진행 중 | 나가면 자료가 사라진다고 묻는다 | 확인 |
| 후기 작성 중 · 내용 있음 | 임시 저장할지 묻는다 | 확인 |
| 검색 결과 · 업체 상세 | 이전 화면으로 | 기본 |
| 이미지 전체보기 | 상세로 돌아간다 | 기본 |
| 결정 완료 · 연결 완료 | 뒤로 못 간다. 다음 화면으로만 | **차단** |

처리하지 않으면 안드로이드에서 시트만 닫혀야 할 때 화면 전체가 뒤로 갑니다. 온보딩 4단계에서 이러면 처음으로 돌아갑니다.

```

[ ] 정보 부족 상태를 그렸는가

[ ] 안드로이드 자간을 적용했는가
[ ] 안드로이드 뒤로가기를 화면별로 처리했는가
