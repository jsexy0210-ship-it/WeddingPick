# 하이브리드 웹 렌더링 QA 체크리스트

`apps/mobile`을 `expo export --platform web`(react-native-web)으로 뽑아 웹뷰에
태울 때, 각 화면이 실제로 웹에서도 정상 동작·정상 디자인인지 점검하는 기준.
사용자가 준 바이브코딩(v0/Cursor/Bolt류) 검증 체크리스트를 이 저장소 구조에
맞게 옮겼다. 병렬로 화면을 점검하는 모든 세션이 이 기준을 그대로 쓴다.

## 1. 레이아웃 & 반응형

- [ ] 모바일(~430px) · 태블릿(768px) · 데스크톱(1280px+) 폭에서 레이아웃이 깨지거나
      불필요한 가로 스크롤이 생기지 않는가
- [ ] 마진·패딩이 `packages/ui/src/theme.ts`의 `Layout`/`Spacing` 토큰만 쓰는가
      (RN에서는 넘어갔어도 웹 렌더링에서 픽셀 어긋남이 새로 보일 수 있다)
- [ ] 텍스트가 길어지거나 데이터가 비었을 때 요소를 뚫고 나가지 않는가
      (`numberOfLines` RN 속성은 웹에서 다르게 동작할 수 있음 — 실제 렌더 확인)

## 2. 디자인 토큰 & 스타일

- [ ] `apps/api/src/test/typography.test.ts`가 이미 잡는 하드코딩(`fontSize:`,
      `lineHeight:`) 외에, 색상 hex가 `@weddingpick/ui` 테마 대신 직접 박혀있지
      않은가
- [ ] 제목·본문·캡션 간 크기·굵기 위계가 웹에서도 그대로 보이는가
- [ ] 다크모드 전환 시 하드코딩 색 때문에 글자가 배경에 묻히는 영역이 없는가

## 3. 인터랙션 & 상태 (RN → 웹 전환에서 가장 잘 빠지는 항목)

- [ ] 버튼·입력창·카드에 기본 상태 외 **hover·focus** 스타일이 있는가 — RN은
      터치 전용이라 원래 없는 경우가 많다. 웹에서는 마우스 사용자를 위해
      최소한 `:hover`/`:focus-visible` 스타일이 있어야 한다
      (`Pressable`의 `style` 함수형 prop으로 `{ pressed }` 외 웹 전용 상태 처리 검토)
- [ ] 비활성(disabled) 상태가 시각적으로 구분되는가
- [ ] 아이콘 크기·스타일이 화면 내에서 통일됐는가, 이미지 비율이 안 찌그러지는가
      (`VendorImage` 등 컴포넌트의 `resizeMode`가 웹에서 `object-fit`으로 맞게
      변환되는지 확인)
- [ ] 상태 전환 애니메이션이 과하지 않고 자연스러운가 (§7 모션 규칙 — 누름
      100ms, 시트 진입 350ms 등)

## 4. 코드 구조 & 컴포넌트화

- [ ] 화면 파일이 지나치게 길면(수백 줄 JSX 한 덩어리) 재사용 단위로 나눴는가
- [ ] 모달·시트·툴팁이 다른 요소 아래로 숨거나 레이아웃을 밀어내지 않는가 —
      RN의 `Modal`/`elevation`은 웹에서 `z-index`로 바뀐다. 네이티브에서는
      문제없던 겹침이 웹 렌더링에서 새로 나타날 수 있는 대표 항목

## 5. 이 저장소 고유 기준 (CLAUDE.md 전체 적용)

- [ ] Pick Mark(§2), 색 규칙(§5), 타이포 8단계(§6), 상태 완전성(§8),
      광고 독립성(§9) — 웹 렌더링에서도 전부 유지되는가
- [ ] `node lint-copy.js apps/ packages/` 통과 (문구는 렌더링 경로와 무관하게 동일)

## 점검 결과 기록

화면 하나를 점검했으면 대시보드(마스터 세션이 알려주는 아티팩트 URL)에
`screen_id`, `verdict`(pass/fixed/blocked), 발견한 문제와 조치를 기록한다.
문제를 고쳤으면 커밋 전에 이 체크리스트를 다시 훑고, 전부 통과할 때만 푸시한다.
