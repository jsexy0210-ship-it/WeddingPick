# Handoff: 웨딩픽(WeddingPick) 모바일 앱

## Overview

결혼 준비 과정을 한곳에서 관리하고, 이용자가 등록한 실제 결제내역을 모아 업체별 결제 구간을 보여주는 모바일 앱입니다. 업체 탐색 → 준비 일정 관리 → 배우자 공유 → 결제 데이터 확인의 4단계 흐름으로 구성되며, 각 단계를 완료할수록 이용 등급과 열람 범위가 올라갑니다.

핵심 원칙 두 가지가 화면 전반을 지배합니다.

1. **웨딩픽은 가격의 적정 여부를 판정하지 않습니다.** 모든 금액 표기는 구간·표본 수·기준 기간을 함께 노출합니다. "진짜 가격", "적정가", "정확한 가격" 같은 표현은 사용하지 않고 `가격 차이 / 실제 결제 사례 / 결제 구간 / 결제 분포`로 통일합니다.
2. **웨딩픽은 중개하지 않습니다.** 업체 매칭·계약 대행·성혼 보장을 하지 않으며, 업체 공식 창구로 연결만 합니다.

## About the Design Files

이 번들의 HTML 파일은 **디자인 레퍼런스**입니다. 의도한 레이아웃·인터랙션·카피를 보여주는 프로토타입이며 그대로 배포할 프로덕션 코드가 아닙니다.

목표는 이 HTML 디자인을 **대상 코드베이스의 기존 환경에서 다시 구현하는 것**입니다. React Native, Flutter, SwiftUI, 웹 등 이미 쓰고 있는 프레임워크와 컴포넌트 라이브러리, 상태 관리 패턴을 그대로 따르세요. 아직 환경이 없다면 프로젝트에 가장 적합한 프레임워크를 선택해 구현하면 됩니다.

프로토타입은 단일 HTML 파일 안에서 화면 전환을 상태로 처리했지만, 실제 앱에서는 라우팅·화면 스택으로 옮겨야 합니다.

## Fidelity

**High-fidelity.** 색상, 타이포그래피, 간격, 라디우스, 모션 값이 모두 확정돼 있습니다. 아래 디자인 토큰 값을 그대로 사용해 픽셀 단위로 재현하세요.

단, 프로토타입은 **Toss TDS Mobile 디자인 시스템**을 기반으로 만들어졌습니다. 대상 코드베이스에 자체 디자인 시스템이 있다면 그쪽 컴포넌트로 치환하되, 아래 명시한 크기·간격·상태 규칙은 유지하세요.

- 목록 행 최소 높이 **56px**, 터치 타깃 최소 **44×44**
- 라디우스: 버튼 10~16, 입력 12, 카드/그룹 16~20, 바텀시트 상단 24, 아바타·칩 999

### Motion

- 진입: `350ms cubic-bezier(.16,1,.3,1)`

- 반복 애니메이션 없음. 축하 연출도 1회만 재생

390 × 844 (iOS 기준). 상태바 44px, 네비게이션바 56px, 탭바 74px.

## 이용 등급 (Role)

4단계이며 화면 전체가 이 값에 반응합니다.

| 등급 | 조건 | 열람 범위 |
|---|---|---|
| 게스트 | 비회원 | 검색, 업체 상세 전체(공식 안내·업체평가·인증후기·공식정보), 비교함, MY |
| 메이트 | 로그인 | + 우리웨딩(지출내역·웨딩 스케줄·방문노트), 관심업체 저장, 결제내역 등록 |
| 프렌드 | 배우자 연결 | + 지출·일정·관심업체 공유 |
| 패밀리 | 결제인증 | + 실제 결제 구간, 시기별 분포 |

**로그인이 필요한 지점은 우리웨딩과 결제내역 등록 두 곳뿐입니다.** 나머지는 비회원에게 모두 공개합니다.

등급이 바뀌면 함께 바뀌는 것: MY 프로필 배지, 나의 웨딩 미션 체크 상태, 업체 상세의 실제 결제 블록(잠금 카드 ↔ 잉크 블록), MY 통계 숫자, 계정 메뉴 라우팅.

## Screens

전체 21개 화면입니다.

### 0. 스플래시

blue500 전면. 64px 흰색 하트+체크 심볼 단독(컨테이너 없음), 아래로 `웨딩픽` (26/35/-0.6/700, 흰색)과 `WeddingPick` (13/19.5, letter-spacing 1.4, 600, 흰색 62%).

심볼은 `480ms cubic-bezier(.16,1,.3,1)`로 0.88→1 페이드인, 텍스트는 200ms·280ms 지연으로 8px 아래에서 올라옵니다. 1.4초 후 온보딩으로 자동 전환.

슬로건은 넣지 않습니다. 서비스 설명은 바로 다음 온보딩에서 합니다.

### 1. 온보딩 (5장)

**Purpose** 서비스 가치와 미션 구조를 소개

**Layout** 상단 우측 건너뛰기 → 진행 인디케이터(활성 22×6px blue500, 비활성 6×6px grey200, radius 999) → t2 헤드라인 → t6 설명 → grey50 예시 카드(radius 20, padding 24, 항목별 라벨/값 행) → 카드 아래 t7 캡션 → 하단 고정 CTA(xlarge, full)

**콘텐츠**

1. `같은 업체도 / 결제 금액은 달라요` — 업체 안내 가격과 실제 결제 사례를 한눈에 비교해보세요. / 업체 안내 390만원, 실제 결제 구간 265~305만원 / 결제인증 34건 · 최근 12개월
2. `결제내역 한 장으로 / 가격 차이를 확인해보세요` — 결제내역이나 영수증을 등록하면 필요한 정보만 읽어 자동으로 정리해요. / 내 결제 312만원, 유사 결제 구간 265~305만원 / 원본 이미지는 24시간 내 삭제돼요
3. `둘이 함께 / 결혼 준비를 정리해요` — 지출내역과 웨딩 스케줄을 공유하고 준비 상황을 함께 확인해보세요. / 지금까지 결제 872만원, 남은 준비 12개 / 초대 코드로 간편하게 연결해요
4. `웨딩 미션을 완료하면 / 모든 기능이 열려요` — 웨딩픽을 이용하면서 하나씩 완료해보세요. / 업체를 살펴봐요 `바로 시작`, 준비를 정리해요 `로그인`, 배우자와 함께해요 `초대 코드`, 결제 데이터를 확인해요 `결제내역 1건` / 진행 상황은 MY에서 확인할 수 있어요
5. `홈은 원하는 순서로 / 바꿀 수 있어요` — 자주 보는 항목을 위로 올리고 필요 없는 항목은 숨겨보세요. / 웨딩 스케줄 표시, 지출 현황 표시, 관심업체 숨김 / 홈 맨 아래 홈 편집에서 바꿀 수 있어요

CTA는 마지막 장에서 `웨딩픽 시작하기`, 그 외 `다음`. 건너뛰기와 마지막 CTA 모두 다음 화면(이름·예식일 등록)으로 이동합니다.

**Purpose** 필수 정보 수집. 뒤로가기·건너뛰기·탭바 없음

**이름 필드**

두 값이 모두 유효해야 완료 버튼이 활성화됩니다.

### 3. 예식일 캘린더 (바텀시트)

**날짜 셀** 44px 높이, 내부 38px 원
- 선택: blue500 배경 + 흰 글씨 + 700
- 오늘: 1.5px blue500 테두리
- 오늘 포함 과거: grey300, 탭 불가 — **결혼식은 미래이므로 당일과 과거는 선택할 수 없습니다**

섹션 순서(홈 편집으로 변경 가능, D-Day와 다음 일정은 고정):

### 6. 홈 편집 (바텀시트)

`끌어서 순서를 바꾸고, 필요 없는 항목은 숨길 수 있어요`. 5개 행(퀵메뉴·웨딩 스케줄·지출 현황·관심업체·결제 데이터 안내)에 드래그 핸들 + Switch. 드래그 중 행은 blue50 배경 + opacity 0.7. 초기화 / 완료.

구현 시 순서는 flex `order`로 처리했습니다. 실제 앱에서는 배열 순서로 렌더하세요.

### 7. 검색

SearchField(자동완성 드롭다운, 업체명·지역 매칭) → 카테고리 칩 가로 스크롤(활성 grey900/흰 글씨, 비활성 grey100/grey700) → 정렬 드롭다운(인기 순 / 금액 낮은 순 / 금액 높은 순) + 카테고리 개수 → 업체 카드 목록 → 하단 고정 트레이

**업체 카드** 업체명·지역 / `업체담기`·`빼기` 버튼(small weak) / 실제 결제 구간 / 출처 캡션

**트레이** height 70, 문구 좌측 · 비교함 버튼 우측 고정. 2곳 미만이면 `같은 카테고리만 비교할 수 있어요` + 비활성 스타일

**규칙** 서로 다른 카테고리를 담으려 하면 토스트로 차단, 최대 3곳

### 8. 업체 상세

헤드라인(업체명) + 지역·영업상태 → 실제 결제 블록 → 업체 제공 정보 → 업체평가 → 인증후기 → 공식정보 → `상담연결`

**실제 결제 블록** — 패밀리 등급에서만 blue500 잉크 블록으로 노출. 구간, 최저·최고 분포 막대, 표본·기간. 그 외 등급에서는 grey50 잠금 카드(`결제내역을 등록하면 확인할 수 있어요`)

**업체평가** — 항목별 ProgressBar. 70 미만은 주황, 표본 부족은 `수집 중` + grey. 캡션 `별점이 아니라 체크리스트 응답을 환산한 값이에요`

**인증후기** — 단계 배지(계약인증·이용인증·상담제보) + 조건 + 본문 + 실납부·출처. 게시 승인된 업체 반론이 있으면 후기 아래 blue500 세로선 블록으로 함께 표시

**공식정보** — 제목 우측 `공공데이터` 배지, 탭하면 기관·출처·기준일 툴팁

### 9. 비교함

`한눈에 비교하고 / 더 쉽게 선택해요` → 주의 툴팁 버튼 → 업체별 열(X 버튼으로 제거) → 카테고리별 항목 행 → `표본 수가 다르면 순위를 매기지 않아요` → `의견 공유하기`

열 수에 따라 `grid-template-columns: 80px repeat(N, 1fr)`. 2곳 미만이면 빈 화면.

카테고리별 비교 항목이 다릅니다. 결정사는 가입비·계약기간·소개 횟수, 웨딩홀은 대관료·보증인원·1인 식대, 스튜디오는 촬영 시간·원본 제공.

### 10. 결제내역 등록 동의 — **최초 1회만**

아이브로우 `결제내역 최초 등록 안내` → t2 `결제내역으로 / 가격 차이를 확인해보세요` → 전체 동의 Checkbox → 5행 안내 표 → 하단 고지 → `동의하고 시작하기`

| 항목 | 안내 |
|---|---|
| 수집 정보 | 업체 · 금액 · 결제일 |
| 처리 방식 | 개인정보 자동 마스킹 |
| 이용 목적 | 결제인증 · 가격 통계 |
| 보관 기간 | 원본 최대 24시간 |
| 등록 기준 | 본인의 결제내역만 가능 |

하단: `원본 이미지는 최대 24시간 내 삭제하며, 불필요한 개인정보는 저장하지 않아요. / 이 안내는 최초 등록 시 1회만 확인하며, 이후에는 바로 등록할 수 있어요.`

전체 동의 전에는 CTA 비활성. 동의 이후 재진입 시 바로 촬영 화면으로 갑니다.

grey900 전면. 3:4 가이드 프레임, 품질 피드백 3행(밝기·흔들림·잘림), 68px 셔터. 앨범 업로드 없음.

### 13. 등록 완료

### 14. 우리웨딩 — 지출내역

도넛 차트(140px, 구멍 94px, conic-gradient) + 4행 범례 → 총 예산 블록(수정 → 바텀시트) → 항목 목록(출처 표기) → 잔금 예정 행(회색) → `잔금은 예식 후 결제라 아직 더하지 않았어요`

예산 미등록 상태로 우리웨딩에 진입하면 총 예산 시트가 자동으로 뜹니다.

### 15. 우리웨딩 — 웨딩 스케줄

기본 14개 프리셋 제공. 웨딩홀 계약 → 결정사 가입 → 스튜디오 촬영일 → 드레스 투어 → 메이크업 시연 → 본식 스냅·영상 → 청첩장 시안 → 예복 맞춤 → 예물·예단 → 신혼여행 예약 → 혼인신고 서류 → 하객 명단 정리 → 식순·사회자 확정 → 웨딩홀 잔금 납부

행 구조: 항목명 / `9월 2일 · 스튜디오 이로` / 상태 배지 / X 삭제 버튼. 탭하면 수정 바텀시트(날짜·업체·상태 3분할 + 취소/완료)

**상태 자동 판정** — 예정일 4일 이상 남음 `예정`, 3일 이내 `진행중`, 지남 `완료`. 사용자가 직접 지정하면 그 값이 우선하고 행에 `직접 지정` 표기

우측 하단 연필 FAB(56px, 탭바 위 120px)로 일정 추가.

### 16. 우리웨딩 — 방문노트

`전체 2개` / `내용을 눌러 수정할 수 있어요` 헤더 → 노트 카드(업체·방문일 / 제안금액 / 메모) + X 삭제 → FAB로 추가

입력 시트: 업체, 방문일(캘린더), 제안금액(숫자만, `만원` 고정 접미), 메모(`특이사항을 적어주세요`)

### 17. MY

프로필(아바타 / 이름 + 등급 배지 / 예식일·배우자 상태) → 예식일 미등록 배너 → 통계 3개(결제인증·관심업체·방문노트, 각각 해당 화면으로 이동) → **나의 웨딩 미션** → 메뉴

**나의 웨딩 미션** grey50 블록. 제목 우측에 등급 배지(게스트/메이트/프렌드/패밀리). 4개 행:

| 항목 | 설명 | 완료 조건 |
|---|---|---|
| 업체를 살펴봐요 | 검색 · 업체정보 · 인증후기 · 업체평가 | 항상 완료 |
| 준비를 정리해요 | 관심업체 · 지출내역 · 웨딩 스케줄 | 로그인 |
| 배우자와 함께해요 | 초대 코드로 배우자를 초대해보세요 | 배우자 연결 |
| 결제 데이터를 확인해요 | 결제 인증 시 모든 정보 확인 가능 | 결제내역 등록 |

완료 항목은 blue500 체크 + grey900, 미완료는 grey300 체크 + grey500. 각 행 탭 시 해당 기능으로 이동.

**메뉴** 배우자 연결 관리 / 내 제보 내역 / 업체 반론 등록 / 웨딩픽 공유 / 문의하기 / 이용약관·개인정보 처리방침. 비회원은 계정 관련 항목이 로그인 시트로 연결됩니다.

### 18. 미션 완료 모달 — **최초 1회**

4개 미션을 모두 완료한 상태로 MY에 진입하면 1회 노출.

blue500 다이얼로그. 흰 원이 `420ms cubic-bezier(.34,1.56,.64,1)`로 튀어오르며 링이 퍼지고(`900ms`), 문구·태그·버튼이 60/120/180/240ms 지연으로 올라옵니다.

`필수 미션을 모두 완료했어요` / `웨딩픽의 모든 기능을 이용해보세요.` / 태그 `업체 탐색` `준비 관리` `배우자 연결` `결제 비교` / `확인`

## Interactions & Behavior

### 네비게이션

화면 이동은 **단일 헬퍼**를 거칩니다. 직접 화면 상태를 바꾸는 코드가 하나라도 남으면 뒤로가기가 어긋납니다.

- `nav(screen)` — 현재 화면을 스택에 push
- `root(screen)` — 스택을 비움 (하단 탭, 제보 시작)
- `goBack()` — pop. 스택이 비었으면 화면별 상위 화면으로 폴백

폴백 매핑: settings→my, spouse/reports/support/terms→settings, termsDetail→terms, inquiry→support, rebuttal→my, noti→home, vendor/compare→search, shoot→consent, confirm→shoot, done→home

### 오버레이 관리

모든 모달·바텀시트·툴팁·컨펌은 프레임 레벨에 있습니다. **화면이 바뀌면 전부 닫아야 합니다.** 동시에 각 오버레이의 노출 조건에 소속 화면을 포함시켜 이중으로 방어하세요. 이걸 안 하면 모달이 다른 화면 위에 남아 앱 전체가 잠깁니다.

우리웨딩 예산 시트와 MY 미션 모달은 화면 진입과 동시에 열리므로, 초기화 setState와 같은 틱에서 상쇄되지 않도록 한 틱 뒤에 열어야 합니다.

### 파괴적 동작

체크리스트 삭제, 방문노트 삭제, 반론 삭제, 배우자 연결 해제, 로그아웃은 모두 컨펌 다이얼로그를 거칩니다. 대상 이름을 함께 표시하고 확인 버튼은 danger 색.

### 토스트

화면 하단 96px, 텍스트 중앙 정렬, 2.2초 후 자동 소멸. 바텀시트 위에도 보이도록 z-index를 높게 둡니다.

### 빈 상태

데이터가 없어도 **레이아웃은 그대로 유지하고 값만 0/—로 표시합니다.** 별도의 안내 화면으로 교체하지 않습니다. 지출 0만원, 분포 바는 회색 단일 구간, 다음 결제·잔여 예산은 `—`. 각 탭에는 등록 유도 배너를 추가합니다.
