# v3 전환 분석 — 지금 코드에 무엇이 맞고 무엇이 어긋나는가

사업계획서 v3(올인원 전환)과 화면·데이터 구조 스펙을 받아, 화면스펙 9번이 요구한
일곱 가지를 지금 코드 기준으로 정리한다. **코드는 아직 손대지 않았다** — 9번이
"승인 전 전체 코드 일괄 수정 금지"라고 못박았고, 아래 4번의 충돌들은 승인 없이
고를 수 있는 것이 아니다.

기준 시점의 코드: API 212 · 도메인 146 · 스키마 18 테스트 통과, 마이그레이션 0021까지.

---

## 0. 먼저 물어야 하는 것 — 두 문서가 서로 다른 범위를 말한다

| | 사업계획서 v3 | 화면·데이터 구조 스펙 |
| --- | --- | --- |
| 1번 정의 | 결혼 준비 전체(웨딩홀·스드메·…·결정사) | **"결혼정보회사가 공식 안내한 조건과…"** — 결정사 단일 |
| 이용점수 | 전 카테고리 공통 기능(7번 Level 1) | 결정사 항목만(5.5: 가격설명/계약일치/매칭이행/과도권유…) |
| 비교표 | — | 공식가격·소개 횟수·해지점수 — 전부 결정사 항목(4번) |

스펙 문서는 스스로 "이전 버전은 결혼정보회사 단일 서비스였음"이라고 적은 그 **이전
버전 기준으로 쓰여 있다.** 그래서 아래 3번·4번의 판단이 갈린다:

- **스펙이 결정사 전용이라면** — 이용점수는 카테고리마다 다른 두 벌(결정사=체크리스트,
  웨딩홀·스드메=항목별 평가)이 되고, 지금 만든 것은 후자로 살아남는다
- **스펙이 전 카테고리 기준이라면** — 지금 만든 별점 후기를 체크리스트로 갈아엎어야 한다

**이 하나가 정해지기 전에는 후기 쪽 코드를 건드리지 않는 게 맞다.**

## 1. 재사용 가능한 것 (그대로 씀)

| 새 문서의 요구 | 지금 있는 것 |
| --- | --- |
| 5번 신뢰도 3단계 CONFIRMED/AUTO_COMPLETED/NEEDS_CONFIRMATION | `needsAttention()` — `confirmedByUser` · `requiresConfirmation` · `confidence<0.7`로 이미 세 갈래 |
| 5번 "판정 금지"(+8%·적정가·바가지 금지) | 이미 지킨다. 중앙값·표본수·기간만 내보내고 평가 문구가 코드에 없다 |
| 5.3 인증 사다리(상담자 제보→견적→계약→이용→해지) | `L0~L4`. 다섯 칸이 그대로 있다 (L4 이름만 다름, 4번 참조) |
| 8.4 제3자 이름 추출 제외 | 추출규칙 10번이 이미 구조 규칙이다 — **개인정보는 값을 복사하지 않고 종류만 남긴다.** 이름 필드가 애초에 없다 |
| 8.2 카드번호 값 저장 금지 | 위와 같은 규칙이 그대로 막는다. `pii_review`·`pii_redactions`로 사람 확인 경로까지 있다 |
| 5.6 매니저 익명화 | 0008의 플래너 공개 잠금과 같은 규칙 — 근거 없는 실명은 검색에 오르지 않는다 |
| 4번 3곳 비교 · "별점 순위 금지" | `MAX_COMPARED_VENDORS=3`, 정렬은 이름순. 순위를 만들 자리가 없다 |
| 7.1 AI 안 쓰는 것들(가격분포·표본수·점수 계산) | 전부 SQL 뷰와 순수 함수다. `comparable_quotes`·`scored_reviews`·`computePriceStat` |
| 6번 필드 단위 출처 표시 | `source` + 필드별 `confidence`가 이미 필드 단위다 |
| TOGETHER 배우자 연결 | A-18 완성 (초대·미리보기·연결 끊기) |
| 문의·이의 창구 | 12번 문의 + 후기 이의(정보통신망법 30일) |

**7.1이 요구한 "AI 없이 처리"는 이미 거의 다 그렇다.** 지금 AI를 부르는 곳은 문서
분석 하나뿐이고, 나머지는 전부 DB·뷰·순수 함수다.

## 3. 1단계 MVP 화면 (제안)

새 문서의 무게중심이 "계약서 검증"에서 **"결제인증 제보 → 실제가격 Unlock"**으로
옮겨갔다. 그 축만 먼저 세운다.

| 순 | 화면 | 상태 |
| --- | --- | --- |
| 1 | 검색 · 업체 상세 (비로그인) | 있음, **로그인 해제 필요** |
| 2 | 제보 — 동의 → 촬영 → 분석 → 선택형 확인 | 촬영·분석 있음, **결제내역용으로 전환** |
| 3 | 실제가격 (Unlock 전/후) | 계산 있음, **Unlock 게이트 없음** |
| 4 | 후기 · 이용점수 | **0번이 정해져야 함** |
| 5 | 3곳 비교 | 있음 |
| 6 | 내 웨딩 · 배우자 연결 | 있음 |

웨딩머니·준비리스트·일정은 2단계로 미룬다 — 9번 목표(제보 100건)를 움직이는 것은
제보 흐름이지 준비 도구가 아니다.

## 4. 정책·기술 충돌 (승인 필요)

### 🔴 4-1. 원본 파기 — 30일 vs 24시간

2026-08-28에 "검증 완료 후 30일"로 정하고 마이그레이션 0018까지 넣었다. 스펙 8.3은
"분석 완료 후 24시간"이다.

둘은 **서로 다른 것을 재고 있다.** 30일은 인증 심사가 원본을 다시 볼 수 있어야 해서
잡은 값이고, 24시간은 카드정보가 찍힌 이미지를 오래 들고 있지 않겠다는 값이다.
계약서가 P1에서 빠지면 남는 원본은 결제내역뿐이니 **24시간이 이긴다** — 다만 그러면
사람이 심사할 때 원본이 이미 없다. 심사를 24시간 안에 끝내거나, 심사를 접수 시점의
자동 판정으로 바꿔야 하는데 후자는 서비스정책서 7번(자동승인 금지)과 부딪친다.

→ **정해주셔야 하는 것: 결제인증 심사를 24시간 안에 끝낼 수 있는가.**

### 🔴 4-2. 이용점수 — 별점 vs 체크리스트

바로 앞 작업에서 별점(1~5) 기반 후기를 만들어 넣었다. 스펙 5.5는 **"예/아니오/모름
체크리스트 자동환산, 별점 아님"**이라고 명시한다. 표본 기준도 우리 3건 vs 스펙 5건이다.

체크리스트가 더 나은 이유가 스펙에 적혀 있다 — **"모름"은 분모에서 빠진다.** 별점은
모르는 것도 3점쯤으로 찍히고 그게 평균에 들어간다. 우리 구조는 "답하지 않은 항목은
넣지 않는다"로 그걸 피하지만, 사용자가 모르면서 답하는 것까지는 못 막는다.

다만 5.5의 항목(가격설명/계약일치/매칭이행/과도권유…)은 전부 결정사 항목이라
웨딩홀 음식·주차에는 쓸 수 없다. **0번이 먼저 정해져야 한다.**

되돌리는 비용은 크지 않다 — 도메인 파일 하나, 마이그레이션 하나, 화면 둘이다.

### 🟡 4-3. 비로그인 = 익명 제보 아님

Level 1을 열면 후기 목록·이용점수가 익명 접근이 된다. 후기 **쓰기**는 로그인이 계속
필요하다 — 한 사람이 한 업체에 하나라는 제한이 사용자 식별에 기대고 있고, 그게 없으면
점수를 밀어 올릴 수 있다. 읽기만 여는 것으로 읽었는데 맞는지 확인이 필요하다.

### 🟡 4-4. 갤러리 선택을 막으면 잃는 것

"카메라 촬영만"은 조작 방지에는 맞지만, 결제문자는 **이미 찍혀 있는 화면 캡처**인
경우가 대부분이다. 캡처를 막으면 제보가 거의 안 들어올 수 있다. 카드 영수증 실물은
촬영만, 결제문자 캡처는 허용 — 이렇게 종류별로 가르는 편이 나아 보인다.

### 🟡 4-5. "AI" 표기

새 문서는 AI를 앞세우지만, 화면 문구에서 AI를 쓰지 않는 규칙은 그대로 두는 것으로
읽었다. 사업 문서와 화면 문구는 다른 것이고, 5번의 "판정 금지"도 같은 방향이다.

### ⚪ 4-6. 계약서 P1 제외는 우리가 찾은 것이다

6번이 근거로 든 "비밀유지 조항 위약벌 계약금 2배"는 실제 계약서 제12조에서 확인한
것이다(2026-08-28). 계약서 관련 코드(문서 종류 7종, 계약 기반 L2 인증, 계약서 촬영
화면)는 **지우지 말고 남겨두기를 권한다** — 법률 확인이 끝나면 되살릴 것이고,
지우면 다시 만드는 값이 훨씬 크다. P1 범위에서 빼되 코드는 둔다.

## 5. DB 스키마 변경안 (초안)

| 마이그레이션 | 내용 |
| --- | --- |
| 0022 | `payment_proofs` — 결제인증 원본 큐. 24시간 파기 시각, 마스킹 표시(값 아님), 재시도 소진 후 파기 |

저장된 파기 시각을 뒤늦게 고칠 일이 없다.

## 6. 구현 우선순위 (제안)

```
① 0번 결정 (이용점수 범위)  ← 여기가 막혀 있다
② 비로그인 읽기 열기        ← Level 1. 다른 것과 안 얽힌다
③ 결제인증 파이프라인 + 24시간 파기
④ Level 3 Unlock 게이트
⑤ 후보 저장 · 비교픽
⑥ AI Router · 비용 추적
⑦ SEO slug + 업체 페이지
⑧ PLAN (웨딩머니·준비리스트·일정)
```

②는 지금 바로 할 수 있고 되돌릴 일이 없다. ③은 4-1이 정해져야 한다.
