## 1. Executive Summary

**서비스명**: WeddingPick | 웨딩픽
**Brand Message**: 찍으면, 진짜 가격이 보인다.

**서비스 정의**
WeddingPick은 결혼 준비 과정에서 발생하는 불투명한 가격과 복잡한 계약조건을 사용자가 직접 비교·검증할 수 있도록 돕는 AI 기반 웨딩 견적·계약 검증 모바일 앱이다.

사용자는 복잡한 정보를 직접 입력할 필요 없이 견적서·가계약서·계약서를 카메라로 촬영하거나 파일로 불러온다. AI가 문서를 분석하여 업체, 상품, 플래너, 가격, 계약조건, 추가비용 등을 구조화하고 WeddingPick에 축적된 실제 견적·계약 데이터와 비교한다.

**핵심 경험**

```
사용자는 찍는다 → AI는 읽는다 → 시스템은 검증한다 → 데이터는 비교한다 → 부부는 결정한다
```

## 3. WeddingPick의 해결방식

```
검색 → 업체·플래너 후보 → 견적 촬영 → AI 분석 → 실제 가격 비교
→ 여러 업체 비교 → 배우자 공동검토 → 가계약 검증 → 본계약
→ 추가금 추적 → 최종지출 → 실제 이용후기
```

이 과정에서 발생한 검증 데이터를 다시 WeddingPick 데이터베이스에 축적한다.

## 4. 핵심 가치 제안

WeddingPick의 핵심 경쟁력은 AI 자체가 아니라 **검증된 실제 웨딩 거래 데이터**다.

장기 축적 데이터: 실제 견적 · 실제 가계약 · 실제 계약금액 · 실제 최종지출 · 추가금 · 계약조건 · 업체별 가격분포 · 플래너 연결 데이터 · 이용경험 · 주차/식사 평가 · 실제 이미지

AI 문서분석 기능은 경쟁사가 구현할 수 있지만, 축적된 실제 계약 데이터는 단기간에 복제하기 어렵다.

## 7. 핵심 기능 ① AI 견적 분석

카메라 촬영 / 사진 불러오기 / PDF 불러오기 중 하나로 입력. 별도 입력폼 요구하지 않음.

**AI 자동 추출 항목**: 문서종류, 업체, 플래너, 상품, 가격, 할인, 계약일, 서비스기간, 포함항목, 별도항목, 추가비용 후보, 취소/환불조건, 주요 계약조건

신뢰도가 낮은 핵심정보만 사용자에게 확인 (예: "계약금액 3,280,000원이 맞나요?" [맞아요] [수정])

## 8. 핵심 기능 ② 가계약 검증

가계약은 WeddingPick의 핵심 개입 시점. 본계약 전 다음을 확인:
가계약 가격 · 유사 가계약 · 실제 계약 중앙값 · 포함조건 · 별도비용 · 추가금 가능 항목 · 취소/환불조건 · 플래너 정보 · 배우자 의견

대표 CTA: **"이대로 계약할까요?"**

단, WeddingPick은 법률적 계약판단을 대신하지 않으며 데이터 기반 확인 사항만 제공한다.

---

## 9. 핵심 기능 ③ 실제 가격 비교

가격은 평균보다 **중앙값** 우선 사용. "내 견적 vs 실제 인증계약 중앙값"을 표시.

판단 표현: 낮은 편 / 비슷한 수준 / 다소 높은 편 / 높은 편
표본 수와 기준기간 항상 표시. 데이터 부족 시 시장가격 생성하지 않음.

---

## 10. 핵심 기능 ④ 여러 업체 비교

동일 카테고리 업체 최대 3곳 비교.

비교정보: 내가 받은 견적 / 실제 계약 중앙값 / 가격 차이 / 추가비용 / 계약조건 / 이용점수 / 실제 후기 / 이미지 / 인증 데이터 수 / 배우자 의견 / 우리 조건 적합도

핵심은 "A업체가 나에게 제시한 조건"과 "A업체의 실제 계약 데이터"를 함께 비교하는 것.

---

## 11. 핵심 기능 ⑤ 플래너 비교

플래너를 업체 부속정보가 아닌 독립 비교대상으로 관리.

정보: 소속/제휴 · 활동지역 · 연결 상품 · 실제 계약 · 이용점수 · 추가비용 사전안내 · 실제 후기. 플래너가 제안한 스드메 조합도 비교 가능.

---

## 12. 핵심 기능 ⑥ 배우자 연결

**WeddingPick 공유** (Acquisition): 친구·지인·SNS에 앱 자체 공유. 개인 견적/계약정보 공유 안 함.

**배우자 연결**: 배우자 초대로 공동 웨딩공간 생성. 연결 전 "내 웨딩" → 연결 후 "우리 웨딩". 공동 관리: 후보·견적·분석결과·가계약·계약·비용·비교·의견·메모.

원본 계약서와 개인정보는 자동 공유하지 않음.

## 13. 부부 공동 의사결정

## 22. 일정 정책

WeddingPick 내부에 별도 범용 캘린더를 개발하지 않음. 사용자가 이미 사용하는 외부 캘린더(Google Calendar, Apple Calendar, ICS)에 일정 등록.

대상: 박람회·업체 상담·웨딩홀 투어·드레스 투어·촬영·계약금·잔금·기타 웨딩 일정. 이벤트에 장소·업체·WeddingPick 링크 포함.

---

## 23. 지도 정책

지도·내비게이션 서비스를 직접 개발하지 않음. WeddingPick은 업체 위치·주차장·대체주차장·다음 행선지·방문순서 정보만 제공하고, 실제 길찾기는 외부 서비스로 연결.

## 24. 방문 전 브리핑

업체 상담·웨딩홀 투어 전 "방문 전 확인" 화면: 내가 받은 견적 · 실제 계약 중앙값 · 확인할 계약조건 · 추가비용 · 주차 · 대체주차 · 식사 · 이용자 평가 · 배우자 의견

## 30. Web 역할

웹사이트는 별도의 Web App으로 확장하지 않는다. 초기 웹 역할 제한:

1. **서비스 소개** — 어떤 문제를 해결하는지
2. **핵심 기능 소개** — 견적 촬영, AI 분석, 실제가격 비교, 업체비교, 배우자 연결
3. **앱 다운로드** — App Store, Google Play
4. **신뢰/정책** — 이용약관, 개인정보처리방침, AI 안내, 운영정책, 회사/서비스 정보, 문의
5. **필요 시 캠페인 Landing** — 광고·박람회·견적 인증 이벤트 유입페이지

**웹의 최우선 KPI: App Download Conversion**

## 32. 초기 데이터 확보

최대 초기 위험은 Cold Start. 회원 수보다 **검증된 실제 견적·계약 데이터** 확보 우선.

| 단계 | 목표 |
|---|---|
| 1단계 | 유효 인증자료 100건 |
| 2단계 | 300건 |
| 3단계 | 핵심 업체별 의미 있는 표본 확보 |

초기 리워드는 견적/계약/최종지출 인증 등 데이터 가치에 따라 차등 적용 가능.

## 33. 데이터 Flywheel

```
사용자가 견적을 촬영한다 → 즉시 분석가치 제공 → 견적/계약 데이터 축적
→ 가격비교 정확도 향상 → 검색·분석가치 증가 → 신규 사용자 증가 → 새로운 데이터 축적
```

배우자 연결과 하객 참여가 추가 데이터 유입경로.

## 38. WeddingPick이 지켜야 할 제품 원칙

1. 사용자에게 입력시키지 않는다 — 찍으면 분석된다
2. AI가 시장 데이터를 만들어내지 않는다
3. 공식정보와 실제 데이터를 구분한다
4. 가격만 보여주지 않는다 — 왜 그런 판단인지 근거를 보여준다
5. 업체를 공격하는 플랫폼이 아니다 — 사용자의 합리적 의사결정을 돕는 플랫폼이다
6. 광고와 신뢰 데이터를 분리한다
7. 웹에 앱을 다시 만들지 않는다 — 서비스는 App 중심이다
8. 기능을 늘리는 것보다 Wedding Journey 연결을 우선한다

## 39. 최종 Positioning

WeddingPick은 웨딩업체 예약 플랫폼도, 단순 후기 커뮤니티도, 웨딩 가계부도 아니다.

> **"AI로 견적과 계약을 읽고, 실제 거래 데이터와 비교하고, 배우자와 함께 더 나은 결정을 내릴 수 있게 하는 웨딩 의사결정 플랫폼"**

- 처음 설치하는 이유: "내 견적이 적정한지 알고 싶어서"
- 계속 사용하는 이유: "결혼 준비의 중요한 결정을 여기서 같이 할 수 있어서"

최종 핵심 자산: **AI 기술 자체가 아니라 검증된 실제 웨딩 가격·계약·이용경험 데이터**
