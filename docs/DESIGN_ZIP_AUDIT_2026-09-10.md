# 최신 디자인 ZIP 검증·구현 대조

**결론: 앱·관리자의 실제 구현 불일치가 확인됐으며, 새 ZIP 자체에도 이전 사양·최신 화면·충돌하는 명세가 섞여 있다. ZIP을 통째로 덮어쓰는 방식은 회귀를 재발시킬 수 있다.**

사용자가 이번에 제공한 ZIP을 최신 디자인 자료로 검토했다. 자료 안의 ‘덮어쓰기’, ‘Codex 전달 프롬프트’ 등은 비교 대상 문서이며, 제품 수정·배포를 지시하는 새로운 사용자 요청으로 취급하지 않았다. 원본과 제품 코드는 수정하지 않았다.

## 2. 새 ZIP과 Git 전달본의 관계

루트 36개 화면 문서 중 **17개는 Git current HTML과 개행 정규화 후 완전히 동일**하다. 나머지 19개는 동일 파일을 찾지 못했다. 19개 모두가 새로운 화면 또는 큰 시각 변경이라는 뜻은 아니다. 경로·문구·내용 차이가 포함된다.

핵심 문서 9개 중 `CHANGELOG.md`, `tokens.json`, `PROJECT_RULES.md`는 개행 정규화 후 동일하다. `ADMIN.md`, `README.md`, `screens.json`, `SPEC.md`, `IMAGES.md`, `IMAGE_PROMPTS.md`는 다르다. ADMIN의 차이는 끝의 시안 열람 설명 추가이며 본문은 같다.

- 관리자 기본·운영 HTML은 이미 Git에 있는 원본과 동일하다. 관리자 구현 차이는 새 시안이 늦게 전달돼 생긴 문제만으로 설명할 수 없다.
- 스타일 이미지 `urban/natural/romantic/glamorous` 4장은 ZIP의 `uploads/스타일 이미지/`와 앱 `assets/images/style/`가 **원시 SHA-256까지 동일**하다. 코드 `features/onboarding/style-grid.tsx:128–131`이 이 파일을 사용한다.
- 웨딩일정의 지출 상자·Pick 인증·배우자 연결 분기는 이미 구현에 반영된 부분이다. 재작업 대상으로 집계하지 않는다.
- `handoff/screens.json`·SPEC는 v3.26 폴더와 같고, CHANGELOG·ADMIN은 v3.27, tokens는 v3.21과 같다. 버전별 폴더는 누적 변경 묶음이지 매번 완결된 패키지가 아니다.

| 항목 | 최신 루트·변경 이력 | 다른 파일에 남은 내용 | 판정 |

제보 루트 HTML 자체도 `:174,178`의 재촬영만 허용 설명과 `:252–268`의 직접 입력 화면이 충돌한다. 루트 파일이라고 모든 절이 정합한 것은 아니다.

### B. 화면 수와 상태가 맞지 않음

- 실제 정의는 앱 174개·웹 8개·관리자 26개 = **208개**.
- excluded 17개 중 16개만 실제 ID와 일치한다. 단순 제외하면 **192개**지만, 위의 폐기 누락이 있어 이를 확정 구현 대상 수로 사용하면 안 된다.
- 메타에는 total 189 / totalListed 202 / 설명 201−15=186이 섞여 있다.
- README에는 구성 190·표 186·명세 201·제외 3이라고 따로 표기한다.
- 스타일 선택 화면에도 `(최대 2개)`를 쓰라는 구조와 제한을 미리 쓰지 말고 3개째 토스트를 띄우라는 규칙이 함께 있다.

**영향:** 완료율·누락 화면 수·AI 작업 배정 범위가 어느 숫자를 읽느냐에 따라 달라진다.

### C. 이미지·HTML 전달 형식이 정밀 검수에 부족

- `handoff/png` 26개는 확장자만 `.png`이고 실제 형식은 모두 **JPEG**다.
- 크기는 25장 909×525, IA 1장 909×540이다. 390×844 화면별 캡처가 아니다.
- `03-home.png`를 실제 열어 확인하니 문서 제목·설명·휴대폰 상단 일부만 포함하고 하단은 잘렸다. 비회원 상태 설명도 남아 있다. 이를 최신 전체 화면 픽셀 기준으로 쓰면 안 된다.
- `handoff/html` 34개 모두 적어도 하나의 로컬 참조가 깨져 있다. 예를 들어 검색 HTML은 `_ds/...`와 `uploads/...`를 자신의 폴더 아래에서 찾지만 실제 파일은 ZIP 루트에 있다. HTML이 부분 렌더링될 수 있으므로 ‘전부 화면이 안 뜬다’고 단정하지 않는다.
- 루트의 `웨딩픽 전체 IA.dc.html`은 존재하지 않는 `./doc-page.js`를 참조한다. `웨딩픽 관리자.dc.html`은 ZIP에 없는 `웨딩픽 홈 v8.dc.html`로 연결한다.

이번 시각 확인은 리소스가 위치에 맞게 존재하는 **루트 HTML을 로컬 서버에서 열어** 진행했다. 외부 CDN의 React/Babel을 사용하는 런타임이므로 완전 오프라인 패키지도 아니다.

## 6. 적용 기준 정리안

1. **ZIP 원본을 보존하고 화면 ID별 채택 원본을 한 표로 고정한다.** 루트·handoff·버전 폴더명을 기준으로 일괄 선택하지 않는다. 변경 이력과 기존 사용자 확정사항을 함께 적는다.
2. **충돌표부터 정리한다.** 검색 시작, 나이 정책/ID, 제보 폐기·직접입력, 날짜 선택, D-day, 관리자 기본 캔버스가 우선이다. 이번 검수만으로 임의 확정하지 않았다.
3. **screens.json과 excluded를 실제 채택 정책에 맞게 재생성한다.** 화면 수는 자동 계산하고 README·메타에 같은 값 사용.
4. **렌더 가능한 단일 전달본을 구성한다.** 상대경로 검증, 화면별 전체 캡처, 디자인 자산 해시와 화면 ID 연결. 지금의 909px 문서 썸네일은 참고용으로 분리.
5. **코드 수정을 디자인·API·저장 결과와 같이 검증한다.** 관리자 홈/이미지/자동화, 앱 검색/후기/제보를 우선으로 실제 서버 응답과 빈·오류 상태까지 확인.
6. **원본 대비 차이와 기능 통과를 각각 기록한다.** 새 디자인을 받았다는 사실이나 타입 검사 통과만으로 ‘동기화 완료’라고 보고하지 않는다.

**이번 검수에서 변경한 것은 검수 도구·결과 파일뿐이다. 최신 디자인의 제품 반영·운영 배포는 하지 않았다.**
