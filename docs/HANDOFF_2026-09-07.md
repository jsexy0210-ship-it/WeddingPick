# 웨딩픽 작업 인수인계 — 2026-09-07

## 결론

`weddingpick-app-web.onrender.com`의 초기 로딩 병목을 코드와 배포 설정에서 줄였다. 최신 디자인 정책의 시스템 서체를 유지하면서 잘못 배포된 Pretendard 전체 폰트를 제거했고, WP-APP-002 스플래시 최소 노출을 실제 모션 종료 시점인 600ms로 맞췄다. 홈은 진입 게이트가 확인한 회원 정보를 재사용하고 독립 API를 병렬 호출한다.

운영 URL에는 이 변경이 배포된 뒤에만 반영된다. Render API가 무료 Web Service이면 15분 유휴 후 콜드 스타트가 남으며, 이번 코드 변경만으로는 제거되지 않는다.

## 변경 전 확인값

- 운영 HTML: warm TTFB 0.038초
- 운영 엔트리 JS: 원본 2,950,505B, gzip 전송 699,493B
- 운영 Pretendard Variable TTF: 전송 2,958,215B, 모든 문서에서 preload
- API `/health`: 1.062~1.875초
- API `/v1/vendors?sort=data`: 약 0.65초
- 스플래시 강제 최소 노출: 1,400ms
- 홈: 인기 업체/콘텐츠 후 회원/알림/후보/TOP3 순차 호출, 전체 종료까지 스켈레톤 유지

## 적용한 변경

1. `SPLASH_MINIMUM_MS`를 1,400ms에서 600ms로 변경했다. WP-APP-002의 마지막 rise 모션 종료와 일치한다.
2. 루트 인증 게이트가 받은 `CurrentUser`를 `SessionMemberProvider`로 전달한다. 홈의 중복 `/v1/me` 호출을 제거하고, 동일 응답은 객체 참조를 유지해 경로 이동 시 홈 API가 다시 실행되지 않게 했다.
3. 홈의 취향·후보 요청을 동시에 시작하고, 인기 업체·콘텐츠·알림도 별도 병렬 그룹으로 호출한다.
4. 취향과 후보가 정해지면 홈 스켈레톤을 해제한다. TOP3는 후보 업종 확인 뒤 받아서 나중에 반영한다.
5. 사용하지 않는 `pretendard`, 모바일 직접 `expo-font` 의존성을 제거했다. `expo-font`의 Expo 전이 의존성은 유지된다.
6. Render Blueprint에 `weddingpick-app-web` 정적 사이트와 해시 자산 1년 immutable 캐시 규칙을 추가했다.
7. 최신 `tokens.json`에서 누락됐던 safe area·플랫폼·로그인 토큰을 생성 코드에 동기화했다.

## 다음 작업

1. 변경 배포 후 운영 HTML에서 Pretendard preload가 사라졌는지 확인한다.
2. 운영 해시 자산 응답이 `Cache-Control: public, max-age=31536000, immutable`인지 확인한다.
3. 로그인 계정으로 진입·홈 완료 시간을 cold/warm 각각 측정한다.
4. Render API가 무료 인스턴스인지 확인하고 운영 단계에서는 상시 실행 인스턴스로 전환한다.
5. 약 535KB Brotli인 단일 Expo web 엔트리 번들을 라우트/기능 단위로 더 줄인다.
6. iOS/Android WebView 실기기와 느린 네트워크에서 로딩·오류·재시도 상태를 검증한다.

- `apps/web`는 이번 성능 변경 대상이 아니다. 기존 미커밋 `apps/web/src/styles.ts` 변경은 건드리지 않았다.
