# 작업 세션 전달문

현재 main의 규칙을 직접 읽는 공통 서식이다. 도구별 사본·과거 디자인 규칙·고정된 세션 주소를 복제하지 않는다.

## 전달 내용

```text
저장소: jsexy0210-ship-it/WeddingPick
역할: [기획·문서 / 구현 / 독립 검수]
이번 작업:
완료 기준:
소유 파일·겹치는 PR:
허용 범위와 배포 여부:

착수:
- 최신 main SHA·Open PR·관련 Issue·Actions를 확인한다.
- AGENTS.md와 CLAUDE.md의 현재 규칙을 읽는다.
- 디자인은 v3.29가 기준이고 docs/design/ 하나만 본다(2026-09-23 대표 지시 —
  「최신파일로 다 덮어씌워」). docs/design/README.md → PROJECT_RULES.md → CHANGELOG.md →
  html/의 해당 대메뉴 시안 순서로 읽는다. **screen-inventory.md는 지금 없다** — v3.28
  6개 파일 전제로 짠 생성 스크립트가 v3.29의 16개(화면 카탈로그가 아닌 전체 IA·
  컴포넌트 시트·사용자 흐름·디바이스 대응·스토어 이미지 포함)에는 안 맞아 재생성
  전까지 비워 뒀다 — 대조표 없이 해당 `.dc.html`을 직접 읽는다.
  **후기 별점은 v3.29 README와 CLAUDE.md가 정반대다** — CLAUDE.md 「⚠️ 후기 별점」
  경고를 먼저 확인하고, 대표님 확인 전까지 별점 코드를 건드리지 않는다.
  옛 v3.19~v3.28 · handoff · handoff-admin · figma-export는 CHANGELOG.md 자신이
  2026-09-23에 파기했다고 적는다 — git 이력에서 꺼내 근거로 쓰지 않는다.
- 최신 사용자 확정 지시와 제안·보류 항목을 구분한다.
- 기존 미커밋 변경과 겹치지 않는 다른 작업을 보존한다.

비교표(코드 수정 전 필수 — 2026-09-23 대표 지시, 비교표 없이 코드 수정 금지):
- 화면을 만지는 세션은 구현자가 아니라 **디자인 검수자 겸 구현자**다. 추측·기존 구현 관성·
  임의 UX 개선을 금지한다. 「보통 이렇게 한다」·「이쪽이 UX상 낫다」·「아마 이런 의도」는 근거가
  아니다.
- Source of Truth는 `docs/design/`(README.md·PROJECT_RULES.md·CHANGELOG.md·html/*.dc.html
  16개) 하나뿐이다. **`docs/design/handoff/`·`docs/design/figma-export/`는 2026-09-22에
  파기됐고 이 저장소에 없다** — 정본으로 적지 않는다. `.dc.html`은 파일 이름만 보지 않고
  해당 WP-ID 구역을 실제로 연다.
- 코드를 고치기 전에 아래 표를 먼저 쓴다:

  | 항목 | 정본(.dc.html 경로+WP-ID) | 구현(파일 경로+줄) | 일치 | 조치 |
  |---|---|---|---|---|

  구조(Depth·Back·Tab·CTA 위치·Fixed/Scroll) · 스타일(여백·정렬·radius·색·타이포) · 상태
  (기본·선택·미선택·Empty·Loading·Error·Disabled·완료) 셋 다 넣는다. 기본 상태 하나만
  맞추고 완료로 보고하지 않는다.
- 정본에 없거나 불명확하면 만들지 않고 `DESIGN_UNRESOLVED`로 남긴다. `.dc.html`을 못
  읽었거나 정본 자체를 확인 못 했으면 그 화면은 `DESIGN_SOURCE_NOT_VERIFIED`로 보고하고
  임의로 진행하지 않는다.
- 수정마다 정본 경로(WP-ID)와 구현 경로 쌍을 남긴다. 증거 없는 「정본대로 수정 완료」는
  보고로 치지 않는다.

진행:
- 승인된 범위를 최소 수정하고 실제 위험에 필요한 검증을 수행한다.
- 위 비교표를 채우며 진행하고, 고친 뒤 같은 표를 PASS/FAIL/NOT CHECKED로 재대조한다.
  `NOT CHECKED`가 하나라도 있으면 완료로 보고하지 않는다.
- 완료·미완료·미확인을 분리한다. 파일 존재·타입 검사만으로 디자인 완료라 하지 않는다.
- 정본(v3.29)에 없는 기능은 제거한다(2026-09-23 대표 지시). 코드에는 있는데 정본 16개
  .dc.html 어디에도 없는 화면·버튼·기능은 삭제 대상이다. 범위는 화면 단위가 아니라
  화면 안 요소까지다(2026-09-23 대표님 확인) — 통째로 없는 화면·라우트만이 아니라
  남는 화면 안의 버튼·토글·옵션·필터도 정본 대조표에 없으면 지운다. 다만 공용
  컴포넌트·다른 담당 화면군의 라우트인지 먼저 확인하고, 이미 예외로 못 박힌 것
  (지도·달력 외부 연결 등)은 남긴다. 무엇을 왜 지웠는지 PR 본문에 적는다.
- 대조는 토큰·픽셀 단위다(2026-09-23 대표 재지시 「토큰, 픽셀 단위로 대조해서 화면ID
  하나하나 다 변경해」). 색상·간격·폰트는 spec/tokens.json 토큰 이름으로, 좌표·크기는
  .dc.html의 px 값으로 맞추고 화면ID(WP-XXX-000) 단위로 하나씩 연다. v3.29 이전 잔존값
  (문구·색상·레이아웃·구 화면번호)은 발견 즉시 지운다.
- 실제로 렌더해서 본다 — `node scripts/screenshot-screens.mjs --build --route "<경로>"`로
  찍고 정본과 나란히 붙인다(`docs/screen-capture.md`). 「코드상 동일할 것」이라고 렌더 없이
  판정하지 않는다. 찍기 전에 **그 화면의 최신 구현이 실제로 이 브랜치·main에 있는지, 더
  최신 구현이 다른 draft PR에 있는지**부터 확인한다 — 오래된 브랜치·오래된 dist를 찍어
  「반영됐다」고 보고하지 않는다(2026-09-23 사고 재발 방지).
- 제품 데이터·인증·배포의 기존 보호 조건을 우회하지 않는다.
- 공통 UI 규칙(별도 지시 없이도 유지): 등록·추가·작성 BottomSheet 기준 · 인증된 사용자는
  Back으로 `/login`·`/setup` 역진입 금지 · Overlay 열려 있으면 Back은 Overlay만 닫음 ·
  2Depth 이상 Header 규격 통일 · Header 서브 문구 미사용 · 진입 출처에 따라 Back
  destination 보존 · 정본에 없는 임의 Alert/Dialog 금지.

인계:
- 관련 변경만 PR에 올린다. 요청이 main 반영까지라면 관련 검증과 병합 결과까지 확인한다.
- 보고 순서를 고정한다: 디자인 근거 → 기존 구현 → 불일치 → 수정 파일 → 실제 화면 검증
  (스크린샷) → 남은 불일치(`DESIGN_UNRESOLVED`/`DESIGN_SOURCE_NOT_VERIFIED` 목록). 이
  순서를 벗어난 「다 맞췄다」 요약만 있는 보고는 완료로 치지 않는다.
- 기준 SHA·PR·수정 파일·검증 결과·남은 문제·다음 작업을 보고한다.
- 문서 반영, 구현 완료, 시각 검수, 운영 배포를 구분한다.
- 시각은 KST로 보고하고 저장·cron의 UTC는 유지한다.
```

## 역할과 검수

전체 페이지 UX/UI 현행화는 Codex가 기획·정책·문서를, Claude가 구현을 맡는다. 마스터는 독립 검수와 통합을 담당한다. 사용자가 이번 작업의 역할·범위를 명시하면 그 지시를 적용한다.

화면 비교는 앱 390×844·관리자 1920×1080·WEB 해당 시안 크기로 한다. 신규/기본·빈 결과·필터 결과 없음·부분 누락·로딩·오류·완료 상태를 전수 대장에 연결한다.

서식의 빈 칸을 실제 작업으로 채우며, 과거 세션 ID·AI 작성자 정보를 새 커밋에 재사용하지 않는다.
