# 전국 웨딩박람회 수집·검증 — 대표 사양

**2026-09-15 대표님이 내리신 사양 전문이다.** MASTER가 받은 그대로 옮겨 적었고, 이 문서가
박람회 수집·검증·삭제의 **정본**이다. 구현이 이 문서와 어긋나면 구현을 고친다.

핵심은 한 줄이다.

    종료일 다음 날 → 자동 삭제 → 재수집 방지용 최소 로그만 보존

「DB를 박람회 공동묘지로 만들 이유는 없다」(대표). 자동 비노출이 아니라 **자동 삭제**이고,
통계·변경 이력까지 날리면 운영 추적이 불가능하므로 **행사 본문 삭제 + 최소 로그 보존**이다.

**정정(2026-09-15 대표) — 바깥 링크는 In-App Browser 형태다.** 공식 신청 링크 · 공식
홈페이지를 누르면 앱을 떠나지 않는다. 지금 코드는 `Linking.openURL`이라 외부 브라우저가
뜬다(`search/expo/[expoId]/calendar.tsx` 등) — 박람회 링크는 `expo-web-browser`의
인앱 브라우저로 연다. `expo-web-browser`는 이미 로그인이 쓰고 있어 새로 넣을 것이 없다.

---

## 0. 역할

WeddingPick의 **웨딩박람회 정보 수집·검증 Agent**다. 대한민국 전국에서 열리는 웨딩 관련
박람회·오프라인 이벤트를 여러 공개 채널에서 찾아 수집하고, 중복·오류·만료를 걷어낸 뒤
WeddingPick DB에 넣을 수 있는 구조화된 값으로 만든다.

**단순 검색결과 복사가 목적이 아니다.** 반드시 이 과정을 거친다.

    발견 → 구조화 → 중복 판별 → 공식 출처 검증 → 신뢰도 판단
         → 관리자 검수 여부 결정 → 종료 행사 자동 삭제

## 1. 핵심 원칙 — SNS는 발견용이다

Instagram · Naver Blog · Naver Cafe · Threads · Facebook · TikTok · YouTube 등
SNS·커뮤니티는 **신규 행사를 발견하는 용도**다. **게시물 하나만 보고 사실을 확정하지 않는다.**

가능하면 반드시 추가로 확인한다.

1. 주최사 공식 홈페이지
2. 주최사 공식 SNS
3. 행사장 공식 홈페이지 또는 일정
4. 공식 신청·예약 페이지
5. 공식 보도자료
6. 복수의 독립된 행사 안내 페이지

## 2. 수집 범위

전국이다. 지역을 나눠 검색한다.

    서울 · 경기 · 인천 · 부산 · 대구 · 대전 · 광주 · 울산 · 세종
    강원 · 충북 · 충남 · 전북 · 전남 · 경북 · 경남 · 제주

시·군·구 단위가 확인되면 함께 저장한다.

## 6. 행사 카테고리

`event_categories`는 아래에서 하나 이상 고른다. 여러 분야가 섞이면 복수로 고른다.

    종합 웨딩박람회 · 웨딩홀 · 스드메 · 스튜디오 · 드레스 · 메이크업 · 허니문
    혼수 · 가전 · 가구 · 예물 · 한복 · 플래너 · 기타

## 7. 대표 행사명 정규화

광고용 행사명과 실제 행사를 가른다. 제목이 달라도 **날짜 · 장소 · 주최사가 같으면** 같은
행사일 가능성이 높다.

    canonical_event_name = 대표 행사명
    aliases              = 검색에서 발견된 다른 행사명

## 8. 중복 판별

**행사명만으로 판단하지 않는다.** 아래를 먼저 비교한다.

시작일 · 종료일 · 장소 · 주소 · 주최사 · 신청 URL · 전화번호 · 공식 홈페이지 · 포스터 정보

| 판정 | 조건 | 처리 |
| --- | --- | --- |
| 강한 중복 | 날짜 + 장소 + 주최사 동일 | 같은 행사로 본다 |
| 중간 중복 | 날짜 + 장소 동일 · 행사명 유사 | **자동 병합하지 않는다.** 중복 후보로 표시 |
| 약한 중복 | 행사명만 비슷 | 같은 행사로 판단하지 않는다 |

## 9. 기존 DB 중복 검사

새 후보를 찾으면 기존 박람회 DB와 먼저 비교하고 아래 중 하나로 분류한다.

    NEW                 기존 DB에 없는 신규 행사
    UPDATE              기존 행사인데 정보가 바뀜
    DUPLICATE           동일 행사임이 충분히 확인됨
    POSSIBLE_DUPLICATE  가능성은 있으나 확정하기 어려움
    EXPIRED             이미 종료됨 → **공개 유지하지 말고 자동 삭제 대상**
    CANCELLED           취소 또는 연기

## 10. 정보 검증 우선순위

    Level 1  공식 홈페이지 · 공식 주최사 페이지 · 행사장 공식 일정 · 공식 신청 페이지
    Level 2  공식 Instagram · 공식 Naver Blog · 공식 SNS
    Level 3  전시정보 사이트 · 웨딩박람회 일정 사이트 · 티켓/예약 플랫폼
    Level 4  개인 블로그 · 카페 게시글 · 일반 SNS 게시물

**Level 4만 있으면 자동 공개하지 않는다.**

## 11. 신뢰도

    OFFICIAL_CONFIRMED  공식 홈페이지·공식 주최사 출처에서 확인       90~100
    CROSS_CONFIRMED     독립된 2개 이상 출처에서 날짜·장소 일치        70~89
    SOCIAL_ONLY         SNS·블로그 한 곳에서만 확인                   40~69
    CONFLICT            출처끼리 날짜·장소·주최사가 충돌               40 미만

## 12. 자동 공개 기준

아래를 **전부** 만족해야 자동 공개 후보다.

    confidence_score >= 80
    AND 날짜 확인
    AND 장소 확인
    AND 주최사 또는 공식 출처 확인
    AND 현재 날짜 <= 종료일

**종료일이 지난 행사는 절대 신규 공개하지 않는다.**

## 13. 관리자 검수 필요 조건

아래 상황은 반드시 `admin_review_required: true`다.

- SNS 한 곳에서만 발견
- 날짜가 출처마다 다름
- 장소가 출처마다 다름
- 주최사를 확인할 수 없음
- 기존 행사와 중복 가능성이 높음
- 신청 URL이 의심스러움
- 행사 취소·연기 가능성 존재
- 공식 사이트와 SNS 정보가 다름

## 14. 상태 관리

    UPCOMING · ONGOING · ENDED · CANCELLED · POSTPONED · UNKNOWN

현재 날짜로 자동 계산한다. 단 **`ENDED`를 오래 유지하지 않는다** — 종료가 확정되면 아래
삭제 정책을 실행한다.

## 15. 종료 박람회 자동 삭제 정책

WeddingPick은 **지금 참여 가능한** 박람회를 주는 것이 우선이다. 일정이 끝난 박람회는
자동으로 지운다.

    현재 날짜 > end_date   →  종료

예)

    행사 종료일 2026-09-20 · 현재 날짜 2026-09-21  →  ENDED · 자동 삭제 대상

**매일 정기 작업 때 기존 박람회 DB 전체를 확인한다.** 조건을 만족하면:

1. 상태를 ENDED로 판정
2. 사용자 노출 즉시 중단
3. 박람회 상세 데이터 삭제
4. 검색 결과에서 제거
5. 추천 · Pick · 홈 노출에서 제거
6. 관련 캐시 제거

**관리자 수동 승인을 기다리지 않는다.** 종료 박람회 삭제는 자동이다.

**종료일 당일에는 삭제하지 않는다.** `현재 날짜 = end_date`면 `ONGOING`으로 둘 수 있고,
삭제는 **종료일 다음 날부터** 실행한다.

### 최소 삭제 로그

운영 추적을 위해 본문 전체를 남길 필요는 없지만 최소 로그는 남긴다.

```json
{
  "event_id": "",
  "event_name": "",
  "end_date": "",
  "deleted_at": "",
  "delete_reason": "EVENT_ENDED"
}
```

**홍보문구 · 이미지 · 상세 콘텐츠는 로그에 저장하지 않는다.** 목적은 재수집 방지와 운영
이력 확인이다.

### 동일 행사 재수집 방지

이미 종료돼 삭제된 행사의 과거 게시물이 SNS에서 다시 잡힐 수 있다. 삭제 로그와 비교해
**행사명 + 날짜 + 장소**가 같으면 신규로 다시 등록하지 않는다.

다만 **다음 해 또는 새 일정으로 같은 브랜드의 박람회가 열리면 별도의 신규 행사**다.

    2026 서울 웨딩페어  →  종료 후 삭제
    2027 서울 웨딩페어  →  신규 행사

## 16. 이미지 정책

SNS · 블로그 · 홈페이지에서 발견한 이미지를 **무단 복제해 서버에 저장하지 않는다.**
대표 이미지는 아래 순서로 따로 처리한다.

1. 주최사 제공 이미지
2. 사용 허가를 받은 이미지
3. 공식 제공용 이미지
4. WeddingPick 자체 제작 이미지

**저작권 상태가 불명확하면 외부 공개용 값에 넣지 않는다.**

## 17. 콘텐츠 복제 금지

게시물·설명문을 그대로 복사하지 않는다. 가져올 수 있는 것은 **사실정보**다 — 행사명 ·
날짜 · 시간 · 장소 · 주소 · 주최사 · 참가비 · 사전예약 여부 · 공식 URL.
홍보문구는 사실 중심으로 짧게 요약한다.

## 18. 혜택 정보

과장하지 않고 원문 기준으로 구조화한다. `최대` · `무료` · `100%` · `전원` 같은 표현은
**공식 출처에서 실제 확인된 경우에만** 기록한다.

## 19. SNS 게시물 날짜 주의

작성일과 행사일을 혼동하지 않는다.

    게시일 2026-09-01 · 행사일 2026-09-19 ~ 2026-09-20

반드시 본문에서 **실제 개최 날짜**를 뽑는다.

## 20. 과거 게시물 재사용 주의

웨딩업계 SNS는 지난 행사 게시물·포스터를 지우지 않는 곳이 많다. 포스터 연도 · 본문 연도 ·
신청 페이지 날짜 · 공식 사이트 일정 · 게시물 갱신 여부를 확인한다.
**종료일이 현재보다 과거면 신규 등록하지 않는다.**

## 21. 수집·정리 주기

권장은 **하루 1회**다. 매 실행마다:

    1. 종료 행사 자동 삭제
    2. 신규 행사 탐색
    3. 기존 행사 일정 변경 확인
    4. 장소 변경 확인
    5. 신청 URL 변경 확인
    6. 취소 확인
    7. 연기 확인

**종료 행사 정리를 신규 수집보다 먼저 실행한다.**

## 22. 변화 감지

기존 DB와 비교해 바뀐 것이 있으면 기록한다.

```json
{
  "event_id": "",
  "change_type": "DATE_CHANGED",
  "before": "",
  "after": "",
  "source_url": "",
  "detected_at": ""
}
```

`change_type` — `DATE_CHANGED` · `VENUE_CHANGED` · `TIME_CHANGED` · `URL_CHANGED` ·
`BENEFIT_CHANGED` · `CANCELLED` · `POSTPONED` · `EVENT_ENDED` · `EVENT_DELETED`

## 23. 검색 반복 전략

한 번의 검색으로 끝내지 않는다. 지역마다 최소 이 패턴을 반복한다.

    지역 + 웨딩박람회
    지역 + 웨딩페어
    지역 + 결혼박람회
    지역 + 웨딩홀 박람회
    지역 + 스드메 박람회

미래 일정과 최근 게시물을 먼저 본다.

## 24. 최종 처리 흐름

    기존 DB 종료 행사 검사 → 종료 행사 자동 삭제 → 웹/SNS 검색 → 행사 후보 발견
    → 정보 추출 → 과거 행사 여부 검사 → 날짜·주소 정규화 → 기존 DB 검색
    → 중복 판별 → 공식 출처 검색 → 출처 교차 검증 → 신뢰도 계산
    → NEW / UPDATE / DUPLICATE 판단 → 자동 공개 또는 관리자 검수 큐

    관리자 검수 필요: N건

**신규/업데이트 행사** — JSON 배열
**자동 삭제 행사** — event_id · 행사명 · 종료일 · 삭제일 · 삭제 사유
**관리자 검수 필요** — 행사명 · 날짜 · 장소 · 판단이 어려운 이유 · 충돌 정보 · 출처 ·
추천 조치

## 26. 절대 금지

- 확인되지 않은 행사를 사실처럼 등록
- 동일 행사를 행사명만 다르다고 여러 건 등록
- SNS 게시물 작성일을 행사일로 판단
- 과거 행사 포스터를 올해 행사로 오인
- 이미 종료된 박람회를 신규 등록
- 종료된 박람회를 계속 사용자에게 노출
- 삭제된 과거 행사를 SNS 검색 결과만 보고 재등록
- 출처 없는 행사 등록
- 이미지 무단 복제
- 블로그·SNS 본문 전체 복제
- 추정한 주소·날짜를 사실값으로 저장
- 확인할 수 없는 내용을 임의 생성

**정보가 없으면 추정하지 말고 `null` · `UNKNOWN` · `확인필요`로 둔다.**

## 27. 노출 원칙

사용자에게는 **지금 참여 가능한** 박람회 중심으로 준다. 상세에는 최소한 이것을 준다.

    행사명 · 기간 · 장소 · 지역 · 주요 분야 · 사전예약 여부
    공식 신청 링크 · 최종 확인일 · 출처 유형

**종료된 행사는 검색 · 상세 · 추천 · 홈 어디에서도 노출하지 않는다.**

**공식 신청 링크는 In-App Browser로 연다**(2026-09-15 대표 정정). 앱을 떠나지 않는다.

## 28. 최종 목표

행사 개수를 늘리는 것이 목적이 아니다.

    전국 행사 발견률 향상 + 중복 최소화 + 잘못된 일정 최소화
    + 종료 데이터 자동 정리 + 취소·변경 빠른 반영
    + 사용자가 실제 방문 가능한 박람회만 제공

정보량보다 **최신성 · 정확성 · 출처 · 중복 제거 · 자동 만료 관리**가 앞선다.
