# 개인정보처리방침 — 코드와 어긋난 곳

2026-09-10 조사. **이 문서는 방침을 고치지 않는다** — 방침 본문(`apps/web/src/subpages.ts`)은
다른 도구가 손보는 중이고, 여기에는 코드를 읽어 확인한 사실만 적는다.

## 1. 연령대가 수집 항목에 없다 — 카카오 반려 사유

카카오가 「연령대」 필수 동의 신청을 반려했다:

> 개인정보처리방침 내 수집하지 않는 (연령대) 항목은 신청할 수 없습니다.
> (개인정보처리방침 내 회원가입 수집 목적의 수집 항목, 조건(필수/선택) 명시 필수)

**서버는 실제로 연령대를 받는다.** `apps/api/src/auth/identity-provider.ts`가
`kakao_account.age_range`를 요청하고, `routes/auth.ts`가 그 값으로 만 14세를 판정한 뒤
**곧바로 버린다**. 남는 것은 `users.age_verified` · `age_verified_at` 둘뿐이다.

방침의 회원가입 표에는 「만 14세 이상 확인 결과」만 있고 그 결과를 무엇으로 냈는지가
없다. **받는 것과 남기는 것을 구분해 적지 않은 것이 문제다.**

들어가야 할 것:

- 처리 항목에 **연령대(필수)**
- 항목마다 **필수 · 선택** 표시(카카오가 요구한 「조건 명시」)
- 보유기간은 실제와 같게 — 「가입 판정 직후 삭제하며 저장하지 않습니다. 확인 결과와
  확인 시각만 보관합니다」
- 생년월일 · 출생 연도는 **받지 않는다**(코드가 그렇다). 무엇을 받지 않는지 적어야
  무엇을 받는지가 분명해진다

## 2. 원본 보유기간이 코드보다 강하게 약속돼 있다

**이것이 가장 위험하다.** 방침 2항은 예외 없이 단정한다:

> 원본 이미지는 업로드 완료 시점부터 최대 24시간 이내 삭제합니다.

코드는 그렇지 않다:

| 값 | 어디 |
| --- | --- |
| `PAYMENT_PROOF_RETENTION_HOURS = 24` | `packages/domain/src/payment-proof.ts` |
| `RETENTION_POLICY.originalDays = 30` | `packages/domain/src/policy.ts` |
| `VERIFICATION_POLICY.backlogDays = 7` | 같은 파일 |

`policy.ts` 주석이 직접 적고 있다 — 「심사가 열려 있는 동안 그 증빙 원본은 파기되지
않는다 … **개인정보가 그만큼 오래 남는다는 뜻**이다」. 즉 **심사가 밀리면 24시간을
넘긴다.** 검증이 끝난 뒤로도 30일 보관한다.

쓴 대로 지우지 않으면 방침 위반이다. 문장을 실제 동작에 맞추거나, 코드를 문장에
맞추거나 — 둘 중 하나를 골라야 한다. 숫자를 임의로 바꾸는 쪽이 아니다.

## 3. 시행일이 화면에 배선돼 있지 않다

| | 상태 |
| --- | --- |
| 이용약관 | 화면에 `시행일 2026년 9월 1일`이 **문자열로 박혀 있다** |
| 개인정보처리방침 | **시행일 자리가 없다** — 그 자리에 설명 문장이 들어가 있다 |

`LEGAL_TERMS_EFFECTIVE_ON` · `LEGAL_PRIVACY_EFFECTIVE_ON` 환경변수가 이미 있고, 비어
있으면 **운영 API가 뜨지 않는다**(`packages/domain/src/release-gate.ts`). 값은 채워져
있는데 화면이 그 값을 보지 않는다 — 시행일을 바꾸려면 코드를 고쳐야 하는 상태다.

날짜를 정하는 것은 사람이 할 일이다. 코드가 할 일은 **정한 값을 화면이 따라가게**
배선하는 것뿐이다.

## 4. 국외 이전 — 나라와 보관 조건이 확인 전이다

방침 5항이 Anthropic · Render · Neon · Expo를 전부 **미국**으로 적었다.

- **리전은 회사 소재지가 아니다.** Render·Neon이 미국 회사여도 서버는 싱가포르 등에
  있을 수 있다. `render.yaml`에 리전 설정이 **없어서** 기본값을 쓰고 있고, Neon은
  프로젝트를 만들 때 고른 리전이다. 배포 설정에서 확인해야 한다
- **Anthropic 행의 「이전 목적 달성 시까지 보유합니다」는 우리 쪽 기준이다.** 우리가
  24시간 안에 지운다고 외부 사본이 함께 없어지지 않는다. 무보관 조건을 별도로 적용받지
  않으면 일반 API 정책(원칙적으로 30일 이내 삭제, 예외 있음)이 적용된다
- 계약 여부가 정해지기 전에는 「보관하지 않는다」고 쓸 수 없다 — 사실과 다를 수 있다

## 확인한 방법

전부 저장소 코드를 읽어 확인했다. 추측한 값은 없다.

```
apps/api/src/auth/identity-provider.ts    연령대를 요청하는 자리
apps/api/src/routes/auth.ts               판정하고 버리는 자리
packages/domain/src/payment-proof.ts      24시간
packages/domain/src/policy.ts             30일 · 심사 중 예외
packages/domain/src/release-gate.ts       시행일 환경변수
apps/web/src/subpages.ts                  방침 본문
render.yaml                               리전 설정 없음
```
