# 웨딩픽(Wedding Pick) — 화면·데이터 구조 스펙 (안심크루 전환용)

> **기준 문서는 계열이 둘이다.** 운영·제품·데이터 정책은 **통합정책 v3.15**(그 계열의 최신),
> 화면·값·용어는 **디자인 핸드오프 `current/`**(현행 v3.27)다. 번호가 둘 다 v3.x지만 같은
> 줄이 아니다. 이 문서는 그보다 앞선 범위로 쓰였다.
> 어긋나면 위 기준이 맞다 — 이 문서를 고친다.

사업계획서에서 개발에 필요한 부분만 추려낸 스펙 문서. 안심크루 기존 코드/디자인 시스템 분석 시 이 문서를 기준으로 재사용·신규 개발 범위를 판단한다.

## 1. 서비스 개요

- 서비스명: **웨딩픽**
- 정의: 결혼정보회사가 공식 안내한 조건과 실제 이용자가 경험한 가격·계약·결과를 비교해, 계약 전 리스크를 검증하는 플랫폼
- 원칙: 매칭 중개·가입결제 대행·성혼보장·업체 추천 안 함 / 비교 정보 제공 + 공식 상담 연결만

## 2. 정보구조(IA)

```
HOME
 └ 업체 검색 (지역/가격대/등급 필터)
     └ 업체 상세
         ├ 공식 상품정보
         ├ 실제 견적 (조건별)
         ├ 인증 후기 (상담/견적/계약/이용/해지 5단계)
         ├ 이용점수 (체크리스트 자동 환산)
         ├ 매니저 평가 (익명화)
         ├ 공식정보 (신고번호/소재지/행정처분 이력)
         └ 업체 공식 반론
 └ 비교함 (최대 3개 업체 동시 비교)
```

## 3. 핵심 화면 — 업체 상세 (킬러 스크린)

상단부터 순서대로 배치:

1. **공식 상품 요약**: 상품명(일반/프리미엄/노블레스), 공식 안내가, 계약기간, 약정 소개 횟수
2. **실제 계약 데이터**: 인증 견적 건수, 평균 계약가, 최저~최고 구간, "공식가 대비 몇 % 낮음" 강조 문구
3. **이용점수**: 종합 점수 + 세부 항목(가격설명/계약설명/매칭만족/매니저대응/해지환불) 막대 그래프
4. **인증 후기 리스트**: 인증 단계 배지(상담/견적/계약/이용/해지) 표시, 최신순/추천순/단계별 필터
5. **매니저 정보**: 익명화된 상담·매칭 매니저 평가
6. **업체 공식정보 + 반론**

공식 안내와 실제 경험을 **시각적으로 명확히 구분**(색상/배경 대비)하는 것이 이 화면의 핵심 요구사항.

## 5. 데이터 구조

### 5.1 업체 기본정보
업체명 / 신고·등록번호 / 소재지 / 대표자 / 운영상태 / 행정처분 이력 / 공식 홈페이지 / 공식 상담 링크 / 공공데이터 기준일

### 5.2 공식 상품정보
상품명 / 등급(일반·프리미엄·노블레스) / 초혼·재혼 / 공식 가입비 / 계약기간 / 약정 소개 횟수 / 성혼비 / 정보 확인일
- 가격 미공개 시 "상담 후 공개"로 표시 (임의 가격 입력 금지)

### 5.3 실제 견적
상담시기 / 성별 / 연령구간 / 지역 / 상품유형 / 최초 제안가 / 계약금액 / 계약기간 / 소개횟수 / 계약여부
- 인증 상태: 상담자 제보 → 견적 인증 → 계약 인증 → 이용 인증 → 해지·환불 인증

### 5.4 인증 후기
유형(상담/계약/이용/해지/일반) + 인증 자료(비공개, 운영자 확인용) + 노출 배지
후기 항목: 이용단계 / 상품유형 / 실납부금액 / 계약기간 / 실제 소개·만남 횟수 / 매니저 변경 횟수 / 추가비용 / 환불경험 / 장단점 / 재이용의사

### 5.5 이용점수 (예/아니오/모름 체크리스트 자동환산, 별점 아님)
가격설명 / 계약일치 / 매칭이행 / 운영정상성 / 과도권유여부 / 담당변경·해지대응
- "모름"은 계산 분모 제외
- 인증 후기 5건 미만 시 "데이터 수집 중" 표시(확정 비율 노출 금지)

### 5.6 매니저 정보
소속 회사·지점 / 상담·매칭 매니저 구분 / 담당기간 / 응답속도 / 설명정확성 / 권유정도 / 해지대응
- 실명은 본인/회사 공개 동의 시만, 그 외 "서울본사 상담 매니저 A" 식 익명화

## 7. AI 비용 최적화 정책 (Claude 전역 개발규칙)

> **웨딩픽 AI Cost-Minimum Principle**: 사용자 입력은 최소화하되, AI 호출도 최소화한다. 자동완성 ≠ AI 호출. 처리 우선순위: **DB 재사용 → Cache → Function → Rule Engine → Event Automation → 저비용 AI → 고성능 AI**

### 7.1 AI를 쓰지 않는 기능 (서버 로직/DB로 처리)
D-Day 계산, 웨딩머니 합계, 결제예정/예산잔액, 후보 상태(이벤트 기반), 준비 진행률, 일정, 배우자 의견 비교(규칙), 실제가격 분포(통계 로직), 인증 표본수, 후기/이용점수 계산, 제보 Unlock(권한 로직), 준비리스트 상태(이벤트), 포트폴리오(기존 데이터 조합), 다음 결제 알림(규칙), 업체/결제 연결(우선 DB matching)

### 7.2 AI가 필요한 기능 — P1은 3개로 제한
1. **결제 증빙 분석**: 이미지 → 업체/금액/날짜/결제정보 구조화
2. **방문노트 음성/텍스트 구조화**: 비정형 발화 → 구조화 필드
3. **웨딩픽 AI 자유질의**: 일반 로직으로 처리 불가한 자연어 요청만 (먼저 의도 분류 → 서버 Function 실행, 가능하면 AI 재호출 없이 템플릿 응답)

### 7.3 핵심 규칙
- **AI 1회 분석 → DB 저장 → N개 기능 재사용** (화면 열 때마다 재분석 금지)
- **Confidence 기반 모델 Escalation**: 저비용 AI 우선 → confidence 낮으면 상위 모델 → 그래도 불확실하면 사용자 확인(버튼 선택이 AI 재호출보다 저렴하면 사용자 확인 우선)
- **OCR/일반 파서 우선 검토**: 정형 데이터 추출 가능하면 규칙 기반 파싱, 불가능할 때만 AI Vision. 반복되는 결제 화면 패턴은 전용 Parser 추가
- **AI Router**: 모든 AI 요청 전에 DB조회/계산/규칙처리/캐시 가능 여부를 먼저 확인 후, 불가능한 경우만 저비용 AI → 낮은 confidence 시에만 상위 AI
- **사용량 제한**: 사용자별 일일 호출 제한, 동일 질문 캐시, 동일 데이터 재분석 금지, 필요 최소 Context만 AI에 전달, 출력 길이 제한
- **비용 추적**: 기능별 request_count / input·output tokens / estimated_cost / success_rate / escalation_rate / user_correction_rate 기록, 기능별 월 AI Budget 설정 가능하게 구현
- **Budget 초과 시**: 상위 AI 호출 제한 → 사용자 선택형 확인 → 직접입력 fallback 순으로 전환
- **AI 장애 대비**: AI가 죽어도 핵심 서비스(DB/Function/Rule 기반 기능)는 정상 동작해야 함
- 가격분포·예산계산·이용점수·D-Day·후보상태·일정·준비진행률·배우자 의견 비교에는 **AI 사용 금지**

## 8. 결제인증 개인정보 처리 규칙

결제인증 제보(결제문자/카드영수증 촬영)는 계약서 대비 법률 리스크는 낮지만, 카드정보·제3자 정보가 찍힐 수 있어 별도 규칙이 필요하다.

### 8.1 동의 문구 — 구체성 확보
포괄 동의("결제 정보를 수집합니다") 금지. 아래를 명시한 구체적 동의만 유효로 취급:
- 수집 항목: 가맹점명(업체명 매칭용), 결제금액, 결제일시, **카드번호 일부·승인번호 등 식별정보가 이미지에 포함될 수 있음**
- 처리 방식: AI가 구조화 데이터(업체/금액/날짜)만 추출, 카드번호·승인번호는 **값을 저장하지 않고 마스킹 처리**
- 목적: 결제인증 배지 부여 + 실제가격 통계 반영(중앙값 형태로만 외부 노출)
- 보유기간: 아래 8.3 참조

### 8.2 카드정보 — 여신전문금융업법 대응
- 카드번호(부분이라도) + 유효기간 조합은 신용카드 정보로 취급 → 전송 구간 암호화(TLS) 필수
- 구조화 추출 후 **카드번호·승인번호는 DB에 값으로 저장하지 않음** (존재 여부/자릿수 마스킹 표시만 유지)
- 결제 수단 자체가 통계에 필요하면 "카드/계좌이체" 등 **수단 종류만** 구조화 필드로 남김

### 8.3 원본 이미지 파기 정책 (명시)
```
촬영 이미지 업로드
→ 임시 저장(세션/처리 큐, 보관기간: 분석 완료까지 최대 24시간)
→ AI 구조화 추출(업체/금액/날짜/결제수단)
→ 카드번호·승인번호·타인 이름 등 식별정보 마스킹
→ 구조화 데이터만 DB 영구 저장
→ 원본 이미지 즉시 파기 (분석 완료 후 24시간 이내, 실패 건은 재시도 큐 소진 후 파기)
```
- UI 고지 문구(안내 화면에 그대로 노출): **"촬영한 이미지는 정보를 읽어내는 데만 사용되고, 분석이 끝나면 24시간 내 자동 삭제됩니다. 서버에는 금액·날짜 같은 정리된 정보만 남습니다."**
- 파기 로그(파기 시각, 건수)는 별도 기록해 사후 감사 가능하게 함
- 사용자가 제보를 취소/삭제 요청 시, 원본이 아직 큐에 있으면 즉시 파기, 이미 구조화 저장된 경우 구조화 데이터도 함께 삭제

### 8.4 제3자(가족카드·공동명의) 정보
- 영수증에 본인 아닌 이름(가족카드 명의자 등)이 찍힐 수 있음 → 이름 필드는 **추출 대상에서 제외**, 업체명·금액·날짜만 구조화
- 본인 동의만으로 처리 가능한 범위(본인 결제 사실 확인)로 한정하고, 타인 식별정보는 애초에 구조화 데이터에 포함하지 않는 것으로 리스크 회피
