# 통합정책 v3.14 충돌·리스크 검토

작성일: 2026-09-02

이 문서는 수집 자료를 v3.14에 반영하면서 그대로 채택하지 않은 내용과 시행 전에 확인할 사항을 정리한다. 법률 자문서가 아니며, 실제 출시 시점의 법령·공식 약관·계약·시스템 설정을 기준으로 확인해야 한다.

## 1. 즉시 해소한 충돌

### 원본 파기 기산점
- 기존 표현에는 `검증 완료 후 24시간 이내`와 `업로드 후 24시간 이내`가 함께 있었다.
- v3.14는 업로드 완료 시점을 기산점으로 통일했다.
- 24시간 안에 검증이 끝나지 않으면 연장 보관 대신 재제출 또는 별도 확인으로 전환한다.

### 감사 로그 영구 보관
- 수집 자료는 `purged_at`, 이미지 지문, 원본 저장 경로를 영구 보관하도록 제안했다.
- 목적 제한과 보유기간 원칙에 맞지 않을 수 있어 영구 보관을 채택하지 않았다.
- 원본 경로와 개인정보 포함 추출 원문은 삭제 후 로그에 남기지 않고, 감사 목적에 필요한 최소값만 별도 보유기간으로 관리한다.

### 업체 이의제기 자동 기각
- 수집 자료의 `증빙이 정상이면 자동 기각`, `자동 법률 통지` 방안은 오판·명예훼손·업무방해 주장에 취약하다.
- v3.14는 자동화를 접수 분류와 안전한 임시 조치로 제한하고 법률 판단·제재·대외 법률 통지는 담당자 승인 대상으로 두었다.

### 소셜 계정 자동 병합
- 이메일이나 CI가 일치하면 자동 연결한다는 제안은 계정 탈취와 오연결 위험이 있다.
- v3.14는 이메일 일치만으로 자동 병합하지 않고 기존 계정 재인증 또는 본인 확인을 요구한다.

### 패키지 금액 자동 안분
- 표준 비율로 스드메 패키지 금액을 나누면 실제 개별 가격 통계를 왜곡한다.
- 항목별 금액이 확인되지 않은 패키지는 전용 통계로 분리한다.

### 기기 고유값 기반 동일인 판정
- Device UUID를 동일인 식별과 제재의 핵심값으로 쓰는 방안은 모바일 운영체제 정책, 재설치·기기 변경, 개인정보 최소수집 원칙과 충돌한다.
- v3.14에는 채택하지 않았다.

## 2. 법률·약관 확인이 필요한 사항

### 동의와 재통지 주기
- `약관 7일/불리한 변경 30일`, `마케팅 2년마다 재확인`, `개인정보 이용내역 연 1회 통지`는 적용 법령, 사업자 유형, 시행 시점에 따라 달라질 수 있다.
- 숫자를 정책에 고정하지 않았으며 출시 전 최신 법령과 법률 검토가 필요하다.

### 개인정보 처리방침에 대한 동의 표현
- 개인정보 처리방침은 고지 문서이고, 개인정보 수집·이용 동의와 법적 성격이 다를 수 있다.
- 가입 화면 문구와 체크박스 구조는 실제 수집 근거별로 재검토해야 한다.

### 위치정보·제3자 제공·국외 이전
- 현재 또는 예정 기능이 위치 기반 정렬, 업체 상담·견적, 해외 리전·해외 처리업체를 사용하는지 확정해야 한다.
- 해당 기능 공개 전에 별도 약관, 동의, 신고·고지 의무를 기능별로 판단해야 한다.

### 사업자 정보 표시
- 전자상거래·통신판매 해당 여부와 실제 사업자 정보를 확정한 뒤 앱·웹 표시 항목을 결정해야 한다.

### 비식별 통계와 업체 권리
- 개인정보를 제거했다고 해서 모든 데이터가 자동으로 법 적용 밖이 되거나 업체의 정정·권리침해 주장이 배제되는 것은 아니다.
- 가격 공개 방식, 업체 식별 가능성, 영업비밀·명예훼손·부정경쟁 쟁점에 대한 별도 검토가 필요하다.

### 제출 데이터 이용권
- `영구·무상 라이선스`를 일괄 부여받는 조항은 필요 범위, 탈퇴 후 처리, 저작물성, 개인정보와의 분리를 검토해야 한다.
- 이용약관 문안 확정 전에는 정책상 권리로 단정하지 않는다.

## 3. 개인정보·보안 리스크

### 외부 OCR·영상 분석
- 외부 처리업체가 입력을 저장하지 않고 학습에 사용하지 않는다는 주장은 계약과 계정 설정 확인 없이는 사용할 수 없다.
- 제공업체, 리전, 보관, 학습 사용, 재위탁, 삭제 보장을 실제 설정과 대조해야 한다.

### 기기 내 마스킹의 한계
- 문자 인식 실패, 다른 형식의 카드·계좌번호, 손글씨와 제3자 정보는 기기 내 가림을 통과할 수 있다.
- 원본 서버 수신 자체를 없애는 구조인지, 서버 재마스킹 후 외부 전송하는 구조인지 기술 설계가 필요하다.

### 이미지 지문
- 이미지 지문은 중복 탐지에 유용하지만 오탐과 우회가 가능하며, 장기 보관 시 이용자 활동 추적값이 될 수 있다.
- 보유기간, 접근권한, 유사도 임계값, 이의제기 절차를 정해야 한다.

### 원본 24시간 삭제
- S3 수명주기의 `1일` 설정이 업로드 시각부터 정확히 24시간을 보장하는지 확인해야 한다.
- 버전 관리, 복제, 백업, 멀티파트 업로드 잔여물, 기기 임시 파일, 외부 처리업체 사본까지 삭제 범위에 포함해야 한다.

### 감사 로그 불변성과 삭제 요구
- 변경 불가 로그는 감사에 유리하지만 개인정보가 포함되면 정정·삭제 의무와 충돌할 수 있다.
- 로그의 개인정보 최소화, 암호화, 별도 키 관리, 보유기간, 법적 보존 예외를 설계해야 한다.

## 4. 제품·운영 리스크

### 소셜 제공자별 약관 동의
- 네이버·카카오가 모든 서비스 약관 동의를 제공자 화면에서 처리할 수 있다는 전제는 제품·심사 상태와 설정에 따라 달라질 수 있다.
- 제공자별 완료 상태를 신뢰하기 전에 실제 전달 필드와 동의 버전 증적을 확인해야 한다.

### 소셜 정보 우선 적용
- 최신 소셜 값을 자동 적용하면 제공자 간 이름·전화번호·생년월일 충돌이나 오래된 정보가 들어올 수 있다.
- 직접 수정값 보호, 출처·갱신 시각 보존, 민감 항목별 사용자 확인이 구현되어야 한다.

### 보상 타임락과 결제 취소 추적
- 결제망·간편결제 사업자의 정식 조회 권한이 없으면 취소 상태를 자동 추적할 수 없다.
- 보상 보류 기간과 회수 기준이 과도하면 소비자 분쟁이 생길 수 있으므로 약관·화면·운영 기준을 일치시켜야 한다.

### 신뢰도 점수
- 점수 산정이 불투명하면 정당한 사용자를 차별하거나 계정을 과도하게 제한할 수 있다.
- 입력값, 감점·회복 기준, 자동 제재 범위, 사람 검토와 이의제기 절차가 필요하다.

### 이상치 임계값
- `중앙값 대비 ±300%` 같은 고정값은 카테고리와 옵션 차이를 반영하지 못한다.
- 카테고리별 분포, 표본 규모, 조건 차이를 반영하고 이상치를 자동 삭제하지 않아야 한다.

### 1영업일 처리 목표
- 업체 이의제기 1차 확인 목표를 지키려면 담당 역할, 휴일 기준, 알림, 미처리 에스컬레이션이 필요하다.
- 인력과 운영 시간이 확정되지 않으면 외부에 보장 문구로 표시하지 않는다.

### 앱 심사용 별도 모드
- 심사 전용 모의 검증이 실제 기능을 오해하게 하거나 일반 사용자에게 노출되면 심사·보안 리스크가 생긴다.
- 별도 빌드, 서버측 허용 계정, 감사 로그, 운영 환경 차단을 갖추고 스토어 정책을 확인해야 한다.

## 5. 시행 전 결정 목록

1. 원본 이미지가 거치는 모든 저장소·리전·외부 처리업체와 실제 삭제 보장 범위
2. 이미지 지문과 감사 로그의 보유기간 및 접근권한
3. 소셜 제공자별 수집 항목, 필수성, 동의 증적, 계정 연결·해제 방식
4. 개인정보 수집·이용, 마케팅, 위치정보, 제3자 제공, 국외 이전의 실제 적용 범위
5. 보상 보류·취소·회수 기준과 사용자 이의제기 절차
6. 업체 이의제기 담당자, 처리기한, 임시 비공개와 최종 조치 권한
7. 패키지·성수기·희소 조건 통계의 계산 규칙과 화면 표시 방식
8. 약관·개인정보 처리방침·앱 화면·실제 시스템 설정의 출시 전 대조 검증

## 6. 외부 약관 공개 전 확정 항목

아래 항목은 외부 배포용 이용약관·개인정보 처리방침·마케팅 동의서에 추정값이나 빈칸으로 표시하지 않는다. 실제 계약서, 사업자 등록정보, 운영 설정과 담당자 승인을 근거로 확정한 뒤 외부 문서와 앱 화면에 반영한다.

### 회사와 고객지원 정보

웨딩픽은 별도 조직이 없는 1인 운영을 전제로 한다. 실제 조직에 존재하지 않는 고객센터 부서나 개인정보 담당부서를 만들어 적지 않는다. 사업자 정보가 발급되기 전에는 외부 문서의 해당 표시를 보류하고, 발급 후 운영자 본인의 공개 가능한 사업자 연락수단과 개인정보 책임 정보를 반영한다. 아래의 ‘담당자’, ‘정책 담당’, ‘제품 담당’, ‘개발 담당’은 조직명이 아니라 한 운영자가 수행하는 역할 구분이다.

1. 회사의 정확한 법적 명칭, 대표자명, 사업자등록번호
2. 통신판매업 신고 대상 여부와 해당하는 경우 신고번호
3. 영업소 주소와 법령상 표시할 연락처
4. 회원·업체의 문의, 권리행사 및 이의제기를 접수할 고객센터 채널과 운영시간
5. 개인정보 보호책임자 또는 담당부서의 명칭과 공개 연락수단

### 개인정보 처리와 외부 사업자

6. 실제 개인정보 처리 항목별 보유기간: 계정, 이벤트·보상, 보안 로그, Pick 구조화 정보, 이미지 지문, 삭제 감사 로그
7. 클라우드·객체 저장, 문자인식·영상 분석, 메시지 발송, 보상 발송 등 실제 수탁자명과 위탁 업무
8. 각 수탁자의 저장 위치, 리전, 재위탁 여부, 보유·삭제 조건, 입력정보의 학습 사용 여부
9. 국외 이전 발생 여부와 발생 시 이전받는 자, 국가, 연락처, 목적, 항목, 시기·방법, 보유기간 및 거부 방법
10. 업체 상담·견적·예약, 이벤트 보상 등 제3자 제공 기능의 실제 제공받는 자, 목적, 항목, 보유기간과 거부 시 영향
11. 맞춤 추천·광고를 위한 행태정보의 실제 수집 여부와 수집 항목, 방법, 목적, 보유기간, 통제 방법 및 제3자 제공 여부

### 마케팅·보상·시행 정보

12. 실제 운영할 광고성 수신 채널, 채널별 발신 주체, 수신거부 경로와 야간 광고 발송 여부
13. 마케팅 동의·철회 이력의 보유기간과 동의 문서 식별·변경 관리 방식
14. NPay 등 보상의 실제 발송 주체, 지급 실패·취소·회수 절차와 이용자 이의제기 경로
15. 각 외부 문서의 공고일·시행일, 변경 고지 기간과 이전 문서 열람 방법

### 확정·반영 절차

- 항목별 근거는 사업자 등록정보, 계약서, 관리자 설정 화면, 시스템 구성, 담당자 승인 기록 중 하나 이상으로 남긴다.
- 정책 담당자는 확정값을 통합정책에 반영하고 법률·개인정보 담당자의 검토 상태를 기록한다.
- 제품 담당자는 가입, 설정, 탈퇴, 이벤트, 업체 문의 화면의 표시 내용이 확정값과 일치하는지 확인한다.
- 개발 담당자는 실제 수집 항목, 저장 위치, 보유기간, 삭제 작업, 외부 전송 설정을 문서와 대조한다.
- 미확정 항목이 실제 처리나 법정 공개에 필요한 경우 해당 기능의 외부 공개와 운영을 보류한다.
- 확정 후 이용약관, 개인정보 처리방침, 마케팅 동의서와 앱·웹 고지를 같은 배포 단위로 갱신한다.
