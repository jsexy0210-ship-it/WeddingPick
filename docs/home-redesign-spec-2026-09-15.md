# 사양 원문 (받은 그대로)

[ROLE] 너는 WeddingPick의 시니어 서비스 기획자 + UX 디자이너 + 프론트엔드 개발자다. 현재 WeddingPick 홈 화면을 아래 확정 기획 기준으로 개편한다.

중요: 기존 기능과 데이터를 최대한 재사용한다. 불필요한 DB/API/라우트 신규 생성 금지. 단, 이번 요구사항에서 명시한 "웨딩픽 추천 전체 페이지"는 별도 페이지 신규 추가가 필요하다. 구현 전 현재 구조와 데이터 연결 상태를 먼저 분석한다. 기존 기능을 삭제하거나 동작을 변경할 경우 영향 범위를 먼저 보고한다. 아래 명칭과 UX 구조를 임의 변경하지 않는다.

## 1. 홈의 역할

홈은 전체 카테고리를 나열하는 검색 페이지가 아니다. 사용자가 홈에서 빠르게 확인해야 하는 것: 결혼식까지 남은 기간 / 예식일·예식장 / 현재 예산 상태 / 커플 연결 상태 / 지금 선택해야 할 웨딩 카테고리 / 카테고리별 추천 업체 / 가까운 박람회 / 현재 준비 단계에 필요한 콘텐츠 / 진행 중인 이벤트.

홈 최종 섹션 순서: 1 히어로 → 2 Pick 추천 → 3 박람회 → 4 웨딩피드 → 5 이벤트.

## 3. 히어로

핵심 정보만 요약. 순서: D-day → 예식일·예식장명 → 남은 예산·사용률 → 커플 연결 상태.

**D-day**는 가장 높은 시각적 우선순위. 예: `D-214`. 예식일 미설정이면 `예식일을 정해볼까요?`, 선택 시 웨딩노트 > 내 웨딩 정보.

**예식 정보**: 예식장 있으면 `2027.04.17 · 루이미스스퀘어`. 예식일만 있으면 `2027.04.17 · 예식장 미정`. 둘 다 없으면 `예식일 · 예식장 미정`. 예식장 미정 선택 시 웨딩홀 관련 추천으로 자연스럽게 연결.

**예산**: `남은 예산 3,000만원 · 27% 사용`. 사용률 = 사용 금액 / 총 예산 × 100. **별도 예산 카드/섹션을 홈에 추가하지 않는다.** 미설정이면 `예산을 정해볼까요?` → 웨딩노트 > 예산.

**커플 연결**: 완료 `함께 준비 중 · 연결 완료` / 미연결 `함께 준비할 사람을 초대해보세요` / 발송 후 `초대 수락을 기다리고 있어요`. 미연결 선택 시 파트너 연결·초대 화면.

## 4. Pick 추천

기존 준비현황 + 웨딩픽 추천 역할을 통합한 핵심 홈 영역. 섹션명 `Pick 추천`, 서브카피 `지금 준비할 순서에 맞춰 골라봤어요`.

**금지**: `추천 3곳` · `추천 5곳` · `후보 3곳` 등 카테고리 헤더의 N건 표시.

## 5. 카테고리 + 아코디언

카테고리명과 액션을 **동일 레벨 한 줄**로. 왼쪽 카테고리명, 오른쪽 상태별 액션 + chevron.

홈 최초 진입 시 **가장 우선순위가 높은 첫 번째 카테고리를 기본 펼침**. **single-open accordion** — 동시에 하나만 펼쳐진다. 아코디언 버튼 클릭 자체는 **화면 이동 금지**, 펼침/접힘만.

## 6. 업체 추천 카드

카테고리별 **최대 3개**, **가로 슬라이드**.

    ┌──────────────────────────────┐
    │ ┌────────┐  웨딩홀         ♡ │
    │ │ 썸네일 │  메종 웨딩         │
    │ │        │  서울 영등포구      │
    │ └────────┘  #채광맛집 #야외정원 │
    │             350~520만원       │
    │             ★4.7 · 저장 892   │
    └──────────────────────────────┘

필수: 썸네일 / 카테고리 / 업체명 / 지역 / 특징 태그 최대 2개 / 가격 / 별점 / 저장 수 / Pick 버튼. 카드 클릭 → 업체 상세. ♡ → Pick 저장·해제. 좌우 swipe, 다음 카드 일부 노출 가능, 홈 높이를 과도하게 늘리지 않는다.

## 7. 상태값

기존 상태값이 있다면 아래 의미와 매핑한다.

| 상태 | 의미 | 액션 | 펼침 내용 |
| --- | --- | --- | --- |
| `NOT_STARTED` | 아직 본격적으로 알아보지 않음 | `[추천]` | 개인화 추천 업체 최대 3개 |
| `EXPLORING` | 업체 보는 중 · Pick 없음 | `[추천]` | 최근 본 곳 + 사용자 조건 기반 추천 최대 3개 |
| `SHORTLISTED` | Pick한 업체 존재 | `[보기]` | Pick 업체 또는 관심도 기반 최대 3개 |
| `COMPARING` | 2개 이상 비교 가능 또는 비교 중 | `[비교]` | 비교 대상 최대 3개. 하단에 필요 시 `[한눈에 비교]` → Pick > 해당 카테고리 비교 |
| `DECIDED` | 최종 결정 완료 | — | **홈 Pick 추천에서 제거** |
| `SKIPPED` | 하지 않기로 설정 | — | Pick 추천과 추천 계산에서 제외 |

## 8. 완료 → 다음 추천 자동 승격 (핵심 UX)

카테고리가 `DECIDED`가 되는 즉시: ① 홈 Pick 추천에서 제거 ② 다음 준비 카테고리를 위로 승격 ③ 승격된 카테고리를 첫 번째 항목으로 ④ 해당 아코디언 자동 펼침 ⑤ 추천 업체 최대 3개 제공.

    기존:  1 웨딩홀 · 2 스튜디오 · 3 메이크업
    웨딩홀 결정 후:  1 스튜디오(자동 승격 + 펼침) · 2 메이크업 · 3 드레스

전체 흐름: 추천 → 업체 보기 → Pick → 비교 → 결정 → 완료 → 다음 카테고리 추천.

## 9. 다음 준비 요약

Pick 추천 하단에는 완료한 항목이 아니라 **앞으로 남은 준비**를 요약한다.

타이틀 `다음 준비도 이어서 볼까요?` / 서브 `아직 결정하지 않은 준비가 N개 있어요` / 예 `스튜디오 · 메이크업 · 예물 · 허니문 외 3개` / CTA `[더보기]`.

**중요: 이 더보기는 웨딩노트로 이동하지 않는다.** 이번에 새로 만드는 «웨딩픽 추천 전체 페이지»로 이동한다.

## 10. 신규 페이지: 웨딩픽 추천 전체

제목 `웨딩픽 추천` / 서브카피 `아직 남은 준비를 한눈에 확인해보세요`.

## 11. 노출 규칙

노출: `NOT_STARTED` · `EXPLORING` · `SHORTLISTED` · `COMPARING`. 제외: `DECIDED` · `SKIPPED`.

정렬 우선순위: ① COMPARING ② SHORTLISTED ③ EXPLORING ④ NOT_STARTED. 추가로 **웨딩 준비 순서 / 예식일까지 남은 기간**을 반영해 동일 상태 안에서 우선순위를 정한다.

## 12. 신규 페이지 UI

**홈과 같은 추천 데이터를 쓴다. 별도 추천 로직을 중복 생성하지 않는다.** 카테고리명 + 추천 업체 카드 최대 3개, 업체 카드는 **홈과 동일 컴포넌트 재사용**, 카테고리별 가로 슬라이드.

카테고리가 많아 세로가 지나치게 길어지면 카테고리 accordion 사용 가능 — 현재 UX 구조를 보고 결정해라.

## 13. 신규 페이지 CTA

카드 클릭 → 업체 상세. ♡ → Pick 저장·해제. 비교 가능 상태면 `[한눈에 비교]` → Pick 비교 화면. 카테고리 내 더 많은 업체가 필요하면 `[더보기]` 또는 `[더 찾아보기]` → 검색 > 해당 카테고리. **단, 홈의 `[더보기]`와 혼동되지 않게 명칭을 구분한다.**

## 14. 홈 ↔ 추천 전체 페이지 상태 동기화

반드시 **동일 데이터 상태**를 쓴다. 추천 전체 페이지에서 웨딩홀 결정 완료 → DECIDED 저장 → 홈 복귀 → 웨딩홀 제거 → 스튜디오 자동 승격 + 기본 펼침. 반대로 홈에서 Pick 저장 → 추천 전체 페이지에도 즉시 반영. **별도 상태 복제 금지.**

## 15. 신규 라우트

기존 라우팅 규칙을 먼저 확인하고 그 명명 규칙을 따른다(`pick-recommendations` · `wedding-recommendations` 등의 «의미»). **임의로 경로를 결정하기 전에 현재 프로젝트 라우팅 규칙을 확인할 것.** 진입은 홈 > Pick 추천 > 더보기. 뒤로가기는 홈으로 정상 복귀.

## 16. 박람회

섹션명 `박람회` / 서브카피 `가까운 일정부터 확인해보세요` / 가로 슬라이드 / 홈 최대 3건. 카드 정보: 기간 · 박람회명 · 장소 · 지역. 우선순위: 사용자 지역 · 예식일 · 일정 · 접근성. 카드 클릭 → 박람회 상세. 더보기 → 박람회 전체 목록. **종료된 박람회 노출 금지.**

## 17. 웨딩피드

섹션명 `웨딩피드` / 서브카피 `지금 알아두면 좋은 것만 모았어요` / 홈 최대 3건.

**단순 텍스트 목록 금지.** 반드시 썸네일 + 메타 + 제목.

    │ 썸네일 │  첫 피팅 전, 스타일리스트에게
    │        │  꼭 물어볼 6가지
    └────────┘                              >

메타 형식 `[카테고리 배지] · 콘텐츠 유형` — 예: `[드레스] · 웨딩 가이드` · `[예산] · 웨딩 가이드` · `[일정] · 준비 캘린더` · `[웨딩홀] · Pick 가이드`.

**시간 관련 정보는 전부 제거한다.** 사용 금지: `10분 전` · `2시간 전` · `1일 전` · `읽는 시간 4분` · `읽는 시간 5분`.

제목 최대 2줄. 썸네일 없으면 fallback thumbnail 또는 번호형 썸네일. 카드 클릭 → 콘텐츠 상세. 더보기 → 웨딩피드 전체.

## 18. 이벤트

홈 최하단. 섹션명 `이벤트` — **`웨딩픽 이벤트` 사용 금지.** 서브카피 `웨딩픽에서 진행 중인 혜택을 확인해보세요`. 배너형.

    ┌────────────────────────────────┐
    │ 이벤트명                        │
    │ 짧은 이벤트/혜택 설명           │
    │                          [보기] │
    └────────────────────────────────┘

배너 클릭 → 이벤트 상세 또는 지정 목적지. 활성 이벤트 없으면 섹션 미노출 가능.

## 19. 검색

상단 검색은 전체 업체 검색. 전체 카테고리: 결정사 · 웨딩홀 · 스튜디오 · 드레스 · 메이크업 · 헤어변형 · 본식스냅 · 부케 · 청첩장 · 예물 · 혼수 · 허니문 · 기타. **전체 카테고리 목록은 홈에 직접 나열하지 않는다.**

## 20. UX Writing

짧고 행동 중심. 과도하게 감성적이거나 광고성인 표현 금지. 확정 문구는 위에 적은 그대로다.

## 21. 반응형 / UI 원칙

모바일 우선. Pick 추천은 아코디언 + 업체 가로 슬라이드. 웨딩픽 추천 전체는 카테고리별 슬라이드. 박람회는 가로 슬라이드. 웨딩피드는 세로 리스트 최대 3개. 이벤트는 배너. 기존 컬러 · radius · spacing · typography · card · button 디자인 시스템을 최대한 재사용한다.

## 22. 구현 전 분석

코드 수정 전에 반드시 확인: ① 현재 홈 컴포넌트 ② 홈 데이터 API ③ 업체 카드 기존 컴포넌트 ④ Pick 데이터 구조 ⑤ 비교 기능 ⑥ 추천 로직 존재 여부 ⑦ 업체 카테고리 상태 데이터 ⑧ DECIDED 처리 구조 ⑨ 예식일·예식장 데이터 ⑩ 예산 데이터 ⑪ 커플 연결 데이터 ⑫ 박람회 데이터 ⑬ 웨딩피드 데이터 ⑭ 이벤트 데이터 ⑮ 검색 라우트 ⑯ 업체 상세 라우트 ⑰ Pick 비교 라우트 ⑱ 신규 페이지 route 구조 ⑲ 추천 데이터를 홈과 신규 페이지가 공유할 구조.

분석 후 먼저 **재사용 가능 / 수정 필요 / 신규 필요 / 영향도 / 신규 route**를 보고한다.

## 23. 구현 원칙

추천 로직을 홈과 신규 페이지에서 각각 만들지 않는다. 공통 추천 source를 쓴다. 기존 아키텍처에 맞는 계층(selector · hook · service · API)을 재사용한다. **DB 테이블 신규 생성은 최후 수단.** 기존 API 확장이 가능하면 신규 API 생성 금지. 업체 카드도 홈용·추천 페이지용 둘로 중복 구현하지 않는다.

# 구현이 사양과 다르게 간 자리 (2026-09-17 정리)

구현한 세션이 사양대로 못 만들었거나 일부러 다르게 둔 자리다. 대표님이 화면을 보시고
지적하신 것과 겹친다.

| 사양 | 구현 | 왜 |
| --- | --- | --- |
| §6 카드에 **썸네일** | 회색 상자 + 이모지 | 업체 이미지가 저장소에 거의 없다(`vendor_images` 승인 건 부족). 캡처는 fixture라 전부 비어 있다 |
| §6 카드에 **저장 수** | 안 그림 | `vendor_candidates` 집계는 가능하나 값이 전부 0이라 「저장 0」이 「아무도 안 담은 곳」으로 읽힌다 |
| §6 특징 태그 `#채광맛집` | `#도시적인` 등 스타일 넷 | 자유 태그를 담는 자리가 없다. `styleTags`가 가장 가까운 실제 값이다 |
| §7 `EXPLORING` | `NOT_STARTED`와 합침 | 조회 기록 표가 마이그레이션 전체에 없다 |
| §7 `SKIPPED` | 안 만듦 | 「안 할래요」를 정하는 화면이 없다 |
| §17 메타의 **콘텐츠 유형** | 카테고리만 | `weddingFeedPostSchema`에 그 칸이 없다 |
| §16 우선순위의 **접근성** | 안 씀 | 역·주차 자료가 없다 |
| §6 카드 폭 | 약 415px(피그마는 208px) | **사양에 폭이 없어 옛 `Layout.cardRecommendWidth`를 그대로 썼다.** 피그마와 어긋난 자리이고 고쳐야 한다 |

히어로의 아바타 둘 · 「두근두근」 · 우측 ⋯ 버튼. 앞의 둘은 사양 §4(통합) · §19(나열 금지)를
따른 결과이고, 뒤의 셋은 사양이 히어로에 네 줄만 적어서 빠졌다.

「다음 준비도 이어서 볼까요?」(§9).
