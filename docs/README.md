새 세션에는 [공통 전달문](session-prompt.md)을 사용한다. 규칙 전문을 도구별 파일로 복제하지 않는다.

## 과거 버전 번호를 어떻게 읽을 것인가

코드 주석과 마이그레이션에는 `v2.0`, `v3.1`, `v3.5` 같은 번호가 많이 나온다.
**그 번호들은 "이 규칙이 언제 정해졌는가"를 적어둔 것이지, 지금 기준이 그 버전이라는
뜻이 아니다.** 규칙을 왜 그렇게 두었는지 다음 사람이 되짚을 수 있어야 해서 남긴다.

읽는 법:

- `v2.0 K-6이 폐기했다` — 그 버전에서 내려진 결정의 기록이다. 유효하다.
- `v3.10 §3` — v3.10에서 정해진 규칙이다. 뒤 버전이 다르게 정했으면 뒤가 맞다.
- `v3.13 §O-1` — v3.13에서 정해진 과거 위치를 가리킨다. 내용이 v3.15와 다르면 v3.15를 따른다.
- `v3.14 §O` — v3.14에서 정해진 규칙이다(v3.15는 v3.14에 T장을 더한 것으로, §O는 바뀌지 않았다).
- `v3.15 §T` — 현재 모바일 RN 구현 범위·플래너/광고 제휴 삭제 기준을 가리킨다.
- 두 주석이 서로 다른 말을 하면 **v3.15가 맞다.** 오래된 쪽을 고친다.

새 주석에 과거 버전을 현재 기준처럼 적지 않는다. 지금 정해지는 것은 v3.15다.

## 폐기된 색인

이 표에 예전에는 `01-business-plan.md`부터 `07-design/handoff-gap.md`까지가 있었다.
그 파일들은 저장소에 없다. 없는 문서를 기준 문서로 적어두면, 읽는 사람은 자기가 못
찾는 것이라고 생각하고 그 자리에서 멈춘다. 그래서 지웠다.

지웠다. 그 세 문서는 여기 없고, 지금 기준은 통합정책 하나다.
