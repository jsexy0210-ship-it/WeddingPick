# 웨딩픽 외부 API 수집 위험 보고서

확인일: 2026-09-04. 코드 기준: main `bbc6ce800ab627efdf423d01365a29cd8e72ca00`.
공개 공식 문서에 근거한 설계 검토이며 개별 계약·계정 승인을 확인한 결과는 아니다.

## 1. 우선 보고할 사항

이전 제안의 세 API 결과를 정규화해 영구 업체 DB에 통합하는 방식은 수정이 필요하다.
API 키 발급이나 유료 이용은 대량 저장·가공·재배포 권한을 의미하지 않는다.
위험은 기술적 중복 제거만으로 해결할 수 없다. API 경로는 설계 대상으로 유지하되
아래 제한을 해소하기 전 저장용 자동 작업으로 활성화하지 않는다.

| 우선도 | 위험 | 대응 |
|---|---|---|
| 높음 | Google Places를 업체 디렉터리 DB 보강에 사용 | 적용 계약·목적 허용 여부 확인 전 일괄 적재 제외 |
| 높음 | 네이버 검색 결과 저장·가공·타 출처 결과와 통합 | 기존 Search/API HUB 각각 확인. 응답 저장·가공 비활성 |
| 높음 | 카카오 로컬 응답과 장소 ID 저장 | 저장 목적 호출 제외. ID 예외를 임의 가정하지 않음 |
| 높음 | 조회시각을 원본 수정시각으로 오인 | 시각 종류 분리. 판정 불가능하면 기존 검증값 유지 |
| 높음 | 공식 이미지와 API 사진의 재사용 권리를 동일시 | 이미지별 재배포·크롭 허락 확인 후 사용 |
| 중간 | 지역 검색 결과 일부를 전국 전체 목록으로 오인 | 미확보 영역을 기록하고 전국 완전성 수치를 주장하지 않음 |
| 중간 | 동일 브랜드 지점 오병합·잘못된 폐업 처리 | 독립 식별 단서와 공식 상태 재검증 |
| 중간 | 요금·키 권한·이관 상태 미확인 | 공급자별 계정·쿼터·비용 상한 확인 후 활성화 |

## 2. Google Places

Google Maps Platform 약관 3.2.3에는 대량 추출·저장, 업체명·주소 복사 저장,
디렉터리 활용 등에 관한 제한이 있다. 현재 웨딩픽 업체 검색 DB를 보강하는 목적은
이 제한과 충돌할 가능성이 높다. 서비스에 다른 기능이 있다는 이유로 허용을 단정하지 않는다.
[공식 약관](https://cloud.google.com/maps-platform/terms)

Places 정책은 허용 예외 외 캐시·저장을 제한하며 Place ID에는 저장 예외를 둔다.
이는 업체명·전화번호·사진의 영구 보관이나 디렉터리 구축까지 허용한다는 의미가 아니다.
지도 및 출처 표시 조건도 실제 화면에서 검토해야 한다.
[Places 공식 정책](https://developers.google.com/maps/documentation/places/web-service/policies)

조치: DB 적재용 Google 배치는 제외. 구체적인 서비스 목적과 적용 계약의 허용 범위를
확인해야 한다. Place ID만 남기거나 응답을 해시·요약하는 방식으로 목적 제한을 우회하지 않는다.

## 3. 네이버

네이버 공식 고객센터는 검색 API 결과의 저장·가공이 불가하며 키 발급으로 승인되지
않는다고 안내한다. 검색 결과를 독립적으로 노출하고 임의 변조하지 않는 조건도 있다.
[고객센터](https://help.naver.com/service/30015/contents/17128?lang=ko&osType=COMMONOS)
[서비스 약관](https://developers.naver.com/products/intro/terms/terms.md)

2026-07-31 시행 약관은 기존 개발자센터 Search API 신규 신청 종료 및 API HUB 이관을
명시한다. 기존 신청자 유예기간은 2027-06-30까지다. API HUB의 별도 계약·기능·가격은
이번 검토에서 확정하지 않았다. 기존 상품의 조건을 새 상품에 그대로 적용하지 않는다.

기존 지역 검색 레퍼런스의 요청 표는 `display` 최대 5, `start` 최대 1이다.
`telephone`은 값을 반환하지 않으며 `lastBuildDate`는 검색 결과 생성시각이다.
따라서 전체 업체 페이지 순회·전화번호 교차검증·업체 수정일 판정 수단으로 가정하면 안 된다.
예제와 오류 표에는 과거 값이 섞여 있으므로 실제 계약 상품도 대조한다.
[지역 검색 문서](https://developers.naver.com/docs/serviceapi/search/local/local.md)

조치: 기존 Search API 결과의 저장·가공 통합 제외. API HUB 연동은 별도 검토 대상으로 둔다.

## 4. 카카오

2025-07-22 공식 데브톡 Map 답변은 라이브 호출만 허용하고 저장 목적 호출과 식별키만
저장하는 형태도 제재 대상이라고 설명한다.
[2025년 답변](https://devtalk.kakao.com/t/api/145284)

2026-02-02 답변은 전체 또는 일부 응답을 별도 DB로 저장해 POI 검색 서비스를 구축하는
것을 금지하며 대규모 저장 계약 모델을 제공하지 않는다고 설명한다. 동시에 ID 기반
라이브 연결을 제안해 ID만 보관하는 예외 범위는 이전 답변과 함께 재확인이 필요하다.
이 제안을 범용 장소 ID 보관 허가로 해석하지 않는다.
[2026년 답변](https://devtalk.kakao.com/t/api/148194)

조치: 응답·ID 저장을 기본 금지로 설계한다. 기존 `scripts/geocode-vendors.mts`의
좌표 저장도 운영 실행 여부와 적용 조건 확인 대상으로 보고한다. 이번 작업에서는
실행·DB 수정·기존 데이터 삭제를 하지 않았다. 공개 로컬 API에 장소 ID 조회가 있다고
가정하지 않고 공식 엔드포인트를 확인한다.
[로컬 API 문서](https://developers.kakao.com/docs/ko/local/dev-guide)

## 5. 최신성 한계

Google Place·카카오 로컬 기본 응답과 네이버 지역 검색 문서를 대조하면 세 업체 결과를
공통 업체 수정시각으로 정렬할 수 있는 근거가 부족하다. 조회시각, HTTP Date,
검색 결과 생성시각, 사진·리뷰 게시시각은 업체 정보 수정일을 대신하지 못한다.
[Google Place 스키마](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places)

조치: 저장 허용 자료에 한해 값별 수정시각·적용기간·검증시각을 구분한다.
수정시각이 비교 가능하면 최신 현재 유효값을 선택한다. 불명확하면 공식 변경 공지나
직접 제공 자료로 재검증하고, 해결 전에는 기존값을 보존한다. 단순 다수결은 세 출처가
같은 오래된 원천을 복제했을 수 있어 최신성 보증으로 사용하지 않는다.

## 6. 기존 구현에서 함께 확인할 위험

- 공공 CSV 파서는 폐업 행을 제외하므로 기존 업체 폐업 전환을 놓칠 수 있다.
- 임포터는 내용 무변경도 갱신으로 집계하고 `vendor_change_log`를 작성하지 않는다.
- 첨부 Python 해시는 운영 상태를 제외해 상태만 변한 경우 SKIP할 수 있다.
- 관리자 이미지 승인 경로는 권리·매칭 검증을 강제하지 않으며 화면/API 계약도 다르다.
- 수집 로그 보유기간을 정할 때 `vendor_change_log.import_run_id`의 NOT NULL 요구 조건과
  실행 로그 삭제 시 ON DELETE SET NULL 동작의 충돌 가능성을 먼저 해결해야 한다.
- 업체명 원문에 일괄 금칙어 치환을 하면 식별값과 계약 조건의 의미가 훼손될 수 있다.
- 현재 프론트의 좌표 잔여 필터와 상태 문서의 지도 설명은 최신 코드와 함께 재확인한다.

실서비스 DB 적용 여부·과거 수집 데이터 출처·실제 API 사용량은 확인하지 않았다.

## 7. 가능한 진행 범위와 다음 조치

공공데이터·업체 직접 제공·수집 허용 공식 출처를 대상으로 기존 임포터의 중복 및
최신성 규칙부터 구현할 수 있다. Google·네이버·카카오는 허용된 연동 목적과 저장
범위가 확정된 뒤 해당 범위만 활성화한다. 플랫폼 결과를 공식 홈페이지 출처로
라벨만 바꿔 적재하지 않는다.

확인할 외부 사항은 적용 Google 계약과 사용 목적, 네이버 기존 계정/API HUB 상품,
카카오 저장·식별키 허용 범위다. 문의가 필요하면 구체적인 사용 목적·필드·보유기간을
명시한 요청을 준비하며 이번 작업에서는 공급자에 연락하지 않았다.

이 보고서는 코드 구현 완료 또는 공급자 승인 완료를 의미하지 않는다.
