# Figma → 정본 시안

이 폴더의 `.dc.html` 9개가 WeddingPick 화면 모양의 정본이다.
화면 모양은 이 폴더만 기준으로 보고, 수치·토큰·문구·정책은 `../handoff/`를 따른다.
다른 디자인 폴더나 복제본을 정본으로 사용하지 않는다.

```
01-home.dc.html            홈
02-search.dc.html          검색
03-pick.dc.html            Pick · 비교
04-wedding-note.dc.html    웨딩노트 (캘린더 · 예산 · 상담기록)
05-vendor-detail.dc.html   업체 상세 · 상담 예약 · 정보
06-onboarding-login.dc.html 로그인 · 초기 설정 · Pick 인증
07-lounge-my.dc.html       라운지 · MY · MY 상세
08-recommendations.dc.html 웨딩픽 추천 (초개인화)
09-dialogs.dc.html         알림 · 확인 · 바텀시트 6유형
```

## 다이얼로그 6유형

브라우저 `alert` · `confirm` · `prompt`를 쓰지 않습니다.

```
DLG-A  알림            고를 것 없음 · 버튼 1개 · 중앙
DLG-B  확인            되돌릴 수 있음 · 취소 + 실행 · 중앙
DLG-C  되돌릴 수 없음   영향 항목 필수 · 빨강 실행 · 배경 탭 안 됨
DLG-D  바텀시트         고르기 · 입력 · 맥락 유지
DLG-E  행동 목록        대상 하나에 동작 3개 이상
DLG-F  토스트          결과만 · 2초 · 막지 않음
```

**버튼 순서는 왼쪽 취소 · 오른쪽 실행 고정.** 실행 버튼은 코랄, 되돌릴 수 없는 것만 `#FF4133`.

**다이얼로그를 겹쳐 띄우지 않습니다.** 열려 있으면 뒤 것을 큐에 넣습니다.

**화면이 바뀌면 성공 알림을 띄우지 않습니다.** 같은 화면에 남을 때만 토스트를 씁니다.

## 웨딩픽 추천 · /recommendations

아직 정하지 않은 업종만 모아 보여주는 초개인화 화면입니다. 결정한 업종은 목록에서 빠지고 다음 것이 올라옵니다.

```
노출 대상   준비 현황에서 결정하지 않은 업종만
정렬        예식일 가까운 순 → 실 제보 많은 순
펼침        첫 업종만 · 한 번에 하나
카드 수     업종당 3곳 + 더 찾아보기
금액        실 제보 3건 미만은 «수집 중»
전부 결정   목록 비우고 웨딩노트로
광고        이 화면에 슬롯을 두지 않는다
```

## 홈 준비현황 · 4칸 + 자동 승격

완료한 업종은 보여주지 않습니다. 앞으로 할 것만 4칸으로 띄우고, 하나를 정하면 빠지고 다음이 올라옵니다.

각 파일 맨 아래에 **Figma 원본에서 고친 것** 표가 있습니다. 주황색은 정책 판단이 필요한 항목입니다.

## 실행

`.dc.html`은 브라우저에서 바로 열립니다. `support.js`는 렌더링 런타임이라 구현에는 필요 없고, `image-slot.js`는 이미지 자리 표시자입니다.

## Root 탭 · 5칸 고정

```
홈 · 검색 · Pick · 웨딩노트 · MY
```

**라운지는 탭이 아닙니다.** 초기에는 후기와 박람회가 몇 건뿐이라 탭 한 칸이 빈 화면을 띄웁니다. 진입은 두 곳입니다.

```
홈 «웨딩 소식» 섹션 우측 «라운지»
MY «둘러보기» 섹션
```

라운지 화면에는 탭바를 두지 않고 back nav만 붙입니다.
