## 최신 확정 사항

- 홈뿐 아니라 앱·관리자·웹의 전체 페이지를 검토한다. 기존 구조·브랜드색을 유지한다.
- 홈 일정 카드는 통합 Pick 추천으로 연결하고 누른 업종을 유지한다.
- **최종 Pick 저장 성공 → 상담 예약 진입 → 별도 예약 제출** 순서다. 후보 담기만으로 예약할 수 없다.
- **웨딩 준비 팁과 예산현황은 홈에 유지**한다. 나머지 홈 섹션 카피와 새 탭명은 확정하지 않는다.
- 로딩은 실제 완성 화면 구조와 맞춘다. 기본·미설정·빈 결과·필터 결과 없음·일부 정보 부족·오류·정상 0을 구분한다.
- 같은 상태와 표시 범위에는 같은 문구 구조·배치·CTA 규칙을 쓴다. 세부 기준은 실행 핸드오프 §8-1이다.
- 등록·추가·작성은 기존 BottomSheet 기준을 따르고, 인증 후 Back으로 로그인에 역진입하지 않는다.
- 검색 Root에는 Back을 두지 않는다. 삭제·통합된 독립 화면을 되살리지 않는다.

## 시각 시안과 수치

화면의 모양·배치는 `figma-export/`, 수치·토큰·기능 규칙은 `handoff/`를 사용한다. 최신 확정 지시가 해당 부분을 바꾼 경우에만 그 지시가 우선한다. `spec/`는 구현이 읽는 런타임 구성으로 정본을 대체하지 않는다.

고유 화면 ID는 208개다. 라우트·시트·공통 상태·제외 항목이 섞여 있으므로 화면 수를 완료율로 쓰지 않는다. 앱은 390×844, 관리자는 1920×1080, WEB은 해당 시안 크기로 같은 상태를 비교한다.

## 문서 관리

- 현재 명세에 이전 구현 방식·보류 기능의 상세 설계·버전별 변경 이력을 병렬로 남기지 않는다. 유효한 규칙은 해당 주제의 명세 하나로 모은다.
- 정리된 과거 내용은 Git 이력과 [전달 ZIP](source/2026-09-20/README.md)으로 확인한다. 활성 폴더에 백업·구버전 사본을 만들지 않는다.
- ZIP 2개는 원본 증빙으로 보존한다. HTML·PNG·JSON·에셋과 원본 ZIP은 이번 MD 정리에서 변경하지 않았다.
- 활성 MD의 수정·삭제 근거와 해시는 [canonical-manifest.json](canonical-manifest.json)에 기록한다. 원본 해시와 현행 문서 해시를 혼동하지 않는다.
- 원본 전달 구성은 99개, MD 정리 후 활성 구성은 97개다. `npm run test:design-canonical`로 원본 ZIP과 현재 활성 파일을 검증한다.
