# 디자인 정본 — 2026-09-20 전달 ZIP

이 저장소의 디자인 Source of Truth는 2026-09-20 전달 ZIP 2개다. 원본은
`source/2026-09-20/`에 수정 없이 봉인하고, 구현에서는 아래의 활성 경로만 읽는다.

```
docs/design/figma-export/   화면의 모양 · 배치 · 시각 시안
docs/design/handoff/        수치 · 토큰 · 문구 · 정책 · 화면 규칙
docs/design/source/         감사·무결성 확인용 ZIP 원본. 구현에서 직접 참조하지 않음
```

파일명·크기·SHA-256과 활성 경로 99개 파일의 정규화 해시는
[`canonical-manifest.json`](canonical-manifest.json)이 고정한다.

## 적용 순서

1. 화면의 모양과 배치는 `figma-export/`를 따른다.
2. 수치·토큰·문구·정책·상태 규칙은 `handoff/`를 따른다.
3. 둘이 어긋나면 모양은 `figma-export/`, 값과 규칙은 `handoff/`를 각각 적용한다.
4. 최신 사용자 예외로 검색 Root의 Back은 시안과 달리 삭제 상태를 유지한다.
5. 최신 PR에서 삭제·통합한 독립 페이지는 되살리지 않고 현재 리다이렉트·통합 화면에 내용을 적용한다.
6. 그 밖의 충돌은 두 ZIP을 우선하고 `design-screen-map.json`에 차이와 검수 상태를 남긴다.

## 정본 시안

`figma-export/`의 화면군은 홈, 검색, Pick, 웨딩노트, 업체 상세, 온보딩·로그인, 라운지·MY, 추천, 다이얼로그다. `.dc.html`은 10개이며 이름이 다른 추천 파일 2개는 원본 구성이라 모두 보존한다.

`handoff/screens.json`은 합계 표기가 서로 어긋난다. 완료·누락 판정에는 선언 숫자가 아니라
실제 고유 화면 ID 208개를 사용한다.

## 공통 원칙

- 디자인 작업은 `docs/design/` 밖의 별도 디자인 폴더를 만들지 않는다.
- `source/` 외에는 디자인 자료를 복제해 별도 세대·백업·정본 폴더를 만들지 않는다.
- 화면 검수는 정본과 실제 구현을 같은 상태로 캡처해 나란히 대조한다.
- 파일 존재, 타입 검사 통과, 화면 ID 주석만으로 디자인 완료 처리하지 않는다.
