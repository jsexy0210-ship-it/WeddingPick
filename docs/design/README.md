# 디자인 정본 — 여기만 본다

**2026-09-17 대표 지시** — 「두 개 파일 main에 업로드하고 **모든 디자인은 해당 경로만 보도록 한다**」.

화면 · 값 · 문구를 정하는 자리는 이 폴더 하나다. 다른 곳을 근거로 쓰지 않는다.

```
handoff/        디자인 핸드오프 v3.28 (2026-09-18)  — 값과 명세의 원본
figma-export/   피그마 → 정본 시안 9장 (2026-09-17) — 화면의 모양
```

## 둘의 역할이 다르다

| | 무엇을 정하나 |
| --- | --- |
| `handoff/` | **수치와 규칙.** `tokens.json`(색 · 크기 · 간격 · 모서리 · 모션) · `screens.json`(화면 190) · `SPEC.md`(정책 · 문구) · `ADMIN.md`(관리자 26) |
| `figma-export/` | **화면의 모양.** 홈 · 검색 · Pick · 웨딩노트 · 업체상세 · 온보딩/로그인 · 라운지/MY · 추천 · 다이얼로그 |

둘이 어긋나면 **`handoff/`의 수치**와 **`figma-export/`의 모양**을 각각 따른다. 그래도
갈리면 고르지 말고 대표님께 묻는다.

## 이것이 대신하는 것

`docs/design-handoff/current/`(v3.12에서 멈춰 있다) · `docs/design-handoff/root/` ·
`docs/figma-spec/`는 **더 이상 근거가 아니다.** 지우지 않고 남기는 것은 기록 때문이고,
새 작업에서 인용하지 않는다.

`weddingpick_figma` 저장소는 여전히 **보는 용도로** 쓴다 — 아래 「찍을 수 없다」 참고.

## 찍을 수 없다 — 재서 확인했다 (2026-09-17)

`.dc.html`은 이 환경에서 **열리지 않는다.** 두 가지가 없다.

```
React · Babel   unpkg.com에서 받는데 프록시가 막는다 (HTTP 000)
_ds/ 번들       zip에 안 들어 있다 — <script src="_ds/…/_ds_bundle.js">가 404
```

`support.js` · `image-slot.js`는 들어왔지만 그 둘만으로는 그려지지 않는다.
**그래서 화면을 눈으로 보려면 `weddingpick_figma`를 빌드해 찍는다**
(`scripts/screenshot-figma.mjs`). 이 폴더는 **값을 읽는 자리**다.

「열어 보면 된다」고 적고 넘어가지 않는다 — 열리지 않는 것을 열린다고 적으면
다음 사람이 같은 자리에서 시간을 버린다.

## 판단이 필요한 것 넷 — 대표님 확인 전까지 코드에 반영하지 않는다

이 패키지가 **대표님이 앞서 따로 정하신 것과 어긋난다.** 골라서 밀지 않는다.

| 자리 | 지금 코드 (대표 지시 근거) | 새 패키지 |
| --- | --- | --- |
| **서체** | Pretendard 단일 (2026-09-14 지시 · 09-15에 실제로 싣고 화면으로 확인) | `tokens.json` `webfont: null` — 「웹폰트를 넣지 않는다. 시스템 서체를 쓴다」 |
| **좌우 여백** | 20 (피그마 12화면 실측) | `README.md` 「Gutter **24px** 고정. 전 화면 예외 없음」 |
| **Root 탭** | 홈 · 웨딩노트 · Pick · 라운지 · MY (2026-09-14 확정) | 홈 · **검색** · Pick · 웨딩노트 · MY — **라운지는 탭이 아니다** |
| **소셜 로그인** | 카카오 + 애플 (2026-09-11 A안 · 네이버 · 구글 제외) | 「소셜 4종(카카오 · 네이버 · 구글 · 애플)」 |

**브랜드색은 어긋나지 않는다** — 새 `tokens.json`도 코랄 `#FF6F61`이다. 피그마 원본의
로즈 `#E7898D`는 이 패키지가 이미 걷어냈다.

## 새 패키지가 들고 온 규칙

**브라우저 `alert` · `confirm` · `prompt`를 쓰지 않는다.** 여섯 유형으로 가른다
(`figma-export/09-dialogs.dc.html`).

```
DLG-A  알림            고를 것 없음 · 버튼 1개 · 중앙
DLG-B  확인            되돌릴 수 있음 · 취소 + 실행 · 중앙
DLG-C  되돌릴 수 없음   영향 항목 필수 · 빨강 실행 · 배경 탭 안 됨
DLG-D  바텀시트         고르기 · 입력 · 맥락 유지
DLG-E  행동 목록        대상 하나에 동작 3개 이상
DLG-F  토스트          결과만 · 2초 · 막지 않음
```

버튼 순서는 **왼쪽 취소 · 오른쪽 실행** 고정. 되돌릴 수 없는 것만 `#FF4133`.
다이얼로그를 겹쳐 띄우지 않고 뒤 것을 큐에 넣는다. **화면이 바뀌면 성공 알림을 띄우지
않는다** — 같은 화면에 남을 때만 토스트.

지금 코드는 `components/confirm-alert.ts`가 웹에서 `window.confirm` · `window.alert`을
부른다. 이 규칙대로면 바뀌어야 하는 자리다.
