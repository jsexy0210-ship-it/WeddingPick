## 핵심 메시지
- 웨딩픽의 핵심 키워드: **플래너 없이, 직접 고르는 웨딩 준비**.
- 앱이 대신 골라준다는 표현(`웨딩픽이 골랐어요` · `웨딩픽이 골라드려요` · `웨딩픽 TOP3`)은 쓰지 않는다. 사용자가 직접 고르고, 웨딩픽은 실 제보 금액과 조건을 보여주는 역할이다.
- 결정사 · 플래너 대행 개념을 업종이나 기능으로 넣지 않는다.

## 용어
- 사용자 화면에 `AI` 금지. `웨딩픽 콘텐츠`로 쓴다. 내부 개발·관리자·비용관리 문서에서는 AI 용어 유지.
- 사용자 화면에 `데이터` 금지. `실 제보` · `실 제보 N건` · `많이 확인된 곳` · `아직 정보가 적어요`.
- 정보 체계 3단. 상위 개념 `실 제보` · 금액 `제보 금액` · 제공 행동 `Pick 인증`.
  `확인된 제보` `확인된 정보` `확인된 금액` `실제로 낸 금액` `실제 결제` `실제 결제 데이터`는 쓰지 않는다.
- 애매모호 표현 금지: `거의` `아마` `대략` `어느 정도` `가능성이 높음` `~일 것으로 보임` 근거 없는 `약`·`정도`.
  대신 `확정` `미확정` `검증 전` `확인 필요` `조건부` `측정값` `추정값`.
- `탐색` 금지 → `검색`. `관심업체` 폐기 → `Pick`.

## 예시 데이터
- 웹은 가명 업체(`강남 A 스튜디오` 형식)와 샘플 이미지를 유지한다. 실제 상호와 실제 촬영물을 노출하지 않는다.
- 앱은 실제 업체명과 실제 이미지를 쓴다. 시안의 가명은 개발 시 실제 데이터로 대체한다.
- 금액은 웹·앱 모두 실 제보로 집계한 실제 구간을 쓴다.

## 전역 Layout Overflow / Overlap / Clipping 정비
콘텐츠는 잘리지 않고, 컴포넌트는 겹치지 않으며, 화면을 초과하는 콘텐츠는 해당 축으로 스크롤되도록 전역 레이아웃을 정비한다. 화면별 임시 패치가 아니라 공통 구조(헤더 · 탭바 · 칩바 · 카드 · 스크롤 컨테이너)에서 원인을 고친다.
- Header / Tab / Filter / Content / Bottom 영역은 서로 겹치지 않는다. `sticky`/`fixed`/`absolute`를 쓰면 다음 콘텐츠가 그 높이만큼 공간을 확보해야 한다.
- 콘텐츠 영역에 불필요한 고정 height를 쓰지 않는다. `auto`/`min-height` 기반으로 콘텐츠 길이에 맞춰 늘어나게 한다.
- 부모의 `overflow:hidden` 때문에 탭 · 텍스트 · 카드가 잘리지 않게 한다. 의도된 크롭이 아니면 자르지 않는다.
- 가로 탭 · 칩은 화면 너비를 넘으면 압축하지 않고 한 줄 + 가로 스크롤을 기본으로 한다.
- 세로 콘텐츠가 뷰포트를 넘으면 정상 스크롤을 제공하고, 하단 콘텐츠가 탭바 · Safe Area에 가리지 않도록 bottom padding을 둔다.
- 같은 현상이 여러 화면에서 반복되면 화면 각각이 아니라 공통 컴포넌트를 고친다.

## Legacy / Stale Artifact 정리
최신 정본만 기준으로 삼는다. 구 디자인 안, 진입 경로가 없는 화면, 삭제된 메뉴명·기능명이 남은 문구, 중복 mock 데이터는 최신본으로 통합하고 구버전을 지운다.
