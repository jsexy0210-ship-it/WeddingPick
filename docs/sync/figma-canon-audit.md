# 피그마 정본 감시 — 잰 것과 판정

**보이는 것은 전부 피그마다.** 피그마를 못 이기는 것은 셋뿐이다 — **말**(금지어 · 업종 이름 ·
지역 짧은 꼴 아홉) · **주소**(`/wedding` · `/community`) · **대표님이 그보다 나중에 내린 지시**.
그 셋 밖에서 「피그마와 다르지만 우리 정책이라 유지한다」는 말이 코드 · 문서 · PR 어디에 있든
위반이다.

이 문서는 **재서 잡는다.** 눈으로 코드를 대조한 것은 「본 것」이 아니다. 판정은
「피그마와 같다」 / 「다르다」 / 「못 쟀다」 셋 중 하나로만 적는다.

**코드는 고치지 않는다.** 고치는 것은 MASTER와 디자인 세션이다.

## 2. 판단이 필요한 것 · 위반으로 잡는 것

### 2-1. 히어로 색 — **고르지 않고 대표님께 묻는다**

피그마는 `#E7898D`, 앱은 코랄 `#FF6F61`이다. 홈 히어로 · Pick 버튼 · FAB가 다 이 색이다.

색은 「보이는 것」이라 원칙대로면 피그마가 이긴다. 그런데 **2026-09-15 대표 지시**(「기존
정본색상으로 싹다 다시 바꿔. 코랄색으로」)가 피그마 커밋(2026-09-14)보다 **나중이다** —
셋 중 「대표님이 그보다 나중에 내린 지시」에 해당한다. 다만 `CLAUDE.md`에서 그 지시는
**앱 아이콘 · 스플래시** 자리에 붙어 있다.

**「싹다」가 화면 안 히어로 · 버튼까지였는지는 이 문서만으로 못 고른다. 고르지 않고 묻는다.**

> **대표님 —** 화면 안의 코랄(`#FF6F61`)도 코랄로 둡니까, 아니면 피그마의 `#E7898D`로 갑니까?

**콘텐츠가 0이면 섹션째 접는다.** fixture에 웨딩피드 항목이 없어서 안 뜬 것이고, 「없다」가
아니라 **「비어서 접혔다」**다. 1주기에 `innerText`에 제목조차 없는 것을 보고 「없다」로 판정했는데,
**조건부 렌더를 갈라 보지 않고 판정한 것이 잘못이다.** 판정: **같다**(규격서 수를 주석에 달고 있다).

### 2. 새로 찾은 것 — **거짓 근거와 그로 인한 회귀**

**`spec/tokens.json`과 `packages/ui/src/theme.ts`가 사실이 아닌 것을 근거로 적고 있다.**

    spec/tokens.json  spacing.gutter.$note
      「… 피그마 12 화면 전부가 20이다.」
    packages/ui/src/theme.ts:639
      「피그마 12 화면을 실제로 재면 전부 20이다(docs/figma-spec/*.txt의 pad … 20 … 20).」

**전부가 아니다.** 규격서 12파일의 최상위 컨테이너 패딩을 전수로 뽑았다.

| 화면 | 규격서의 값 |
| --- | --- |
| home · search · pick · our-wedding · my · community | `pad … 0 …` (좌우는 안쪽 블록이 20) |
| contract-verify | `pad 28 **20** 40 **20**` |
| vendor-1 · vendor-1-booking · vendor-1-consult | `pad … 0 …` (안쪽 20) |
| **onboarding** | **`pad 32 24 32 24`** |
| **login** | **`pad 64 24 32 24`** |

**열 화면이 20이고 두 화면이 24다.** 브라우저에서 잰 값도 같다 — 피그마 `/onboarding` 좌우 **24**,
`/login` 좌우 **24**.

**그래서 회귀가 났다.** 「전부 20」을 근거로 `Layout.gutter`를 20으로 내리면서 **온보딩과 로그인이
피그마의 24에서 20으로 좁아졌다.**

| 화면 | 피그마 | 앱(`79926a12`) | 판정 |
| --- | --- | --- | --- |
| 로그인 | **24** | **20** | **다르다 — 양쪽 4px씩 좁다** |
| 온보딩 | **24** | **20** | **다르다 — 양쪽 4px씩 좁다** |

두 화면 다 `Layout.gutter`를 쓴다(`login/index.tsx:376` · `onboarding.tsx:106,110,114,116,118` ·
`step-frame.tsx:152,170` · `region-picker.tsx:92` · `question-head.tsx:43` · `style-grid.tsx:154` ·
`budget-grid.tsx:114` · `prep-status.tsx:161` · `progress.tsx:78` · `inline-toast.tsx:76`).

> **한 값으로 두 수를 덮은 것이 원인이다.** `gutter`와 `pageX`가 지금 **같은 20**을 가리키는데
> (`theme.ts:648,650`), 피그마는 실제로 **두 수**를 쓴다. 이름이 둘 있으니 수도 둘로 가르면 된다 —
> 어느 쪽으로 가를지는 MASTER가 정한다. 나는 잰 것만 적는다.

- **피그마 `/vendor/1/booking` · `/vendor/1/consult` · `/contract-verify`** — 앱 쪽 대응 라우트를

### 9. 2주기 요약

**고쳐진 것이 많다.** 좌우 20 · 탭 바 · MY · 웨딩노트 · 검색 · Pick의 틀, 그리고 규칙 3 · 4.

**남은 것은 셋이다.**

1. **거짓 근거와 그로 인한 회귀** — 「피그마 12 화면 전부 20」은 사실이 아니다(로그인 · 온보딩은
   24). 그 근거로 두 화면이 4px씩 좁아졌다. **가장 먼저 고칠 자리다.**
2. **등급 체계가 피그마 위에 있다** — B등급이라 값을 안 옮긴다는 판정이 코드 주석 넷과 문서 둘에
   살아 있고, 라운지 · 라운지 상세 · 검색 · 비교 네 화면의 값을 막고 있다. 규격서가 생긴 지금
   등급은 쓸모가 없다.
3. **규칙 파일이 절반만 지워졌다** — 폐기 표시를 붙였지만 본문이 남아 살아 있는 규칙으로 읽히는
   자리가 셋(`CLAUDE.md:81` · `session-prompt.md:102` · `codex-handoff.md:103`), 표시조차 없는
   자리가 여럿(규칙 5 · 「목업이 이긴다」 · `root/README.md` · `rn-migration/*`). 그리고 규칙
   번호로 인용한 주석 셋이 **바뀌기 전 내용**을 가리킨다.

**대표님께 드릴 말씀 하나.** **피그마 저장소의 브랜드색이 아직 `#E7898D`다.** 코드는 코랄로
돌아왔고 규격서에는 「낡았다」고 적었지만, **정본이 피그마인 한 다시 뽑을 때마다 되살아난다.**
피그마 쪽을 코랄로 바꾸는 것이 근본이다.
