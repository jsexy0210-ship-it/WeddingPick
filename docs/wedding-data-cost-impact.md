# 수집 파이프라인 서버 영향 및 비용 점검

확인일: 2026-09-04. 구현 기준: PR #62, bbadebb. 코드와 공식 요금 문서를
대조한 결과다. 실제 계정 플랜·사용량·청구서는 확인하지 않았으므로 무료 또는
청구액 확정으로 해석하지 않는다. 금액 예시는 USD, 세금·환율 제외다.

## 결론과 현재 실행 상태

신규 상시 서버는 필요 없다. 수집은 GitHub Actions에서 실행하고 --apply일 때
Neon에 직접 접속한다. Render API를 거쳐 수집하거나 NCP에 이미지를 올리지 않는다.
현재 로컬 실수집 10건, JSON 4개 총 4,404 bytes다. 운영 DB에는 반영하지 않았다.
Actions 실행 33838694039는 계정 결제 실패 또는 지출 한도 문제로 시작 전에
차단됐다. 이 메시지만으로 실제 미납 금액이나 이번 작업의 청구액을 알 수 없다.

## 구성별 영향

| 대상 | 코드상 영향 | 비용 발생 조건·판정 |
|---|---|---|
| Render API | 정기 수집 요청·파싱 CPU·메모리 부담 없음. DB 변경은 검색 결과에 반영될 수 있음 | 수집용 신규 인스턴스 비용 없음. 기존 서비스 요금은 별도 |
| Neon DB | apply 시 연결, 조회, 업체별 트랜잭션, 출처 기록·감사 이력 쓰기 | 컴퓨트 활성화·스토리지·전송 사용량이 늘 수 있음. 플랜과 잔여 한도 확인 필요 |
| GitHub Actions | 검증 1개 + 수집 2개 Linux 작업. 각 작업 npm ci | 비공개 저장소는 무료 할당 초과 시 과금. 공개 저장소 표준 runner는 무료 |
| Actions 산출물·캐시 | JSON 7일 보관, npm 캐시 사용 | 계정 공유 artifact 한도와 별도 cache 한도에 영향 |
| NCP Object Storage | 현재 업로드·다운로드 호출 없음 | 이 수집 경로로 인한 객체 저장·요청 비용 없음. 기존 사용료는 별도 |
| Google·네이버·카카오 | 현재 수집 경로에서 API 호출 없음 | 이번 경로로 인한 API 호출료 없음. 기존 서비스 호출료는 별도 |
| 공공데이터 원천 | 공식 페이지와 CSV 요청. 현재 2개 출처 | 현재 경로에 유료 API·결제 호출 없음. 향후 인증 API 쿼터는 별도 확인 |
| 모바일·웹 배포 | 정기 수집 자체는 빌드·배포 없음 | main 병합은 기존 CI/Deploy를 실행하므로 빌드·배포 사용량 별도 발생 가능 |

Render는 main.yml에서 CI 성공 후 migration·배포 훅 경로가 존재한다.
따라서 '수집이 서버를 호출하지 않는다'는 사실과 '코드 병합의 배포 영향'을
구분한다. 실제 서비스 자동 배포 설정과 플랜은 콘솔 재확인이 필요하다.

## Actions 예상 사용량

public-data.yml의 작업 제한은 검증 15분 + 출처당 10분 × 2 = 실행당
총 runner 시간 약 35분이다. 병렬 작업 시간도 각각 합산한다. 월 4~5회 정기
실행을 모두 제한시간까지 사용하면 약 140~175분이다. 이는 시간제한을 이용한
보수적 예산 계산이며 실제 측정값이나 계정 전체 비용 상한이 아니다.

비공개 저장소의 Linux 2-core 유료 사용분 단가 $0.006/분을 적용하면 전부
유료일 때 약 $0.84~$1.05/월이다. 무료 할당 내에서는 runner 추가 요금이 없을
수 있다. PR CI·브랜치 push·수동 실행·재실행·main 배포는 이 계산에서 제외했다.
특히 현재 브랜치에 push할 때마다 수집 workflow와 PR CI가 실행될 수 있다.

[공식 runner 단가](https://docs.github.com/en/billing/reference/actions-runner-pricing).
[공식 Actions 청구 기준](https://docs.github.com/en/billing/concepts/product-billing/github-actions):
GitHub Free 기준 월 2,000분·artifact 500MB이며 계정의 다른 작업과 공유한다.
artifact 초과분은 $0.25/GB-month. 캐시는 저장소별 기본 10GB이며 한도를 늘리면
초과 과금이 가능하다. 실제 계정 잔여량·설정은 미확인이다.

## DB 성능·누적 위험

- 현재 수집은 업체별 순차 처리다. 두 출처 작업은 병렬이지만 공통 advisory lock이
  수집 트랜잭션을 직렬화한다. 일반 API 읽기를 이 잠금으로 막지는 않지만 동일
  업체에 대한 동시 수정은 row lock을 기다릴 수 있다.
- pool 설정은 프로세스당 max 10이다. 현재 순차 로직은 이를 모두 쓰지 않지만
  향후 병렬화 시 연결 수가 증가할 수 있다. 수집 전용 max 1~2와 DB statement/
  lock timeout 적용을 운영 확대 전 검토한다. 현재 쿼리 timeout은 별도 설정이 없다.
- 같은 업체 재수집은 업체·감사로그를 중복 생성하지 않지만 출처 기록의 collected_at은
  갱신한다. 따라서 변경이 없어도 DB 쓰기·WAL·컴퓨트 비용이 완전히 0은 아니다.
- 처음 10개가 모두 신규로 반영될 경우 업체 10행, 출처 10행, 감사 이력 40행,
  실행 이력 2행을 생성한다. 실제 결과는 기존 업체·잠금·충돌에 따라 달라진다.
- import_runs/import_errors/변경 이력의 자동 보관기한·정리는 이번 구현에 없다.
  정상 주간 두 출처는 실행 이력 연 약 104행, 오류 반복 시 더 증가한다.
  감사 이력과 일반 실행 로그를 구분한 보관 정책이 필요하다. 임의 삭제하지 않는다.
- 0071은 vendors ALTER TABLE과 검증 제약을 포함한다. 테이블 크기·동시 트래픽에
  따라 DDL 잠금과 기존 행 검사로 지연될 수 있다. 아직 운영 migration 미실행이다.
- 신규 업체가 검색에 노출될 수 있지만 가격 자료 자동 매칭과 이미지 수집은 없다.
  서비스 표시 품질과 업체명 중복 검증은 운영 반영 후 확인해야 한다.

Neon은 플랜별 컴퓨트·저장 과금과 scale-to-zero 설정에 따라 증가액이 달라진다.
현재 10건만으로 월 요금을 정할 수 없다. [공식 요금](https://neon.com/pricing),
[scale-to-zero 설명](https://neon.com/docs/introduction/scale-to-zero).
Render의 기존 전송량·빌드 사용량도 계정 전체와 공유될 수 있다.
[공식 무료 서비스 제한](https://render.com/docs/free).

## 외부 트래픽·메모리

현재 workflow는 수집 단계 후 apply 단계에서 원천을 다시 다운로드한다.
두 출처 기준 수집만 하면 페이지 2 + CSV 2 = 4회, apply까지 하면 총 8회다.
각 응답은 4MiB·30초 제한이 있다. 전체 HTML/CSV를 DB나 artifact에 보관하지 않는다.
검증한 동일 스냅샷을 apply하도록 개선하면 중복 다운로드와 두 조회 사이 변경
가능성을 줄일 수 있다. 단, 라이선스·출처 검증을 우회하는 임의 JSON 입력은 금지한다.

로컬 CSV는 입력 64MiB, DB 적용 1회 1,000업체 제한이다. CSV 전체 파싱과 JSON
직렬화를 메모리에서 수행하므로 실제 메모리 사용량은 입력 크기보다 크다.
전국 규모에는 스트리밍·지역별 분할과 실측이 필요하며 현재 10건 결과를 전국
성능 보장으로 확대 해석하지 않는다.

## 운영 활성화 전 확인 항목

1. GitHub Billing & plans 차단 사유·잔여 무료 할당·유료 예산 확인. 결제나
   지출 한도를 이번 점검에서 변경하지 않았다.
2. PostgreSQL 통합검증 통과, main 병합과 migration의 잠금·실행 결과 확인.
3. 첫 apply의 처리 시간·업체 수·오류·Neon 활성 시간/저장 증가량 측정.
4. 전국 확대 전 중복 다운로드 제거, DB timeout/연결 상한, 로그 보관 정책,
   출처 수 증가에 따른 Actions 작업 수·예산 재산정.

현재 설정의 7일 산출물 보관·HTTP 크기/시간 제한·실행당 업체 상한·작업 timeout은
비용 억제 장치다. 계정 전체 과금을 막는 하드 예산은 아니며 무과금을 보장하지 않는다.
