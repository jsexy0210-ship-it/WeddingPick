# PO 운영 원칙

## 우선순위

1. P0 장애와 사용자 데이터 보호
2. 핵심 사용자 흐름의 실제 동작
3. 목업·카피·접근성 품질
4. 부가 기능과 문서 정리

완료율보다 운영 가능 여부를 먼저 판정한다. 프로세스가 살아 있어도 DB·저장소·인증이 실패하면 운영 가능으로 보고하지 않는다.

## 비용 없는 검증 경로

- GitHub Actions는 필수 게이트로 사용하지 않는다. 계정 결제·사용 한도에 막히면 `scripts/ci-local.ps1`을 실행한다.
- Git 저장소 용량은 운영상 제한 없이 사용한다. 정책·소스·검증 결과·핸드오프 문서는
  누락 없이 커밋하고 푸시한다. 단, 비밀값·의존성 캐시·빌드 산출물·개인 임시파일은
  `.gitignore`로 추적하지 않는다.
- Render 자동 배포 후 `/health`와 핵심 API smoke test를 수행한다.
- 외부 API·AI 호출은 테스트에서 실제 호출하지 않고 계약 테스트·mock을 사용한다.
- 유료 인프라가 필요한 단계는 PO 승인 전까지 기능 플래그로 닫아 둔다.

## 데이터 정리 원칙

- 캐시·빌드 산출물·압축 해제 임시 폴더만 자동 삭제한다.
- 정책 구버전, 운영 로그, 사용자 문서, 마이그레이션은 감사·복구에 필요할 수 있으므로 자동 삭제하지 않는다.
- 삭제 전 대상·보존 기간·복구 가능 여부를 기록하고, 범위가 불명확하면 보류한다.

## 출시 판정

- `npm run typecheck`, `npm run lint`, `npm test` 통과
- 운영 `/health`가 DB까지 `ok`
- 실제 OAuth 제공자별 콜백 확인
- 대표 화면 목업 대비 캡처 확인
- P0/P1 미해결 0건
