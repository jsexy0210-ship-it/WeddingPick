# 최종통합정책 v2.0 — 무엇이 바뀌고 무엇을 고쳤나

2026-08-29에 `웨딩픽_최종통합정책_v2.0.md`와 갱신된 `웨딩픽_화면데이터구조_스펙.md`를
받았다. v2.0이 **최상위 문서**이고, 화면·데이터 구조 스펙이 그다음, 그 아래가 과거
문서다. 부딪히면 위를 따른다.

이 문서는 **이미 만든 것 중 v2.0이 뒤집은 것**과 그것을 어떻게 고쳤는지를 적는다.
새로 만들 것은 6번에 순서로 둔다.

---

## 1. 🔴 실제 결제 구간의 잠금을 걷어냈다 (K-6)

### 무엇이 바뀌었나

폐기된 것: `결제인증 회원만 실제 결제 데이터 접근`
새 규칙(D-1): **비회원도 기본 실제 결제구간을 본다.** 결제인증이 여는 것은 접근이
아니라 **깊이**다 — 조건이 비슷한 사례와 상세 분석.

> 실제가격 자체를 전부 잠그지 않고 데이터 깊이를 보상으로 사용한다. (D-1)

### 무엇을 고쳤나

- `hasDataUnlock` → `hasDeepData`. 이름이 바뀐 것이 아니라 **여는 대상이 바뀌었다**
- `vendorPricesSchema`에서 `available: 'locked'` 갈래를 지웠다. 잠긴 상태를 표현할
  타입이 없으면 화면이 그것을 그릴 수 없다
- 업체 상세: 잠금 카드 대신 **잉크 블록**(핸드오프 8번). 등록 CTA는 남되 "가격이
  열립니다"가 아니라 "조건이 비슷한 사례를 보실 수 있어요"라고 말한다
- `GET /v1/me/data-unlock`의 `unlocked` → `deepData`
- 등록 완료 화면의 `실제 가격이 열렸습니다` → `조건이 비슷한 사례를 볼 수 있어요`.
  **등록 전에도 보이던 것을 열렸다고 말하면 그건 거짓이다**

### 왜 이렇게 고쳤나

잠금을 지우는 가장 안전한 방법은 **잠긴 상태를 표현할 수 없게 만드는 것**이다.
필드를 남겨두고 화면에서만 안 그리면, 언젠가 어느 화면이 다시 그린다.

## 2. 🔴 가격 공개가 5건 문턱에서 4단계 사다리로 (C장 · 원문 14·15번)

### 무엇이 바뀌었나

폐기된 것: `결제인증 5건부터 금액 공개`

| 데이터 수 | 보여주는 것 |
|---|---|
| 0~2건 | 수집 중. 구간 비공개. 데이터 수는 표시 |
| 3~4건 | 구간 공개 + `아직 데이터가 적어요` |
| 5~9건 | 일반 구간. 부족 안내 제거 |
| 10건 이상 | 중앙값·조건별·시기별까지 |

> 업체별·화면별로 별도 기준을 만들지 않는다. (원문 15번)

### 무엇을 고쳤나

`packages/domain/src/disclosure.ts` 하나에 사다리를 넣고, **판별 유니온**으로 만들었다:

```ts
export type PriceDisclosure =
  | { stage: 'collecting'; count; caption }
  | { stage: 'early';    count; caption; low; high }
  | { stage: 'general';  count; caption; low; high }
  | { stage: 'detailed'; count; caption; low; high; median };
```

**`median`은 `detailed`에만 있다.** 9건짜리 업체에 중앙값을 그리는 코드는 컴파일되지
않는다. `low`/`high`는 `collecting`에 없다 — 마찬가지다.

구간은 최저·최고가 아니라 **분포의 허리(p25~p75)**를 쓴다. 3억짜리 한 건이 구간을
통째로 망가뜨리지 않게 하려는 것이고, 테스트가 그 경우를 잡는다.

`canDiscloseCondition`은 **전체와 조건을 따로 판단한다**(C-3 · K-8). 전체 12건 중
그 조건이 1건이면, 그 1건은 조건별 가격이 아니라 한 사람의 결제다.

### 아직 안 한 것

- C-4 재식별 방지 — 지역·날짜·상품·옵션 조합이 사람을 좁히면 묶거나 숨긴다.
  지금은 조건 수만 본다
- C-1 12개월 창 — 라벨은 `최근 12개월`인데 질의는 아직 기간을 자르지 않는다.
  **라벨이 사실보다 앞서 있다.** 다음에 고친다

## 3. 🟡 `표본` → `데이터` (J장)

> 사용자 노출 및 현행 정책에서 `표본` 대신 `데이터`를 사용한다.

화면 문구에서 걷어냈다. 주석과 내부 변수명은 그대로 둔다 — 사용자에게 보이는 말이
아니고, `sampleCount` 같은 이름은 통계 용어로서 정확하다.

## 4. 🟡 아직 안 고친 것 (순서대로)

### 4-1. 후기 신고·업체 반론의 자동처리 (K-3 · K-4 · D-3)

폐기된 것:
- `후기 신고 = 관리자 큐` → 일반 신고는 자동처리, **법적/중대 분쟁만 관리자**
- `업체 반론 = 모두 관리자 검토` → AI 1차검증 + 안전한 범위 자동처리

지금 우리 코드는 **둘 다 사람이 본다.** 방금 만든 반론이 특히 그렇다.

고칠 때 지킬 것:
- A-2가 `업체와 사용자 사이의 중대한 분쟁`을 사람 몫으로 남겨뒀다. 자동으로 여는
  것은 **안전한 범위**뿐이다
- `rebuttal_decision_has_reviewer` 제약은 사람 id를 요구한다. 자동 결정을 넣으려면
  **결정자가 사람이 아닐 수 있다는 것을 표에 적어야 한다** — 제약을 지우는 것이
  아니라, 자동 결정 주체를 1급으로 만들고 rule_version·confidence·evidence를 함께
  남긴다(L장)
- 원문 24번이 즉시 임시숨김 대상을 정했다: 전화번호·계좌번호·주민등록번호·상세
  개인정보·명백한 불법 콘텐츠. 이건 규칙으로 잡을 수 있다

### 4-2. 업체 관계자 인증 (원문 26번) — 열려 있던 질문의 답

우선순위가 정해졌다:
1. 업체 공식 도메인 이메일
2. 공식 홈페이지·공식 채널에 공개된 이메일
3. 사업자 관련 증빙

회사 이메일이 없는 소규모 업체를 위해 대체 수단을 둔다. 증빙은 **일반 사용자에게
원본을 공개하지 않는다**(원문 27번).

### 4-3. 자동 의사결정 공통 필드 (L장)

`event_id / workflow_id / source / source_checked_at / policy_version /
model·rule_version / confidence / decision / reason_code / evidence_refs / cost /
latency / retry_count / execution_status / rollback_target`

지금은 `ai_usage`가 모델 호출만 기록한다. 규칙으로 내린 결정은 아무 데도 남지 않는다.

**개인정보는 이 로그에 복제하지 않는다**(L장 마지막 줄) — 우리 추출규칙 10번과 같은 말이다.

### 4-4. 예식 완료 (D-4 · 원문 34번)

예식일이 지나면 `예식 완료`로 바꾸고 준비 알림·추천을 멈춘다. 대신 최종 후기,
미등록 결제인증, 총지출 정리를 권한다.

지금은 예식일이 지나도 D-Day가 계속 세고, 웨딩 스케줄이 계속 `예정`을 띄운다.

### 4-5. 광고와 자연 결과 분리 (E장)

유료 노출은 광고임을 표시하고, 광고비가 데이터·후기·검증·랭킹에 영향을 주지
않는다. 지금 광고가 없으므로 **없는 동안 구조를 정해두는 것이 싸다.**

### 4-6. 이벤트/보상 (I장)

친구초대 NPay 3,000원(첫 유효 결제인증 시), 홍보인증 2,000원. **앱스토어 리뷰와
NPay를 연결하지 않는다** — 이건 금지사항이다.

## 5. v2.0이 우리 판단을 확인해 준 것

- **가격 판정 금지**(J장, 원문 17번) — `저렴/비쌈/적정가/바가지`. 이미
  `copy-rules.ts`가 코드로 막고 있고 테스트가 화면 문구를 훑는다
- **계약서 업로드 요구 금지**(J장) — v3에서 이미 P1에서 뺐다
- **이상치 자동 삭제 금지**(C-2) — 우리도 지우지 않고 표시만 한다
  (`price_reports.rejected_at`)
- **보상과 신뢰도 분리**(C-10) — 아직 보상이 없지만, 만들 때 신뢰점수에 더하지 않는다

## 6. 순서

```
Ⅰ 가격 공개 4단계 + 잠금 해제 + 표본→데이터     ✅
Ⅱ 자동 의사결정 공통 필드 (L장) + 신고·반론 자동처리 (K-3·K-4)
Ⅲ 예식 완료 (D-4)
Ⅳ 12개월 창 (C-1) + 재식별 방지 (C-4)
Ⅴ 남은 화면 모양 (스플래시·스켈레톤·정렬·도넛·FAB·설정)
```

Ⅰ이 먼저인 이유는 **화면 모양을 맞추기 전에 화면이 말하는 내용이 맞아야 하기**
때문이다. 잠긴 카드를 예쁘게 다듬어봐야 그 카드는 지워질 카드다.
