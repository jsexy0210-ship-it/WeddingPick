## 왜 생겼는가

그 전까지 세션들은 시안 그림과 우리 화면을 **눈으로 견주며** 고쳤다. 그 방식은 반드시
해석이 섞인다. 실제로 한 세션이 준비 현황의 글자 위계를 「2×2로 넓어졌으니 업종명을
크게」라고 판단해서 뒤집었다. 그럴듯하지만 **시킨 적 없는 일**이다. 눈대중으로 맞추는 한
이런 일은 계속 난다.

그래서 재서 준다. 화면을 만드는 쪽은 **여기 적힌 수를 그대로 옮긴다.**

## 읽는 법

`.txt`를 먼저 본다. 들여쓰기가 DOM 깊이고, 한 줄이 노드 하나다.

    div 390×158  pad 16 16 16 16 · mar 0 20 24 20 · bg #E7898D · r22
      span 237×46  "D-127" · 46/700 #FFFFFF · lh 46 · ls -1.38px

읽으면 이렇다 — 히어로는 390×158, 안쪽 여백 16, 바깥 여백 위0 오른20 아래24 왼20,
배경 `#E7898D`, 라운드 22. 그 안의 `D-127`은 46px 700 흰색, 줄높이 46, 자간 -1.38px.

| 적힌 것 | 뜻 |
| --- | --- |
| `430×932` | 실제로 그려진 폭×높이 |
| `46/700` | font-size / font-weight |
| `lh` · `ls` | line-height · letter-spacing |
| `pad` · `mar` | 위 오른 아래 왼 (CSS 순서) |
| `r22` | border-radius 22 |
| `#FFFFFF 55%` | 흰색 투명도 55% |
| `flex/column` · `gap 8` · `cols …` | 배치 |

`.json`은 같은 내용을 기계가 읽는 꼴이다.

## 색은 sRGB로 떨어진다

크로미움은 투명도가 섞인 색을 `oklab(0.999994 … / 0.55)`처럼 돌려준다. 그대로 적으면
옮겨 적을 수가 없어서, **1×1 캔버스에 칠해 픽셀로 되읽는다.** 어떤 표기로 왔든 hex로
떨어진다.

## 이 수를 그대로 쓰되, 값은 토큰을 거친다

화면 코드에 hex·px을 직접 적지 않는다(최상위 규칙 1번). 여기 적힌 수가 `spec/tokens.json`에
없으면 **토큰에 더하고 `$note`에 이 파일의 어느 줄에서 왔는지 적는다.** 가까운 기존 값으로
때우지 않는다.

색은 이미 SEED에서 뽑아 맞춰 뒀다(`spec/seed-tokens.json` · `spec/seed-map.json`).

## 이 수를 따르지 않는 자리

「보이는 것」이 아니라 **부르는 이름 · 주소 · 심볼 · 법**은 `CLAUDE.md` 맨 위 「최상위 정책
규칙」의 표를 따른다 — Pick Mark 두 path · 주소 · 예식일 휠 3열 · 지역 아홉 · 온보딩 세
질문 · 업종 이름 · 금지어 · 브랜드색 · 고지가 먼저.

**시안의 값이 가짜인 자리도 있다.** 「2027년 1월 15일」 · 「경기·인천」 · 「블루밍 스튜디오」 ·
unsplash 이미지는 시안용이다. 수치는 따르고 내용은 실제 값으로 채운다.
